## 执行顺序

1. **N80-E1 正式 Web 单文件游戏**：创作者从当前工程点击构建，看到打包状态，下载含工程、源素材与正式 Player 的 HTML；缺失素材显示名称与恢复办法；修改工程后旧下载失效。
2. **N80 后续离线交付**：在上述真实产物基础上完善文件体积、目录包、PWA/离线缓存、构建元数据和正常用户可用的本地预览。单文件实现不等于整个 N80 或 M1 通过。
3. **持续制作作品**：开发侧只通过产品 UI 维护一个短篇，逐步成长为 20–30 分钟 Benchmark。每次功能由写作、演出、调试、导出中的真实阻碍决定；不要求用户提前参加计时验收。
4. **平台最小路径**：提前贯通 Windows/Android 正式 Host 的工程、资源、存档和生命周期，发现真实平台差异；随后补双端编辑与安装发布。
5. **资源与优化**：N70–N72 结合真实产物和设备数据完成源/派生管理、Dicing、收益报告、无收益回退，仍属于 M1，不能用原型代替。
6. **功能与 UI 收束**：补当前 P0 工作流缺口、N62 玩家路线图及跨端一致性，统一整体 UI 后再组织真人验收，最后完成安装/签名/发布。

这些是工作顺序，不是对后续功能完成或正式发布的预先批准。当前已推进至 N80-E3 PWA 离线交付；主线 PR 的合并仍需单独处理。

## 开发规则

- 每个切片先明确用户、入口、连续操作、可见结果和失败恢复。
- 功能推进是主要工作。必要测试围绕实际产品路径和受影响回归；普通 UI 改动不新增独立安全审计或入口合同。
- 功能、必要测试、文档尽量同一提交。已有成功验证不因纯文字修改反复执行。
- 日期到期和历史文档措辞不能替代对当前任务的判断。本次指令已授权调整路线及开始 N80-E1；旧 RA-N21-011 日期保留为历史，不伪造新的到期日。
- 真人验收延后到功能与整体 UI 就绪；发布前所需的存档兼容、数据恢复、安装和签名仍按实际风险落实。

## N80-E1 实现与剩余边界

入口沿用 Preview 的“构建与导出”。现在从当前 Canonical 经正式 Compiler 预检，读取当前工作区真实源 Blob，把正式 Player 的生产 bundle、样式、工程和媒体一起写入 HTML。正式 Player 使用既有 Core、Runtime、Host、Save 和附加页，不复制解释器。旧导出器仅保留给历史证据，不再作为 App 的导出路径。

E1 使用内嵌原始媒体，文件体积与内存开销会随素材增长；E2 已新增目录包，E3 已新增下述 PWA 离线交付，资源优化与原生安装包尚未完成。浏览器本地文件的存档能力取决于浏览器存储支持，跨文件/跨设备迁移不作承诺。

预期：下载后的文件能独立启动正式 Player，运行剧情并使用附加内容；缺失素材不提供残缺产物。原实际：旧导出只生成独立简化解释器，无法继承正式 Player 功能。现在 App 已改为同一个正式 Player 入口。

### 本步结果与接续

- 真实 production 浏览器路径：打开示例 → 导入真实 PNG → 构建下载 → 断网打开本地 HTML → 开始故事 → 附加内容往返 → 剧情结局。实际通过，附加页往返 Runtime hash 不变，PNG 解码为 16×9，390×844 无横向溢出、无未捕获异常。产物 462,856 bytes；证据见 `evidence/n80/formal-web-export.json`，复跑命令 `node tools/run-n80-web-export-browser.mjs`（先构建 Editor，需 Chrome/Edge）。该 PNG 验证包含和解码，不冒充剧情画面显示测试。
- 定向功能回归：`formal-web-export.test.ts` 与 `playable-preview-app.test.tsx` 共 8 项通过，覆盖真实源 bytes、缺失/损坏恢复和 App 下载入口；Editor production build 与 Editor/Player TypeScript 通过。测试脚本中 DOM 返回值改为布尔判断，避免 CDP 序列化 DOM 失败；不将脚本错误算作产品故障。
- 目标对齐：本步交付的是“创作者拿到可以独立玩的文件”，没有新增第二套解释器、真人计时或新的验收阶段。N80-E1 完成不等于 N80、跨平台或 M1 完成。
- E1 接续计划现已由下方 E2 完成：目录包、构建信息与本地预览说明；单文件入口保留。
- 换机：使用 `codex/n60-e1-debugger-session` 最新提交，`npm ci` 后构建 Editor；工作区 IndexedDB 和私有素材不会随 Git 迁移，需要用户导出工程/资源后在新机导入。需要修改 Player 并验证开发模式导出时重启 Editor 开发服务（导出 bundle 按服务生命周期缓存）。现有大型 Editor chunk 警告保留，不为本切片单独展开体积重构。

## N80-E2 目录交付（2026-10-10）

用户场景：创作者有较多媒体，想把游戏解压试玩、整包发给玩家或上传静态网站。在现有“构建与导出”点击“构建目录 ZIP”，看到打包状态，下载并完整解压，打开 `index.html`。失败时显示具体缺失源素材与重新导入提示；修改工程后旧下载作废。

实现：与单文件共用正式 Compiler 预检、源 Blob 读取和正式 Player。ZIP 包含 `index.html`、`player.js`、`player.css`、按内容摘要命名的独立媒体、`build-info.json` 和中文使用说明。素材不再 Base64 内嵌，相同内容与扩展名共用一个文件，不新增解释器。保留旧单文件入口。

预期/原实际/修正结果：原来只能生成内嵌单文件，无法提供独立媒体目录。现在 production Editor 导入真实 PNG 后下载 ZIP，解压并断网从 file URL 启动，正式 Player 到达结局，附加页往返状态 hash 不变，PNG 解码 16×9，390×844 overflow 0、未捕获异常 0；见 `evidence/n80/formal-web-directory.json`。PNG 此处验证实际文件包含与解码，不声称已验证全类型媒体演出。

必要验证：两份受影响功能测试共 8 项通过，涵盖旧 HTML 与新 ZIP 下载、解压后的工程/源字节、构建摘要和缺失源恢复；Editor production 构建通过。浏览器复跑：先 `npm run build --workspace @world-studio/editor`，再 `node tools/run-n80-web-export-browser.mjs --directory`。不是重新执行全项目验收。

边界：使用不压缩的 ZIP 保留原媒体，避免 Base64 膨胀，不是 N70 优化；小工程可能因说明/索引额外增大。打包仍需内存，不承诺超大工程流式打包。file URL 存档受浏览器和路径影响，目录 ZIP 不是存档备份；E2 时尚未实现的 PWA 由下方 E3 接续。

E2 的下一步现已由下方 E3 实现。继续从真实短篇制作中的阻碍选择功能，不先开展新的验收/安全专项。

## N80-E3 PWA 离线交付（2026-10-10）

用户路径：创作者仍导出同一个目录 ZIP，完整上传 HTTPS 静态网站；玩家展开顶部“离线与安装”，看到大致大小，主动点击“下载离线内容”，就绪后可断网重开。首次进入不强制下载全部素材，缓存失败显示重试，不阻止在线游戏。安装按钮只在浏览器提供安装事件时出现，并给出菜单安装的替代说明。

更新路径：点击“检查更新”，新版本下载完成后提示保存进度、关闭所有游戏窗口再重开；不调用 skipWaiting 强制打断剧情。缓存按站点目录与完整文件版本隔离，发布不完整时不替换旧缓存；不清空 Player 存档。包含 index、播放器、样式、媒体、离线脚本、图标与 manifest，支持目录子路径和缓存媒体的 Range 请求。

真实差异与修正：首次故意让 PNG 下载失败，产品能报错，但重试仍调用已经失效的 registration.update，无法恢复；修正为首次安装失败后重新注册下载任务。production 真实 ZIP 部署在 localhost 子目录，随后完成失败→重试→就绪→服务端不可用且浏览器断网重开→附加页往返→结局。部署第二版测试素材后，等待期间 Runtime hash 不变，关闭页面后离线重新打开获得第二版。证据 `evidence/n80/formal-web-pwa.json`，原 file 目录路径亦保持通过。

必要验证：8 项受影响功能测试通过，覆盖导出、清单与缓存内容摘要、播放器变化产生新缓存版本；Editor TypeScript/production 构建通过。浏览器命令 `node tools/run-n80-web-export-browser.mjs --pwa`；其中第二版是脚本按真实导出清单格式生成的部署夹具，不冒充作者二次编辑 UI 路径。Chrome 安装条件检查无错误，但未执行真实桌面安装或 Android/iOS 安装。

范围边界：这是 Web 离线功能切片，不关闭整个 N80。仍缺面向非技术作者的本地站点预览入口、发布名称/版本/图标设置、压缩与许可证材料，以及完整两浏览器/设备发布验证；当前默认通用图标，缓存可被浏览器清理，不承诺永久离线或跨设备存档。SW 所需 HTTPS/localhost 与等待更新的机制依据 [MDN Service Worker 文档](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)，直接打开 file 目录不注册 SW。

下一步优先解决作者试发布的实际操作：提供本地站点预览入口与清楚的发布反馈，让作者不用自行搭服务器即可检查同一 Web 产物；随后补作品名称/版本/图标等面向玩家的发布设置。在真实短篇路径中推进，不先扩展审计框架。
