## 执行顺序

1. **N80-E1 正式 Web 单文件游戏**：创作者从当前工程点击构建，看到打包状态，下载含工程、源素材与正式 Player 的 HTML；缺失素材显示名称与恢复办法；修改工程后旧下载失效。
2. **N80 后续离线交付**：在上述真实产物基础上完善文件体积、目录包、PWA/离线缓存、构建元数据和正常用户可用的本地预览。单文件实现不等于整个 N80 或 M1 通过。
3. **持续制作作品**：开发侧只通过产品 UI 维护一个短篇，逐步成长为 20–30 分钟 Benchmark。每次功能由写作、演出、调试、导出中的真实阻碍决定；不要求用户提前参加计时验收。
4. **平台最小路径**：提前贯通 Windows/Android 正式 Host 的工程、资源、存档和生命周期，发现真实平台差异；随后补双端编辑与安装发布。
5. **资源与优化**：N70–N72 结合真实产物和设备数据完成源/派生管理、Dicing、收益报告、无收益回退，仍属于 M1，不能用原型代替。
6. **功能与 UI 收束**：补当前 P0 工作流缺口、N62 玩家路线图及跨端一致性，统一整体 UI 后再组织真人验收，最后完成安装/签名/发布。

这些是工作顺序，不是对后续功能完成或正式发布的预先批准。当前实现范围为 N80-E1；主线 PR 的合并仍需单独处理。

## 开发规则

- 每个切片先明确用户、入口、连续操作、可见结果和失败恢复。
- 功能推进是主要工作。必要测试围绕实际产品路径和受影响回归；普通 UI 改动不新增独立安全审计或入口合同。
- 功能、必要测试、文档尽量同一提交。已有成功验证不因纯文字修改反复执行。
- 日期到期和历史文档措辞不能替代对当前任务的判断。本次指令已授权调整路线及开始 N80-E1；旧 RA-N21-011 日期保留为历史，不伪造新的到期日。
- 真人验收延后到功能与整体 UI 就绪；发布前所需的存档兼容、数据恢复、安装和签名仍按实际风险落实。

## N80-E1 实现与剩余边界

入口沿用 Preview 的“构建与导出”。现在从当前 Canonical 经正式 Compiler 预检，读取当前工作区真实源 Blob，把正式 Player 的生产 bundle、样式、工程和媒体一起写入 HTML。正式 Player 使用既有 Core、Runtime、Host、Save 和附加页，不复制解释器。旧导出器仅保留给历史证据，不再作为 App 的导出路径。

本步使用内嵌原始媒体，文件体积与内存开销会随素材增长；目录包、PWA、优化资源、安装包尚未完成。浏览器本地文件的存档能力取决于浏览器存储支持，跨文件/跨设备迁移不作承诺。

预期：下载后的文件能独立启动正式 Player，运行剧情并使用附加内容；缺失素材不提供残缺产物。原实际：旧导出只生成独立简化解释器，无法继承正式 Player 功能。现在 App 已改为同一个正式 Player 入口。

### 本步结果与接续

- 真实 production 浏览器路径：打开示例 → 导入真实 PNG → 构建下载 → 断网打开本地 HTML → 开始故事 → 附加内容往返 → 剧情结局。实际通过，附加页往返 Runtime hash 不变，PNG 解码为 16×9，390×844 无横向溢出、无未捕获异常。产物 462,856 bytes；证据见 `evidence/n80/formal-web-export.json`，复跑命令 `node tools/run-n80-web-export-browser.mjs`（先构建 Editor，需 Chrome/Edge）。该 PNG 验证包含和解码，不冒充剧情画面显示测试。
- 定向功能回归：`formal-web-export.test.ts` 与 `playable-preview-app.test.tsx` 共 8 项通过，覆盖真实源 bytes、缺失/损坏恢复和 App 下载入口；Editor production build 与 Editor/Player TypeScript 通过。测试脚本中 DOM 返回值改为布尔判断，避免 CDP 序列化 DOM 失败；不将脚本错误算作产品故障。
- 目标对齐：本步交付的是“创作者拿到可以独立玩的文件”，没有新增第二套解释器、真人计时或新的验收阶段。N80-E1 完成不等于 N80、跨平台或 M1 完成。
- 下一切片优先处理大素材单文件不便分发的问题：从同一工程导出目录包（含入口、正式 Player、素材和构建信息），给创作者可操作的本地预览说明；保持本次单文件入口可用。先做目录分发，再在同一产物上补 PWA，不重新建立解释器或审计框架。
- 换机：使用 `codex/n60-e1-debugger-session` 最新提交，`npm ci` 后构建 Editor；工作区 IndexedDB 和私有素材不会随 Git 迁移，需要用户导出工程/资源后在新机导入。需要修改 Player 并验证开发模式导出时重启 Editor 开发服务（导出 bundle 按服务生命周期缓存）。现有大型 Editor chunk 警告保留，不为本切片单独展开体积重构。
