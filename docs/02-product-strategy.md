# 产品战略

## 1. 产品愿景

让任何有故事的人都能在手边设备上开始创作，让专业团队也无需为了规模、协作和发行迁移到另一套工具。

## 2. 定位

WorLd Studio 是一个 **本地优先、跨设备、生产级的视觉小说创作与发布平台**。

它不是：

- 只能发布到自有社区的互动阅读平台；
- 只能写对话、仍需接入 Unity/Godot 的中间件；
- 只有节点图、项目越大越难维护的 Demo 工具；
- 通用游戏引擎的简化版；
- 依赖生成式 AI 才能完成基础工作的“AI 外壳”。

## 3. 目标用户

### Persona A：独立创作者

- 会写故事，但不会编程；
- 主要在 Windows 和 Android 手机之间切换；
- 希望快速导入素材、预览并发布试玩；
- 最怕 SDK、路径、脚本报错和应用签名。

核心价值：合理默认值、模板、可视化编辑、手机继续创作、一键构建。

### Persona B：职业编剧/叙事设计师

- 管理数十万字、多个章节和路线；
- 偏好键盘、文本和批量操作；
- 需要搜索、重构、变量追踪、路线图和审阅；
- 不希望因使用可视化工具而失去版本控制。

核心价值：脚本一级公民、稳定 ID、全局搜索、语义重构、路线 QA。

### Persona C：小型制作团队

- 编剧、美术、程序、翻译和配音并行工作；
- 需要任务状态、评论、权限、版本历史和资源交付；
- 必须在多平台保持一致，避免发布前集中救火。

核心价值：本地优先协作、资源状态、语义 Diff、构建中心和发布门禁。

### Persona D：扩展开发者

- 希望添加命令、资源类型、导出器、运行时系统和 UI 组件；
- 需要稳定 API、调试工具、沙箱和兼容约束；
- 不希望每次编辑器升级都重写插件。

核心价值：声明式命令、插件 SDK、运行时服务接口、版本化能力清单。

## 4. 核心产品支柱

### 4.1 One Story, Many Views

同一个故事可通过四种视图编辑：

1. **Route Map**：章节、场景、路线、结局和跨场景跳转。
2. **Sequence**：场景内部按时间顺序排列的对白和演出块。
3. **Script**：适合高速写作、批量修改、Git 和外部工具的文本。
4. **Stage**：角色、镜头、UI 与演出的所见即所得布局。

所有修改进入同一 AST/IR；视图只是不同投影。

### 4.2 Mobile Is a First-Class Editor

手机端不压缩桌面三栏布局，而采用任务模式：

- 写作；
- 路线；
- 舞台；
- 资源；
- 预览；
- 构建。

复杂属性使用底部 Sheet，节点连接提供列表式备选操作，所有拖拽都有点击/文本替代方案。

### 4.3 Narrative Intelligence

“最强”的关键不是更多转场，而是让大型故事更可靠：

- 不可达节点、死路、无暂停循环；
- 变量读写与条件来源；
- 从当前状态到某结局的可行路径；
- 路线覆盖与未测试分支；
- 缺失资源、无效引用和资源重复；
- 本地化缺失、长度风险和配音错位；
- 版本更新后的存档兼容风险。

### 4.4 Production Without Lock-in

- 本地项目无需账户即可创建和发布 Web；
- 源文件可读、可拆分、可备份、可 Git；
- 可导出完整工程和中间产物；
- 云同步和云构建是增强服务，不是打开工程的前提；
- 核心运行时与编辑器分离，发布游戏不携带编辑器。

### 4.5 Build Anywhere

- Web：本地/浏览器可直接生成静态包。
- Windows：云端或本机生成安装包/便携包。
- Android：云端 Gradle 构建 APK/AAB。
- iOS：macOS/Xcode 构建节点生成 IPA/TestFlight 产物。
- 构建输入、工具链和产物都可追踪，支持可复现构建。

### 4.6 Open Extension Ecosystem

- 自定义剧情命令；
- 自定义资源类型；
- UI 组件和主题；
- 导入器/导出器；
- Live2D、Spine 等许可隔离插件；
- 分析、翻译、配音和 AI 助手集成。

### 4.7 Expressive Professional Studio

编辑器首先是一套现代、图形化、多彩且具有高质量动效的导演工作台，但视觉表现不能以牺牲专业密度和生产效率为代价：

- 颜色必须表达对话、角色、画面、音频、逻辑、选择和诊断语义；
- 动效必须解释空间、因果、运行状态和直接操控，并可被输入打断；
- Writer、Director、Flow、Production、Debug & QA、Mobile Focus、Quick Start 七种工作模式共享同一工程格式；
- Beginner/Pro 只是默认布局不同，不制造能力阉割版工程；
- 专业基线对齐 Naninovel 的脚本/可视化双轨与 Utage 的表格化批量生产；
- 最终作品以商业 Galgame 的演出、音画、UI 完整性、稳定性和多平台一致性验收。

详细标准见[《视觉体验与商业制作基准》](10-visual-and-production-bar.md)。

### 4.8 Budget-driven Optimization

容量、速度和稳定性从项目建立时就进入预算，而不是发行前临时压缩：

- 同时衡量下载、安装、补丁、系统内存、GPU 内存、解码、加载和帧时间；
- Optimization Center 提供 Quality First、Balanced、Small Download、Low Memory 和 Custom Profile；
- 图片、音频、视频、字体、语言、脚本、插件和章节包分别优化；
- Story Graph 参与下一场景预测预载，资源生命周期使用引用计数、LRU 和显式释放；
- 弱网、断网、低内存、前后台切换、磁盘不足和损坏缓存都有可恢复路径；
- 自动优化不覆盖源素材，必须展示量化收益、质量差异、工具版本和回退方式。

详细标准见[《容量、性能与运行稳定性优化规格》](12-size-performance-stability.md)。

## 5. 渐进式复杂度

产品应允许用户沿同一项目逐步成长：

| 阶段 | 用户看到的界面 | 高级能力 |
|---|---|---|
| 第一次使用 | 模板、舞台、对白卡片、预览 | 隐藏脚本与复杂状态 |
| 开始分支 | 选择卡、简单变量、路线图 | 自动生成默认条件 |
| 中型项目 | 章节、搜索、表格、本地化 | 批量操作、语义重构 |
| 高级项目 | 脚本、调试器、QA | 函数、插件、运行时服务 |
| 团队生产 | 审阅、状态、构建中心 | 权限、语义合并、发布门禁 |

新手模式和高级模式不能生成不同工程格式。

## 6. 非目标

首个生产版本不做：

- 通用 3D 游戏引擎；
- 角色建模、绘画、视频剪辑或完整 DAW；
- 自研 Live2D 替代品；
- 主机平台一键发布；
- 交易和内容分发平台；
- 复杂 RPG 战斗编辑器；
- 强制在线账户；
- 自动生成整部作品的一键 AI。

这些能力可通过插件、外部工具或后续生态解决。

## 7. AI 策略

AI 是可选助手，不是项目格式的一部分。

适合：

- 台词润色候选；
- 分支一致性检查；
- 角色口吻检查；
- 翻译初稿与术语检查；
- 资源自动标签；
- 自动生成测试路径和假数据。

约束：

- 默认关闭，明确展示数据发送范围；
- 支持自带密钥和可替换供应商；
- 不用用户项目训练模型；
- 生成内容保留来源与审批状态；
- 所有核心功能无 AI 仍可使用。

## 8. 成功标准

### 用户任务指标

- 新用户 15 分钟内完成含选择的可玩短篇；
- 现有用户在手机上 3 分钟内完成台词修改并看到预览；
- 10 万字项目全局搜索响应小于 300 ms；
- 路线图只加载当前层级，10,000 场景节点项目仍可导航；
- 发布前自动发现 95% 以上的结构性引用错误；
- 同一项目四平台关键剧情状态一致。

### 产品指标

- 首日完成首个可玩预览的比例；
- 从创建项目到首次成功构建的中位时间；
- 7 日创作留存；
- 跨设备继续编辑率；
- 构建成功率和平均排队时间；
- 被 QA 检出并在发布前修复的问题数；
- 因锁定或格式问题导致的项目丢失率必须接近零。

### 体验与成品指标

- 七种工作模式的核心任务均有明确任务完成率和耗时基线；
- 编辑器关键动效在目标设备达到 60 FPS，且不阻塞输入、保存和撤销；
- 减少动效模式覆盖全部核心流程，不降低可理解性；
- 使用同一工具完成 20–30 分钟商业级 Benchmark Episode；
- Benchmark Episode 在 Windows、Web、Android、iOS 的剧情状态、存档和关键画面一致；
- 成品按演出、音画、UI、排版、操作和稳定性与选定商业参照池进行同维度评审。

## 9. 商业与开源建议（待确认）

推荐“开放工程格式 + 开放核心运行时 + 可审计本地编辑能力 + 收费云服务”的模式：

- 免费：本地编辑、Web 导出、开放格式、基础运行时；
- 个人订阅：云同步、构建额度、版本历史；
- 团队订阅：实时协作、权限、审阅、组织构建；
- 市场分成：主题、模板、插件；
- 企业：私有构建节点、单点登录和长期支持。

具体许可证需要法务与商业模式评审后决定，不能在调研阶段默认采用某个开源许可证。
