# 长篇普通推进与恢复线程输入 · 2026-10-16

接续 [#349](349-web-checkpoint-responsiveness.md) 的实际工作区，继续处理普通单句推进和后台保存对阅读的影响，交付 1.7.11 Web 候选。

## 已开发

- 一次完整历史验证期间，共用已验证的不可变字符串及其 JSON 引号结果。保留上限为 512 个、输入/输出合计 64K 个 UTF-16 单元，单字符串不超过 512 单元；不保存对象、数组、编码字节或哈希结论。嵌套范围独立，成功/异常后均恢复并释放，下一次操作仍完整检查旧历史。
- 历史每个 checkpoint 的结构和哈希、每个 entry/归档/输入仍重新核对。只是相同键名、已读文本 ID 等字符串在同一次同步验证中不反复做 NFC/引号处理。最终 JSON 的 NFC/UTF-8 边界继续验证；中文、补充字符、转义组合和畸形字符串规则保持。
- 已读/收藏/结局 ID 校验合并为一次顺序扫描，保留 ID 格式、数量、排序和唯一性要求。
- 独立恢复以及手动/快速/场景自动/检查点保存发给 Worker 的数据，只包含正式序列化器需要的剧情程序、完整历史、当前状态和回想隔离信息，不再复制无关的编译目录、Host 操作或旧候选。Player Core 保存接口接受最小的剧情程序输入，原完整 Core 调用仍兼容；使用相同公开序列化器，存档字节/哈希和后台取消/超时/物理写入规则保持。
- 实际发布时发现双位数版本的显示问题：`1.7.10` 按文本排序会出现在 `1.7.2` 前。兼容版本提示现按数字顺序显示；工程中兼容记录的排序/格式及源身份保持，导出脚本分别检查显示顺序与真实记录。
