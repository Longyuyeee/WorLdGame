# 信息架构与交互设计

## 1. 设计原则

1. **上下文不丢失**：从路线、脚本、时间线或预览切换时，仍定位同一场景和语句。
2. **移动端不是缩放版桌面**：手机一次只完成一个主要任务。
3. **拖拽不是唯一交互**：所有拖拽都有菜单、键盘或文本替代。
4. **错误就在内容旁边**：诊断可点击、可解释、可快速修复。
5. **高级能力逐步出现**：新手只看到必要字段，专家可展开全部参数。
6. **预览永远可到达**：任何编辑视图最多一次操作进入当前上下文预览。

## 3. 桌面工作区

### 3.1 默认布局

| 区域 | 内容 |
|---|---|
| 顶栏 | 项目、全局搜索、保存/同步状态、预览、构建 |
| 左侧导航 | 章节/场景、角色、资源、UI、本地化、QA |
| 中央主编辑器 | Route、Sequence、Script 或 Stage |
| 右侧 Inspector | 当前语义对象参数、引用和诊断 |
| 底部可选面板 | 运行日志、变量、调用栈、构建日志 |

面板允许调整、停靠和保存布局，但中央主编辑器始终保持最大视觉优先级。

### 3.2 上下文同步

当用户选择一条对白时：

- Sequence 滚动并选中对应块；
- Script 定位对应语句；
- Stage 显示执行到该语句后的画面；
- Route 高亮所在场景；
- Inspector 显示对白、角色、表情、本地化和配音；
- Debugger 可从该语句启动。

这个关系由稳定语义 ID 实现，而非行号。

## 4. 平板工作区

平板默认双栏：

- 主栏占 65%：当前编辑器；
- 辅栏占 35%：Inspector 或 Preview；
- 左侧项目树以可收起 Drawer 出现；
- 横屏保持双栏，竖屏切换为单栏 + 底部 Sheet；
- 支持触控笔框选、拖动和快捷菜单。

## 5. 手机工作区

### 5.1 底部主导航

- **故事**：章节、场景和路线；
- **写作**：Sequence/Script 的移动版；
- **舞台**：视觉位置与演出；
- **资源**：导入、拍摄、录音、标签；
- **运行**：预览、QA 和构建。

### 5.2 手机写作模式

- 默认显示单列内容块；
- 上下滑浏览，左右滑不承担危险操作；
- 轻点块进入编辑，长按打开排序/复制/删除；
- 键盘打开后，格式栏贴近键盘上方；
- “下一条/上一条”用于连续录入；
- 选择、条件和跳转使用表单式目标选择；
- 可切换纯文本模式进行高速写作。

### 5.3 手机路线模式

节点图不是唯一入口：

- 默认显示场景列表与缩略路线；
- 进入局部分支后才显示可拖动节点；
- “连接到……”菜单可替代拖线；
- 双指缩放，单指移动需从空白区开始；
- 顶部提供“从入口到这里”“从这里到结局”路径按钮；
- 超大图用章节导航和搜索，不一次渲染全部节点。

### 5.4 手机舞台模式

- 画布占主要空间；
- 选中角色后出现底部控制条：位置、大小、表情、进入/退出；
- 双指缩放画布，拖动对象只在选中后生效；
- 精确数值进入底部 Sheet；
- 提供安全区、横竖屏和常见设备预设；
- 所有手势可通过数值/对齐按钮完成。

## 6. 四视图工作流

\`\`\`mermaid
flowchart LR
    Route["Route Map\n组织跨场景路线"] --> Sequence["Sequence\n编排场景内容"]
    Sequence --> Stage["Stage\n调整视觉演出"]
    Sequence <--> Script["Script\n高速写作与批量修改"]
    Stage --> Preview["Live Preview\n从当前语句运行"]
    Preview --> Debug["Debugger / QA"]
    Debug --> Route
\`\`\`

### 6.1 Route Map

只承载高层语义：

- 章节；
- 场景；
- 结局；
- 跨场景跳转；
- 路线条件摘要。

场景内每句对白不默认展开为节点。

### 6.2 Sequence

面向非程序用户的主要创作界面：

- 顺序块适合对白密集内容；
- 分支块在原位置展开，不把内容拆散到全局画布；
- 演出块可折叠为摘要；
- 条件复杂时可进入局部子图；
- 提供“只看对白”“只看演出”“只看逻辑”过滤器。

### 6.3 Script

面向键盘用户和版本控制：

- 输入时实时解析；
- 不完整语句允许短暂存在，避免每个字符都阻断；
- 诊断区分错误、警告和建议；
- 可视化无法识别的新插件命令必须原样保留；
- 格式化不能重排对白或改变语义 ID。

### 6.4 Stage

Stage 是某个运行时状态的视觉投影：

- 默认模拟执行到当前语句；
- 直接拖动角色会生成/修改对应演出命令；
- 如果视觉修改需要插入新命令，必须显示将插入的位置；
- 修改 UI 主题不会污染剧情脚本。

## 7. 关键任务流程

### 7.1 新手首个短篇

\`\`\`mermaid
sequenceDiagram
    actor Creator as 创作者
    participant Home as 新建向导
    participant Editor as 编辑器
    participant Preview as 预览
    participant Build as 构建
    Creator->>Home: 选择“恋爱短篇”模板
    Home->>Editor: 创建角色、场景与默认 UI
    Creator->>Editor: 写对白并添加两个选项
    Editor-->>Creator: 实时显示路线和错误
    Creator->>Preview: 从当前对白试玩
    Creator->>Build: 生成 Web 分享链接/包
\`\`\`

### 7.2 手机继续编辑

1. 打开最近同步或本地导入项目；
2. 首页显示上次编辑场景和待处理诊断；
3. 进入写作模式，定位上次语句；
4. 修改台词或替换资源；
5. 点击预览，保持当前上下文运行；
6. 自动保存本地，联网后增量同步；
7. 如需发布，提交云构建任务。

### 7.3 本地化与配音

1. 冻结一批文本 ID；
2. 导出翻译表或分配在线任务；
3. 译者查看截图/上下文并填写；
4. 编辑器标记缺失、过期和溢出；
5. 导出配音台本；
6. 文件按文本 ID 自动关联；
7. 在目标语言下批量试听和 QA。

### 7.4 构建失败

1. 构建中心显示阶段：校验、编译、资源处理、平台包装、签名；
2. 错误使用用户语言解释，并保留原始日志展开项；
3. 能定位工程内容的错误直接跳转；
4. SDK/签名类错误进入修复向导；
5. 修复后只重跑受影响阶段；
6. 相同输入可复用缓存。

## 8. 诊断交互

每条诊断至少包含：

- 严重级别；
- 人类可读标题；
- 原因；
- 影响；
- 内容位置；
- 建议修复；
- 可自动修复时的预览；
- 规则 ID，便于忽略或团队配置。

发布门禁默认阻止：

- 缺失入口；
- 悬空跳转；
- 确定性死循环；
- 缺失 P0 资源；
- 工程格式不兼容；
- 签名配置无效。

## 9. 可访问性

编辑器：

- 键盘完整操作；
- 屏幕阅读器标签；
- 不只用颜色表达状态；
- 可调字号、对比度和动效；
- 触控目标不小于移动平台建议尺寸；
- 拖拽都有替代命令。

运行时：

- 自述/文本朗读；
- Alt 文本；
- 字体、行距、对比度和文本速度；
- 减少动态效果；
- 字幕和音量分通道；
- 触摸、鼠标、键盘和基础手柄。

## 10. 原型验证任务

原型测试不询问“你喜不喜欢”，而观察任务：

1. 创建角色并写三句对白；
2. 添加两个选项并连接不同结局；
3. 找出一个不可达场景；
4. 在 Script 改名并确认 Sequence 同步；
5. 在手机上替换立绘并移动角色；
6. 从第二个选项直接预览；
7. 导出 Web；
8. 找到某变量在哪里被修改；
9. 将一个场景交给译者并查看状态；
10. 恢复误删内容。

通过标准：目标用户无需口头指导完成 8/10，且核心任务没有数据丢失或不可逆操作。
