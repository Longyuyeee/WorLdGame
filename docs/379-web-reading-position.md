## 实际问题

用 #378 的真实 HTML，在 390×844 竖屏将个人字号调到 140%，滚动至第一段中部，再切为 844×390 横屏并转回竖屏。旧实现只保留 scrollTop；横屏内容变短后，浏览器将 220px 夹至 79px，回到竖屏仍为 79px，顶部完整可见行的起点从索引 55 退至 22，回退 33 个字符。剧情 hash 没变，但玩家需要重新寻找读到的句子。[原测量](../evidence/web-reading-position/baseline.json)和[返回竖屏前后问题画面](../evidence/web-reading-position/before-rotation-returned.png)保留。

## 阅读行为

当前段落以可见文字及其相对位置作为临时锚点，重排后让原阅读位置所在行继续可见，回到原布局时恢复原位置。旋转、个人字号、字体就绪、主动全屏和菜单往返共用这项保护，不用滚动百分比替代文字位置。

主动向上／下滚动会更新阅读点；浏览器因重排夹住滚动范围，以及保护自身引起的滚动事件，不会反过来覆盖旧阅读点。临时整段可见、隐藏或零高度也不丢弃原锚点。没有主动滚动的新段落保持从顶部显示；明确读到段尾后，重排仍留在段尾。换段、历史回退／前进、语言或工程变化重新从对应段落开头显示，不沿用上一段的文字偏移。

Auto 继续等待未读的下方正文；重排后先更新未读状态，再按原规则调度，不因缩小窗口、字号变化或恢复前台直接跳过正文。点击文字仍先显示全文／读下一屏，读完后才推进；没有改变原语音等待、输入与保存规则。

## 实现与边界

逻辑位于 Player 的 [reading-position.ts](../apps/player-shell/src/reading-position.ts)与 [use-reading-surface.ts](../apps/player-shell/src/use-reading-surface.ts)。只处理当前段落的 DOM 几何，不读取全篇或历史、不创建逐字节点；字符矩形通过二分查找，跳过 ruby 注音并避免拆开 UTF-16 代理对。记录使用 CSS 滚动像素，考虑界面缩放；正文关闭浏览器原生 overflow-anchor，避免两套定位相互争抢。缺少 Range 几何能力的宿主保留像素回退，不以回退冒充文字定位保证。

这是一份**当前页面内、当前段落的显示状态**，不写 Runtime、工程、手动／快速／恢复存档或备份。刷新、重开或读取存档仍按原契约恢复段落和剧情，不承诺恢复段内滚动位置；没有新增格式、兼容回执、跨设备同步或已读迁移。叙事内容和媒体均未改变，不增加作品版本。
