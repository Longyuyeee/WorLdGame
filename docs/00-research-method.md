# 调研范围与方法

## 1. 调研目标

本轮调研回答五个问题：

1. 成熟 Galgame/互动叙事工具各自解决了什么问题？
2. 它们在大型项目、多人协作和移动创作时为什么失效？
3. 哪些能力属于视觉小说运行时的行业基线，不能被当作差异化卖点？
4. 跨端编辑和跨平台发布在技术与产品上有哪些硬约束？
5. WorLd Studio 应该聚焦什么，而不是无限扩大范围？

## 2. 调研对象

### 核心视觉小说工具

- Naninovel
- Unity Visual Novel Tool “宴” / Utage
- WebGAL 与 WebGAL Terre
- LetsGal Studio
- Ren'Py
- Visual Novel Maker
- TyranoBuilder / TyranoScript

### 叙事语言与对话中间件

- Yarn Spinner（用户所说的 “Yaspinner” 按 Yarn Spinner 理解）
- ink / Inky
- Twine
- Dialogic

### 跨设备编辑与云发布参照

- GDevelop
- Construct 3
- Kocho（历史移动端参照）

## 3. 统一评价维度

| 维度 | 关注问题 |
|---|---|
| 创作模型 | 文本、表格、节点、命令列表还是混合模式？ |
| 大型项目 | 数万行、多章节、多路线时是否仍可搜索、拆分和版本控制？ |
| 可视化 | 是否能编辑，而不只是展示流程？ |
| 实时预览 | 修改是否能定位并刷新到当前语句？ |
| 调试与 QA | 是否检查不可达、死路、变量和本地化问题？ |
| 演出能力 | 角色、背景、音频、视频、摄像机、动画、Live2D/Spine 等 |
| VN 基础系统 | 存读档、回滚、跳过已读、自动播放、日志、鉴赏等 |
| UI 定制 | 新手能否换主题，开发者能否深度扩展？ |
| 本地化 | 稳定文本 ID、翻译状态、配音资源和文本溢出检查 |
| 扩展性 | 自定义命令、插件 API、运行时替换和源码开放程度 |
| 跨设备创作 | Windows、浏览器、平板、手机上的实际编辑能力 |
| 发布 | Web、Windows、Android、iOS 以及签名/商店流程 |
| 协作 | Git 友好性、实时协作、评论、权限和冲突处理 |
| 可迁移性 | 是否能导出可读源文件，是否被专有平台锁定？ |
| 商业与许可 | 购买、订阅、运行时授权、第三方 SDK 许可风险 |

## 4. 证据等级

- **A 级**：官方产品页、官方文档、官方源码仓库。
- **B 级**：作者演示、公开发布视频、官方商店页面。
- **C 级**：社区讨论和个人经验，仅用于发现痛点，不作为唯一技术事实。
- **待验证**：公开资料不足或版本仍在快速变化，必须安排实际试用。

文档中涉及 LetsGal Studio 的结论主要来自公开 B 站演示，因未找到同等完整的官方文档，其功能完整度、导出范围与工程格式均标记为待验证。

## 5. 研究限制

- 厂商功能页能证明“宣称支持”，不能证明大型生产项目中的稳定性。
- 社区反馈存在样本偏差，只用于生成假设。
- 移动端商店应用可能因地区或版本变化不可用。
- iOS 签名、应用商店审核和 SDK 版本会变化，发布设计必须在实施前重新核验。
- Live2D 等第三方 SDK 具有独立许可，技术可行不代表可以随编辑器自由再分发。

## 6. 后续实测计划

进入交互原型前，安排以下同任务测试：

1. 新建含两名角色、两条路线和两个结局的 15 分钟短篇。
2. 批量导入 100 张立绘/背景和 200 条语音。
3. 修改角色名并检查所有引用。
4. 添加变量条件并定位不可达结局。
5. 导出 Web、Windows 和 Android 测试包。
6. 在手机上修改台词、替换立绘、连接分支并重新预览。
7. 两人同时修改不同章节，再模拟修改同一段文本。

每个竞品记录完成时间、点击数、错误数、能否恢复、产物大小和阻塞原因。
