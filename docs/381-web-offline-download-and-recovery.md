# 381 离线下载进度 取消与恢复

2026-10-17，接续 [#380](380-web-story-branch-context.md)，按 [#304 Web 完整作品交付](304-web-complete-gal-delivery.md)进入同版网站交付复核。复查九场景脚本后没有新增明确的剧情修订，本批解决实际慢网下载时看不出进度、不能取消、失败后不知道哪个文件出错的问题。作品仍为 **1.9.0 内容候选**，技术基线仍 S0.41。

## 玩家流程

在标题或阅读菜单点击下载后，现在显示已处理／清单文件总数和当前文件，可取消本次下载；返回故事、保存或关闭再打开菜单，下载继续进行，状态与取消入口保持。键盘取消后焦点返回重试操作，不落到页面底层。这里是**文件计数，不是已下载字节百分比**，大文件尚未完成时计数可以停留，不显示虚构速度或剩余时间。

下载失败会指出具体文件；HTTP 错误显示状态码，摘要不匹配说明可能上传不完整。普通下载／缓存补齐对应“重试离线下载”，新版下载对应“重试更新”，不会误把重下载旧版当作更新成功。取消初次安装清理本次不完整缓存；取消已有缓存的补齐保留已有文件；取消或失败的新版本不替换旧缓存、不删除玩家存档。完成下载后仍等待所有游戏窗口关闭再正常激活，没有增加强制跳转或自动读取存档。

实现位于 [web-offline-export.ts](../apps/editor/src/web-offline-export.ts)。Worker 只向本游戏 scope 下的窗口报告进度；客户端同时核对 Worker 身份和请求 ID，其他窗口的修复不能用错误 ID 取消。请求 AbortController 中止网络，回写缓存前再次检查取消。文件仍按原摘要校验后写入，不把部分下载标为就绪。

实测修正三处时序问题：取消后检查状态不得重建刚删除的空缓存；CACHE 的失败回包先于取消确认时不得误报下载失败；Worker 已进入 redundant 后才到达的文件错误仍需显示，但不能覆盖后续新下载。旧 STATUS 结果和迟到任务结果也不能覆盖新的操作状态。相关回归覆盖了两种回包顺序与错误事件顺序。

- **71 项相关回归／10 文件**通过，[结果](../evidence/web-offline-download/related-tests.json)包含新增 Worker 任务／取消、UI 回包顺序、具体文件错误、独立请求与菜单键盘循环；另有 **18 项 Node 工具测试**通过。根类型检查、Editor／Player 构建和 118 个便携文件＋4 个 Node 适配文件的架构审计通过；仍有 Vite 大 chunk 警告，未运行全仓 check 或长期 soak。
- [原界面复现](../evidence/web-offline-download/baseline.json)：实际 1.9.0 网站在 player.js 下载处等待时没有文件进度或取消按钮。[修复前失败](../evidence/web-offline-download/before-fix-failure.json)保留“具体文件错误被迟到状态覆盖”的失败，不替代最终结果。
- [Chromium 七组实际任务](../evidence/web-offline-download/browser-checks.json)：真实导出、首次下载的进度／阅读／保存／取消／503／重试；删一张背景后的补齐取消、保其他文件、重试、断网刷新读档；旧缓存的更新取消／失败／重试／等待关闭／重开断网读回原 hash。缓存完成后实际逐份核对 35 个清单文件的字节摘要；这不是新增“每次打开都重新校验全部缓存”的产品功能。
- 旧缓存更新场景通过 Chromium 的硬刷新绕过缓存，取得真实新页面，同时保留真实旧 Worker、缓存和槽位；随后恢复正常网络路径，使用真实新 Worker 下载／取消，未伪造游戏或 Worker 字节。该定向任务只证明硬刷新取得新版 UI 后的流程，不声称旧 UI 自动获得新按钮。
- 当前网站从入口完成离线桌面“留下”和在线 390×844“远行”路线，各 66 段正文、6 句静音观察的原生语音自然结束，合计两结局；两条路线在公交站／新照片段快速保存、刷新读取后恢复原 hash。手机尺寸不是物理手机，静音不是人工听感，loopback 不是已上线公网。
