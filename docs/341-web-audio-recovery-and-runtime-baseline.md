# 声音失败恢复、无声阅读与媒体基线纠偏 · 2026-10-16

接续 `b03a2c2` / [#340](340-web-deployment-check-and-offline-update.md)，首先处理其第一接续项：把实际离线音频失败与游戏/缓存实现区分，再补玩家可操作的恢复闭环。对齐 [#304](304-web-complete-gal-delivery.md)，没有转做原生平台或另造媒体引擎；不为本机测试端口的限制预载全作品或改写存档。

## 先前悬而未决的问题，现在查到哪一层

独立 `tools/probe-native-audio.mjs` 不导入游戏、React 或存档。用脚本生成的一秒 PCM16 WAV 与作品原雨声，对照 HTTP、Blob、data 三种真实原生 audio 地址，再做隔离 Worker 的缓存/Range 和停服对照。每种引擎六个无 Worker 媒体案例、三个受控媒体案例，共 27 个实际案例；以原生时间推进和错误记录判断，不注入 ended/假 audio 对象。正对照 Chromium/Firefox 必须通过，否则探针失败。

本机 Windows / Chromium 151、Firefox 153 的 HTTP/Blob/data、Worker-only 地址和 origin 停服播放均成功。**Windows Playwright WebKit 26.5 的同一 WAV 经 HTTP 可以播放，但 Blob/data 未成功，Web Audio 接口不可用。** 进一步对照：

- JS 向仅在 Worker 中存在的 WAV 请求 Range，得到带诊断标记的 206、正确两字节。
- 原生 audio 请求普通 HTTP WAV 时，origin 收到直接请求，而 Worker 的 fetch 记录为空。
- 原生 audio 请求同一个 Worker-only 地址时，origin 收到请求并返回 404，Worker 仍未收到；音频失败。
- origin 停服后，新 URL（避免复用先前媒体缓冲）在 Chromium/Firefox 走 Worker 并播放，在本机 WebKit 未播放。

因此，#340 的现象已经定位到**本机 WebKit 原生媒体加载路径没有经过 Worker**，并非游戏缓存缺媒体或 WAV 本身普遍不可解码。这里依据本机请求对照作边界结论，不声称已定位 WebKit 内部具体函数/补丁，也不推断真实 Safari/iPhone 同样失败。[Playwright 官方浏览器说明](https://playwright.dev/docs/browsers)明确不同操作系统的媒体能力有差异、接近 Safari 的媒体验证应使用 macOS；该说明不代替本机实测。

本批不把此限制写成“游戏离线音频已修好”，也没有改 UA、跳过媒体错误或用假播放事件凑严格矩阵。原 #340 失败报告保留历史；新的 `native-media-probe.json` 保存全部正/负对照。探针初次未处理 Web Audio 接口不存在而异常，补充能力缺失记录后完成；data 雨声在本机 WebKit 存在不报错但不推进的超时，也按未播放记录，不当成功。

## 玩家遇到声音问题，不再只有一个反复重试按钮

1. 声音失败显示作品中的实际素材名称，按媒体下载、解码、不能打开或未知错误给出保守建议：检查网络、重试、备份 `.worldsave` 后换浏览器/作者提供的完整目录、反馈作者。错误码不是准确 codec 诊断，不能断言所有同名浏览器都不支持。
2. 只有声音失败时，重试仅重建失败的**音轨/通道**。健康雨声/BGM、画面、当前段落和运行状态不重建；两个通道共用同一 Asset ID 时也按当前元素分别判断。现有宿主 `onRetryMedia` 回调保留。图片/视频缺失仍走原完整媒体修复，不能无声回退把它们遮掉。
3. 选择“本次先无声阅读”，停止 Auto/快进但不自动翻页；卸载当前声音元素，取消迟到播放请求、暂停并清空 detached src/load，释放其媒体加载。手动阅读、选择与保存可继续。它是本次会话决定，不改个人静音/音量、工程、剧情或存档，不记作音频播放通过。
4. 顶部工具栏显示“无声 · 恢复”，与画面/菜单同处，不持续用浮层盖住正文；窄屏缩短画面按钮文字但保留“欣赏画面”可访问名称。恢复只重新播放当前声音，不回退剧情、不自动重开 Auto，也不改个人音量。刷新/新页面恢复默认声音模式，若浏览器仍不支持会重新提示，不悄悄永久静音。
5. 权限拒绝仍走原“恢复声音”手势入口，不混成损坏文件。非权限的 play() 拒绝即便没有独立 error 事件也能给恢复出口；旧元素或取消请求的迟到错误不能污染新轨道。宿主暂停时不能重试或恢复。操作消失后焦点返回当前阅读控件，不触发推进。

实际截图发现初版长浮层在纸色主题对比不足、320 px/横屏遮挡正文，已改为工具栏状态并给权限恢复面板明确浅色文字；不是只检查 DOM 存在。本批不新增全作品预载、AudioBuffer 常驻、格式转换或旁路 Core 的声音状态。

## 验证范围

相关回归入口 `npm run audit:web-audio-recovery`：#340 的 206 项基线，加六个 Player 文件的 128 项，合计 **40 文件/334 项不同相关测试**；本批新增 16 项。覆盖按通道重试、只读状态/音量、Auto 停止、混合图片故障、暂停、手势权限、无 error 事件的拒绝、迟到请求、释放与手动继续，以及原 Player/阅读/设置行为。类型、Editor/Player 构建和工作区/架构/需求/交付基线四项审计另核对。既有 jsdom 原生 play/pause/load 未实现提示不代表真实播放，实际媒体证据以浏览器为准；大 chunk 警告保留，不声称完整全仓/soak 通过。

实际浏览器最终记录在 `browser-checks.json`，**默认三引擎的 17 个检查通过**；`requestedEngines`、`sourceReused` 和产物摘要明确检查范围：

- 作者实际保存重开/正式双导出一项。
- 三引擎各两项声音恢复：真实服务器故意漏一份 BGM，雨声保持播放；恢复文件后重试成功且健康雨声 DOM 与剧情 hash 保持。保存刷新后让全部声音失败，选择无声、320 px/横屏再恢复声音，同一状态、个人设置保持。
- 三引擎各一项实际 1.7.2→1.7.3 升级：旧版离线重开/显式读档，新版等待且第二窗口仍旧版，全部关闭后激活；新版本离线读取旧快速槽位、导入真实旧 `.worldsave`，显式读取后相同状态，原快速槽位打包记录不变。Chromium/Firefox 离线媒体实际播放；WebKit 使用已独立验证的 origin 停服，记录原生声音失败，选择无声后状态保持，恢复 origin、显式恢复声音才通过在线原生播放。后者仅算故障恢复通过，**离线原生播放保持 false**。
- 三引擎各两条在线完整路线，每路线 60 段旁白+6 对白、六句原生语音自然结束、两个正确结局，结尾无残留声音。没有派发假 ended 来越过等待语音。
- Chromium 本地 HTML 导入真实 1.7.2 备份、显式读取及媒体播放一项。WebKit 本地 HTML/Blob/data 播放不作通过承诺。

`passed` 仅代表报告列出的恢复/在线路线检查；`fullOfflineAudioMatrixPassed=false`、`offlineAudioFixed=false` 明确保留。没有把 Windows WebKit 当真实 Safari、桌面 320/390 px 当手机，也没有把原生时间推进当人工听感。#340 的漏传新版重试、不兼容拒绝、回滚为历史通过，本批没有重新制造不兼容剧情包来重复计数。

过程中的浏览器脚本先误以为快速保存后菜单仍开着，随后误用“读取进度”标题作 dialog 名称/把“快速”按钮当 tab；按真实“存读档槽位”弹窗和保存后状态修正，没有直接写数据库或移除读取确认。最近一次过程失败报告保留，仅以最终报告和一致产物摘要作为本批通过依据。

最后与真实浏览器并行复跑时，既有离页保护用例出现一次“按钮已保存，但 beforeunload 提醒仍存在”的断言失败，189/190 基线通过；该四项文件独立复跑全部通过。读取实际 `usePageLeaveGuard` 发现它在被动 effect 中移除监听，测试只等待 DOM 的保存按钮，没有等待清理。测试改为在原保存确认后明确 waitFor 提醒解除，不延长超时、不改变产品实现，也保留保存未完成/失败/新稿未保存必须提醒的检查；随后顺序完整复跑。该同步纠偏不算新产品功能或新增测试数量。正式目录的 player.js/player.css 另与当前源码即时生产构建逐字节比较一致。

最终结局截图还发现一个真实残留：音轨已停止/移除，恢复提示仍使用提交前的旧 DOM ref，最后一次渲染后没有新状态让它消失。新增“明确停止两条轨道后结局无恢复按钮”的回归先失败；提示改为只检查当前实际舞台音轨与对应元素，修复后通过。最初夹具的 end 本身没有 stop，因此先补明确的 stop 演出再复现，未把允许结尾音乐的工程强制静音。六条最终完整路线同时检查声音元素为零且没有残留恢复按钮。
