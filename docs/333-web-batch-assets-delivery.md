## 这批交付了什么

素材页可一次选择多份文件，在独立弹窗核对名称、用途和所选条目，再按既有媒体检查与保存流程逐项导入。图片可统一指定背景、立绘、CG 或界面用途，不改变音频用途；同名文件生成不同的新 ID，不覆盖已有素材。普通坏文件不阻止其他项完成；停止后保留已提交项，重试只处理未完成项，成功项可直接打开详情。

真实截图显示长列表结束后能看到失败数量，却未必看得到失败文件。本批增加“定位失败项”：滚到首个失败/名称校验不通过的条目，并把键盘焦点放到名称字段；移除后可定位下一项，无失败时隐藏。操作区保持可见，桌面、390 px、320 px 长列表及浅深主题截图已查看。

批量功能的主体实现来自 #331；本批补齐真实验收、失败定位、回归与可复跑脚本，而不是把这些既有代码算作重新开发。此前 #331 的暂停状态和未验收记录保留为历史。

## 边界与下一批顺序

每批最多 50 项/512 MiB，单项最多 64 MiB；逐项提交，不提供整批回滚。文件引用和未完成队列仅在内存，关闭/刷新不会恢复它们；已成功素材随工程保留。MIME/扩展名只是用途建议，仍需实际内容检查。本批浏览器覆盖 PNG/WAV，未新增字体/视频的整链浏览器验收。60 MiB 只证明此次读取阶段停止/重试，不表示每种提交时点都能撤销已完成事务。

下一批按用户实际作品任务继续，不先新增平台或无关功能：

1. **正文和演出定稿**：沿原 1.5.4 工程继续校订对白/旁白、演出切换、音乐与语音衔接；具体问题记入已有校订任务，修改后复测。自动读完两路线不是人工阅读/听感或 20–30 分钟计时结果。
2. **连续制作与实际运行问题**：对真实工程的冷打开、场景切换、连续写作/试玩和保存恢复实测，处理能复现的卡顿、媒体失败与操作阻塞。历史约 616.6 ms 长帧未在本批重新测量或关闭。
3. **兼容与发布准备**：按主流手机浏览器准备测试，取得可用设备后补实际触控、横竖屏、后台/恢复和保存；本机视口与 Chromium 不代替物理设备、Safari 或其他引擎。核对素材来源/许可、最终署名和作品展示资料，再进行实际托管地址回查。

公网、授权、人工定稿、实际手机和最终完整作品验收仍未完成；全仓测试、长期运行、完整旧档/离线升级链本批未重跑。Windows/Android 原生产品继续搁置。

## 换电脑复跑

先同步本分支并安装锁文件依赖。浏览器脚本需要 Playwright（本机使用 Codex 的工具运行时），默认使用其已安装的 Chromium；也可通过 `STUDIO_CHROME` 指定实际可执行文件。不把本机用户名或 Chromium 安装版本写死在脚本中。

先构建 Editor，在 `apps/editor` 启动生产预览：`npx vite preview --host 127.0.0.1 --port 5195 --strictPort`；另一终端在仓库根运行 `npm run audit:web-batch-assets:browser`。支持 `STUDIO_UI_URL`。脚本使用隔离浏览器项目，动态生成 WAV，并在结束时清理自己的临时文件；截图和检查结果写入证据目录。换机全新安装未在本批额外验收。
