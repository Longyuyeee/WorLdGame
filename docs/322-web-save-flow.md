# Web 存读档任务与进度保护 · 2026-10-15

接续 `b50d865`（#321）。本批完成“保存当前位置 → 选择旧进度 → 核对/取消或读取 → 返回故事 → 重开继续”的实际玩家流程。

## 已完成

- 原生存档弹窗先选择“保存进度 / 读取进度”。手动、快速槽位按任务显示一个动作；自动和检查点只提供读取。手动分页及既有备份页保留。
- 卡片分别显示槽位、场景、章节、本地时间。可用截图保留真实预览；无截图和空槽位使用紧凑文字，不铺大块空画面。桌面双列、手机单列，短横屏收起重复说明，留出槽位操作空间。
- 游玩中点击读取，先在同一个弹窗核对当前场景和目标进度。取消或 Escape 返回列表，进度保持；忙碌时不能关闭或取消读取。键盘/手柄确认和取消不穿透弹窗推进底层剧情。
- 手动、快速、自动、检查点及备份页的读档入口统一经过确认。标题没有正在进行的剧情时，沿原校验直接读取。
- 请求读取时保留所选会话摘要。确认时重新读取槽位；会话已变则拒绝，当前故事保持，并刷新列表，允许重新选择新版本。错误继续使用原兼容性和损坏提示。
- 成功读取后关闭自动/快进并清理旧的待完成媒体事件，返回手动阅读。
- 没有可用自动恢复时，标题提供“继续最近存档”，按已保存时间选择槽位并显示来源/场景/时间；点击仍走正式校验。有可用自动恢复时沿原恢复入口，避免两个继续入口并列；存档列表随时可打开。

保存覆盖仍使用原确认和写入流程；本批读档确认不提供手动覆盖写入的跨页面原子保证。槽位格式、Runtime、旧档兼容和已读/解锁合并规则未改。

实际任务：

1. 从当前《雨停之前》1.5.4 源工程真实导出 HTML 和目录。桌面 HTML 保存两个不同段落，检查任务/卡片和取消/Escape；同一浏览器数据区的第二个页面实际覆盖所选槽位，原页面确认被拒绝且 Runtime 摘要保持，重新选择后读取新正文、自动关闭。
2. 标题页通过实际界面清除自动恢复记录，再从“继续最近存档”读取最新手动槽位。另一个手动槽位仍能读取原段落；没有以两个来源地址或两个页面冒充物理跨设备。
3. 390 px HTTP 目录游戏保存/推进/取消/确认恢复目标段落，原生弹窗与 844×390 横屏范围核对，自动槽位可读，既有备份入口可达。本次没有重新执行完整备份文件往返或离线更新。

截图和报告在 `evidence/web-save-flow`：`desktop-save-cards.png`、`desktop-read-confirm.png`、`desktop-changed-slot.png`、`desktop-recent-title.png` 与手机/横屏截图；最终报告 `browser-checks.json` / `browser-final.log`。新游戏大小/摘要留在报告，生成后临时清理，没有重复提交大包或重发发行候选。

初始回归失败包括旧双动作/标签/默认页测试未走新确认路径，已迁移。短夹具最初错误要求旧存档摘要与读档后的 Runtime 全值相同；原 Core 会合并当前已读/解锁，改为核对目标内容、确认前进度不变及正式载入结果，没有更改 Core 或放松载入校验。类型检查曾发现测试辅助参数和未用变量，已修正。原日志保留；jsdom 的媒体 play/pause 未实现信息不作为真实播放结论。
