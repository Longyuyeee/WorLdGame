## 用户问题与恢复路径

原首页把各种不适用文件都显示成笼统的“工程包未通过校验”，有些只有缺少工程清单的技术错误。特别是同名作品同时导出了工程 ZIP、本地目录、网站上传 ZIP 和制作交付包后，换机作者容易把“能玩的游戏”当作“可以继续改的工程”。这批对应最初 PRD 的工程完整导入／导出、无账户恢复和可用失败反馈，不扩展原生平台或云账户。

| 所选文件或结构 | 当前反馈与下一步 |
| --- | --- |
| 网页目录 ZIP、网站上传 ZIP、只有网页入口的包 | 说明是网页游戏而非可编辑工程；回原电脑导出工程，或选择完整制作包 |
| HTML，即使改名为 ZIP | 说明网页不能恢复完整作者工程；不会打开或执行 HTML |
| 本工具导出的玩家 .worldsave | 指向同一作品游戏内“存读档 → 备份”，不能用玩家进度恢复作者素材 |
| 本工具导出的校订／试玩记录 | 先恢复对应工程，再去“检查”页导入，不自动创建空工程或合并记录 |
| 受支持 ZIP 中的工程／交付入口多套一层目录 | 解释额外层级，不自动拆层；优先选择原样导出的 ZIP |
| 有 source/project.zip、没有根目录 delivery.json | 不作为完整制作包导入；可重新取得完整包，或明确选择解压后的源工程重新校验，外层记录不自动恢复 |

恢复卡片就近出现在导入入口下方，显示实际所选文件名、分步指引和“重新选择工程或制作交付包”。焦点进入已经挂载的标题，重选同一文件仍触发新校验；打开其他任务会清除旧指引。首页另有折叠的换机说明，区分创作备份、公开游戏和玩家进度，提醒先在新电脑验证编辑、保存和素材，再处理旧备份。项目仅保存在当前浏览器和本机，不暗示 GitHub 或浏览器账户会自动同步创作内容。

## 校验与写入边界

文本用途提示只读取内存数据的前 4096 字节，匹配 HTML 开头或本工具文本导出的根元数据前缀，不解析完整玩家历史，不从文件扩展名判断成功，也不把提示视作文件真实、完整或安全的证明。不匹配时沿用原错误处理。

ZIP 用途提示在原路径、条目数量、展开大小、压缩方式和 CRC 检查之后执行。根目录已有 world.project.json 或 delivery.json 时，不走用途猜测，继续原工程 Schema、源素材大小／SHA、交付清单和工程身份校验；坏工程不能借一个网页入口被当作正常游戏绕过错误。额外套层只给操作指引，不自动选择内部工程，也不把缺清单的内部 ZIP 当成已验证源工程。

Worker 只返回有限的用途代码，界面使用本地固定指引，不把后台错误文本当作可信 HTML。未知代码继续原技术诊断。520 MiB 读取上限、512 MiB 展开预算、无 Worker 时只允许不超过 2 MiB 的兼容回退、超时、取消／卸载和迟到结果丢弃均保持。所有用途拒绝都发生在写入阶段之前；正式导入仍在完整校验后才创建工作区及恢复素材。Runtime、玩家存档、公开游戏和制作包格式不变。
