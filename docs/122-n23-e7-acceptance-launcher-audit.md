# N23-E7 一键验收启动器审计

> 审计日期：2026-08-15
>
> 实现前基线：`597244a280ab2a04a44d94e249b452cb651caf20`
>
> 分支：`agent/n22-stage-media`
>
> 结论：从干净仓库到生产构建验收编辑器已有单一 Windows 入口；真人状态仍为 N21 `0/1`、N23 `0/2`

## 1. 审计发现

此前软件代码和 N23 可玩闭环均可运行，但参与者启动编辑器仍需知道 npm workspace、Vite 开发服务器与端口。README 没有验收启动命令，也没有可执行门证明生产构建能通过 HTTP 完整加载。这会把开发环境知识错误地转嫁给非程序参与者，并使“软件无法运行”和“产品任务失败”混在同一记录里。

## 2. 本轮实现

- 根目录 [`start-n23-acceptance.cmd`](../start-n23-acceptance.cmd) 可直接双击；
- 若依赖不存在，只执行锁文件约束的 `npm.cmd ci`，不修改依赖版本；
- `npm.cmd run acceptance:n23` 生成 Editor 生产构建，以固定 `http://127.0.0.1:43123/` 启动并自动打开浏览器；
- 端口被占用时严格失败，不自动漂移到另一 origin，避免 OPFS 工程落入不可预测的存储域；
- 页面标题从内部阶段名 `S0` 改为面向参与者的 `WorLd Studio`；
- 关闭启动窗口或按 Ctrl+C 后停止本地服务，不对公网监听。

该入口需要本机预装 Node.js 22.12 或更高版本。它是 N23 验收环境，不是 Windows 安装包、签名应用或 N90/N110 发布产物。

## 3. 可执行审计

`npm.cmd run audit:n23-acceptance-launcher` 会真实执行以下链路：

1. 校验根脚本、双击入口、锁定安装和固定命令没有漂移；
2. 使用 Vite 生成 Editor 生产构建；
3. 在 `127.0.0.1:43123` 启动严格端口的 Preview Server；
4. 通过 HTTP 获取入口 HTML；
5. 获取入口引用的全部 JS/CSS 资源并检查非空；
6. 确认生产 JS 仍包含“打开五分钟验收工程”；
7. 关闭服务器并返回结构化结果。

本轮烟测通过：入口 HTML 569 bytes、主 JS 636,678 bytes、CSS 70,627 bytes。根级 `npm.cmd run check` 已接入该门，后续入口缺失、资源 404、端口启动失败或产品按钮从生产包消失都会使检查失败。

## 4. 验收者操作

1. 解压或拉取准备验收的确切提交；
2. 双击根目录 `start-n23-acceptance.cmd`；
3. 首次安装完成后浏览器自动打开；
4. 确认地址为 `http://127.0.0.1:43123/`；
5. N21 从“新建空白工程”开始；N23 从“打开五分钟验收工程”开始；
6. 验收期间保持命令窗口打开，结束后按 Ctrl+C。

主持人可以在参与者到场前完成依赖安装和启动，但不能替参与者执行 N21/N23 冻结任务。

## 5. 边界与下一门

E7 只关闭“验收软件没有稳定启动入口”的缺口。它不能替代真人操作，也不把开发版提升为正式桌面应用。风险例外现只允许并行形成 N30 Compiler 工程候选；产品验收顺序仍严格是先完成 `N21-HV-01`，再由两名不同参与者完成 `N23-PA-01`，两者通过并关闭 `RA-N21-002` 后才能进入 N31。

## 6. 复跑命令

```powershell
npm.cmd run audit:n23-acceptance-launcher
npm.cmd run audit:n21-human-validation
npm.cmd run audit:n23-product-acceptance
npm.cmd run check
```
