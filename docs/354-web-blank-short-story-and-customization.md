# 354 · 从空白工程做完短篇与自定义能力判断

2026-10-16，接续 #353 的实际未提交工作区。按用户要求，使用当前生产构建的真实界面完成一次作者流程；测试限于遇到的修复和实际产物。Web 优先，原生版本继续搁置。

## 这次实际做出的作品

《给明天的回信》0.1.0：一章、三个场景、46 段旁白/对白、1,552 个正文字符（含标点）、两条分支和两个结局。共 58 个剧情步骤，其中 9 个演出步骤；使用三张背景、一张立绘、雨声和背景音乐。故事围绕旧车站停用与写给自己的回信展开，两个结局分别是“有人等你回来”“把明天写进信里”。篇幅来自下载工程的实际正文统计，没有把两行测试句算成完整作品。

从首页新建空白项目，经“添加成段文字”输入正文、创建林晚、重命名章节/场景、新建分支场景、编辑选择目标、批量导入六个真实 PNG/WAV 文件、插入背景/人物/声音演出、设置入场转场与时长、设置暖纸/青绿外观和阅读参数，再填写版本与制作说明。正文和工程都通过正常界面创建，没有向浏览器存储或内部状态注入工程 JSON，也没有用已有《雨停之前》工程作为新项目起点。媒体复用 `assets/rain-story`，六项许可仍待处理，不能作为已获发行许可的素材。

## 遇到并修复的问题

**跨场景继承的角色无法直接从列表选择。** 在远行分支中添加人物退场时，“操作哪位角色”为空。旧界面只列本场景此前的角色，要求作者展开高级项手填 `actor_1`，对普通用户不合适。

修复 `direction-stage-context.ts` 和 `CharacterTargetFields.tsx`：保留本场景此前仍在场的角色列表，另外列出工程其他步骤使用过的角色，以素材名称显示“可能继承”候选。候选不自动选中，不假定任何分支一定经过人物登场；提示用完整试玩确认。相同位置去重、已有本场景角色不重复显示，新角色位置的全工程保留逻辑不变。兼容未显式写 `action=show` 的旧演出。

实际重新构建、刷新并重开工程后，在分支里选择“可能继承：林晚·微笑”，直接完成退场，独立导出的列车场景也确认没有残留立绘。修复前的两个源文件保留在证据目录 `baseline`。

**同名工程难区分。** 导入包会新增本地工作区，首页出现两张相同名字的卡片，原先只显示日期。已增加同名标记、最近打开提示和含时分秒的打开时间，按钮与更多菜单的无障碍名称也能区分；单击仍直接进入所选工作区，工程标题和内容不改。实际刷新后检查两张卡片并打开最近导入的一份，截图 `home-same-name.jpg`。

**测试声音打扰用户，已立即停止并补预览静音。** 用户要求后，先在独立玩家设置中勾选“静音全部声音”并关闭正在播放的测试游戏，再继续工作。编辑器预览增加默认开启、记住选择的“预览静音”；所有预览音轨在初次播放、资源就绪和重试时都先应用 muted，切场景/换工程沿用本机偏好，不改作品混音和导出设置。最终真实预览中 BGM/环境声音轨均显示静音，DOM 中两个正在播放的音频均 `muted=true`，另一个音频已暂停；随后退出试玩。见 `silent-preview.json` / `silent-preview.jpg`。后续测试保持静音；启动浏览器自动化时应使用静音输出选项，真实听感仅在用户明确要求时开展。本轮前段有声音，不能追记为全程静音。

## 下一步按用户任务推进

1. **P0：作者可编辑的游戏外观。** 在“游戏外观”内按标题、正文/选择、存读档、菜单/设置/历史、附加内容/结局分页面收纳；每页选择模板→调整组件参数→在真实播放器预览。先交付标题和正文/选择的完整链，再扩展其他页。支持撤销、恢复默认、保存重开和双导出一致。组件动作绑定使用现有运行能力，不让作者手写内部标识。
2. **P0：字体与可复用皮肤。** 直接从素材库选默认/姓名/正文/按钮字体，设置字号与间距；主题/皮肤资源包可导入、另存、跨工程使用。缺素材/不兼容版本有明确恢复反馈。作者不应通过修改 JSON 才能换字体和控件样式。
3. **P0：预设驱动的演出。** 提供有缩略图/演示的对话框、UI、人物、文字动效分类；选预设后改强度、时长、缓动、循环等参数，可保存为自有预设。在短篇中各实际使用一种并验证导出。区分舞台、UI 与文字效果，避免一个列表摊满全部参数。
4. **P1：剩余完成感。** 接通真实存档缩略图；明确跨结构编辑的撤销范围；逐步补视频/字体/界面素材实用流程与移动断点。沿当前短篇复用验证，不为每次小功能重跑所有历史候选。

下一批的完成判据：普通作者可以用自己的图和字体做出与默认皮肤明显不同的标题与阅读界面，并让同一效果保留在保存重开的工程、HTML 和目录游戏中。后续再逐页扩大 UI 自定义。当前没有把以上待开发项计为已完成。
