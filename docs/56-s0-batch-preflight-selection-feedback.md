# S0.37 批量预检与选择反馈审计

## 阶段目标

S0.37 不扩大批量编辑的写入权限，而是让 S0.36 已有能力在提交前可理解、可预测、可拒绝。作者必须能看见当前选择位于场景中的哪些步骤、同类 Cue 是否已完整选择、实际会修改多少项、多少项已经一致，以及是否存在会使整批失败的重复参数冲突。

本阶段继续关闭批量删除、跨场景修改和未审计参数；多选仍是 Writer 会话内的临时状态，project schema 保持 v2。

## 冻结契约

### 权威预检

`inspectDirectiveBatch` 与真实 `patchDirectiveBatch` 共用以下准入条件：

- 目标非空、稳定 ID 唯一且最多 256 条；
- source 与已解析文档语义一致且无阻断诊断；
- 每个稳定 ID 唯一指向 Directive；
- 所有目标使用同一种 `background`、`show` 或 `audio` 命令；
- 目标按稳定 ID 确定性排序。

预检只返回命令类型、排序后的 ID 和只读参数快照，不返回可提交 source。真实批量 Patch 必须先通过这项预检，再在局部工作副本中计算写入，因此界面提示不能成为绕开核心校验的另一条路径。

### 选择与范围反馈

- 进入多选后显示已选数量和真实场景步骤编号；六项以内逐项列出，更多选择显示首尾范围。
- “选择本场景同类”以当前首个 Cue 的命令为筛选条件；如果同类数量超过 256，按钮禁用并明确提示，绝不静默截断。
- “清空选择”只改变临时 UI 状态，不修改 source、revision 或持久化 schema。
- 0 条、1 条、混合类型和超过上限分别使用准确提示，不把空选择误报为类型冲突。

### 提交前摘要

- “将修改”表示当前参数值确实不同的目标数。
- “已一致”表示应用后不会产生字节变化的目标数。
- “冲突”表示该参数在单条 Directive 中重复出现，真实提交会整批拒绝。
- 实际修改数为 0 时提交按钮禁用，不创建 command 或空 revision。
- 摘要使用 `role=status`、`aria-live=polite` 和独立可访问标签；Cue、多选开关继续使用 `aria-pressed`。

## 手机端与视觉规则

- 选择范围、预检摘要和操作区在窄屏改为纵向排列。
- “选择本场景同类”和“清空选择”在手机布局中并列，触控高度至少 44 px。
- 颜色只作为辅助：数量、文字状态和禁用状态共同表达结果，冲突不会只依赖红色。
- 批量面板保持现代多彩的琥珀/紫色渐变，但不会遮挡权威脚本、Preview 或错误提示。

## 审计结论

1. 预检与写入不再各自猜测目标合法性，混合命令等失败会在任何参数 Patch 之前被识别。
2. UI 摘要基于当前投影参数并对重复 key 做冲突计数；最终安全性仍由 source 层再次验证。
3. 自动选择不会跨场景、不会超过上限、不会隐式选中不同命令，也不会产生 revision。
4. 已一致批次在 UI 被阻止；即使绕过 UI，核心 Patch 仍返回 `changed=false`，不会获得部分结果。
5. 真实浏览器审计发现并修复了“0 条选择被误报为类型不一致”的语义缺陷。

## 验证证据

- `npm run check`：45 个测试文件、302 项测试、TypeScript、生产构建、34 个可移植文件 / 3 个 Node adapter 架构边界、脚本与资源性能门全部通过。
- 256 条 Directive 预检 3.14 ms，冻结预算 500 ms；随后原子批量 Patch 293.89 ms，冻结预算 2,000 ms。
- 真实 Chromium 验证：默认 Preview 仍为 16:9 / 1920×1080；“选择本场景同类”得到步骤 `#1、#2`；设置 Fade 前显示 `2 将修改 / 0 已一致 / 0 冲突`；提交后 revision 只增加 1，摘要变为 `0 将修改 / 2 已一致`，按钮禁用；清空选择不增加 revision。
- UI 回归覆盖同类选择、范围摘要、无变化禁用、清空零写入和空选择准确提示；核心回归覆盖确定性排序、只读预检结果及既有混合/重复/缺失/超限失败。
