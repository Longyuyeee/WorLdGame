# 启动去重、长篇存读档与 1.7.6 候选 · 2026-10-16

接续 `0bb5e72` / [#344](344-web-bounded-image-decode.md)，按 [#304](304-web-complete-gal-delivery.md) 顺序处理剩余启动和长篇使用问题。不改变剧情、画幅或素材，不扩大到原生平台；没有许可/设备/网址就不代填通过。

## 先查真实代码，再定修复范围

Shell 的 state initializer 已用工程创建 Core，但项目重置 effect 在第一次挂载又创建了一次，重复执行正式编译和已核对版本的来源哈希。三项测试先明确复现“两次而不是一次”，再用当前 executable hash 记录已经初始化的内容；仅真正内容变化时重建，等价对象不重启，历史偏好仍按原政策单独更新。不是跳过编译、身份或旧档兼容验证，也不是用一个挂载布尔值忽略后续工程变化。

另用实际 Shell/IndexedDB 制作 480 段纯文字夹具，通过界面逐句到达 120/240/480 段，再保存、推进、显式读取。没有注入私有 History、直接填数据库或伪造语音/完成事件。原包代码在 480 段快速保存/读取分别出现约 144 / 227 ms 主线程任务，短篇无长任务不能代替它。

## 存读档计算与持久化边界

- 手动、快速、场景自动槽位的完整会话校验/序列化，以及显式槽位读取、显式恢复记录读取，调用同一个公开 Core 保存/读取实现，在支持时交给自持有 Worker。仍完整核对 History 链、格式、哈希、版本和 Meta Progress；Host 继续核对槽位摘要、原 build/scene、展示类型和标题，确认/覆盖/冲突规则未删。
- 保存捕获点击时的边界，不把后台完成时的新句子冒充原保存位置，也不把当前阅读倒退。读取继续保留正式的已读/收藏单调合并：读过下一句再读旧槽位，完整 state hash 可以合法改变，夹具核对恢复的正文、History 长度与 cursor，不强迫擦掉已读标记来追求旧 hash。正式作品的结局刷新仍实际核对同一受保护 hash。
- 每个 Shell 前台计算串行一项，与原独立恢复区的一项分开；最多两项计算并存，不为每句排前台任务。原正式写入协调器和存储编码/原子 IO 保留；没有把已经开始的物理事务伪装取消。换工程/内容、换存储/捕获器、卸载会取消计算及旧代队列，写入前和 UI 更新前复核上下文，迟到结果不得写回新范围。
- Worker 成功、错误、传输异常、5 秒超时、取消时终止并撤销自有 URL；错误不会清空旧槽位或恢复点。无 Worker / 构造被拒绝时用原完整校验兼容路径，并单独计 fallback，不宣称此时主线程不卡。原已读/回想、内存压力和正式元数据保护保持。
- 启动恢复读取变为异步后，错误应显示“后台校验未完成”而非把存档一概说成损坏；可重试读取原记录。测试抓到标题仍提供重新扫描而不是重试读取，修正标题与正文入口；不调用清除来解决计算超时。真正坏格式/未核对旧版仍按原诊断拒绝。

**未搬走的工作：**正式 Runtime 推进与剧情 checkpoint 生成、内存压力保护、存储编码/解码和 Host 展示投影等仍可能占主线程。前后台消息的结构克隆和状态回传也有成本，不能把迁移说成总 CPU 或物理内存消失。

## 过程纠偏与接续

初版长篇脚本误找只在紧凑布局显示的菜单；按实际桌面控件修正，没有更改产品来迎合探针。冷启动条件误把包含装饰箭头的 textContent 当纯按钮文字，修正为真实标题按钮可用后重跑，前期失败保留。Runner 测试复用假 Worker 后仍用首个请求 ID 回复，修正为对应最后一次请求，不增加超时。新异步读取使旧回归和矩阵的“点击后立即检查 hash”看到 `none`；改为等待真实恢复完成，再保留原 hash/结局/画面断言，不跳过检查或放宽预算。最终成功报告独立核对，不拿失败截图当完成画面。

一次三引擎矩阵在最后 WebKit 路线的“下一句”可点击稳定性等待处超时，保留 `browser-webkit-click-failure.json` / `webkit-click-failure.png`。随后同一包的独立 WebKit 两路线通过，尚未稳定复现根因；没有 force click、扩大超时或宣称修复了未知故障。收尾协议/队列所有权修正后重新正式导出，再重跑完整矩阵/连续使用/对应测量，不沿用前一运行时的通过记录；最终报告与当前四产物摘要对应。这次间歇性卡点仍应在真实 WebKit/Safari 使用中关注。
