# 视觉系统与实现接续

本设计共用布局、控件和语义，提供多种主题。主题切换属于用户偏好，保存在本设备，不写入剧情脚本；工程的游戏界面主题另存于项目。

## 1. 视觉方向

作者长时间面对中文文本，正文应当是主角。默认浅色使用冷白工作区、清楚的灰色层级和蓝色选中态；深色使用石墨背景与较亮文字；暖纸使用纸色与棕色强调。舞台和游戏画面始终按作品本身呈现，不随编辑器主题改变素材颜色。

| 令牌 | 晴空 · 浅色 | 夜航 · 深色 | 暖纸 · 写作 |
|---|---|---|---|
| 背景 | `#F4F5F8` | `#171B24` | `#F3EEE5` |
| 主内容面 | `#FFFFFF` | `#202631` | `#FCF9F3` |
| 主要文字 | `#202737` | `#E8EBF2` | `#403C35` |
| 次要文字 | `#697384` | `#A8B2C3` | `#81776A` |
| 分隔线 | `#E5E8EF` | `#353D4B` | `#E2DACF` |
| 强调 | `#3564E9` | `#90ACFF` | `#786348` |
| 轻选中面 | `#EEF3FF` | `#2B3857` | `#EEE8DB` |

语义颜色必须同时有文字或形状：成功勾选、错误图标、提醒符号。色彩不能单独表达类型、状态和可操作性。主题需要覆盖禁用、选中、焦点、错误、菜单、输入、覆盖层，而不只是背景换颜色。

## 2. 排版与空间

- 工具正文 14 px，辅助信息 12–13 px；中文写作正文 16–18 px、行高 1.8–1.95。手机输入不低于 16 px。
- 页面标题 24–28 px，部件标题 16–18 px；标题与正文靠字号和空间建立关系，不把所有标签做成大写粗体。
- 间距使用 4 / 8 / 12 / 16 / 24 / 32 / 48。主内容宽度依据任务，写作正文约 650–780 px；表格和路线可占更大画布。
- 圆角：控件 6–8 px，详情面与媒体 8–12 px。多层容器不反复套带边框卡片。
- 写作行用留白组织，媒体提示折成一行，分支块用一个语义边界。只有可独立选择的素材、工程等内容使用卡片。
- 主按钮按当前任务唯一强调；同一行可以有次按钮，但不能出现保存、构建、运行、修复全是同等强度。
- 图标使用同一套 Lucide，配可见中文标签；仅非常常见且有可访问名称的动作可只有图标。
- 不依赖悬浮才能发现必要动作。手机点击目标 ≥44 px，菜单和返回按钮不互相覆盖。

## 3. 布局合同

### 全局壳

顶部：返回项目首页、工程名称、真实保存状态、工程搜索、试玩。主导航只负责切模块。模块内标签负责切页面。当前页面的操作栏负责局部动作。底部状态低强调，不显示 Schema、Source of Truth、Effect ID、内部 revision。

写作：场景列表 + 单个正文，画面/属性按需。演出：画面 + 选中对象 + 下方时间线。路线：画布 + 选中节点详情。生产工具：列表或网格 + 当前项详情。发布：步骤 + 当前步骤表单。不能为了复用布局把所有工具页变回三列大表单。

### 交互容器

| 组件 | 默认行为 | 应用 |
|---|---|---|
| AppShell | 管理模块导航与场景上下文 | 工程全局 |
| ModuleNav | 明确当前页面，路由可返回 | 场景/路线/角色/变量等 |
| SceneEditorShell | 保存当前语句身份与编辑位置 | 写作/演出/脚本 |
| ContextDrawer | 一个当前对象，关闭后返回发起控件 | 属性、素材、翻译、动作 |
| TaskDialog | 标题、内容、取消/确认；焦点约束 | 新建、命名、短确认 |
| NestedTaskPage | 父草稿快照、返回栈、选中结果 | 选择场景/素材/导入差异 |
| NoticeBanner | 需要处理的持续状态 | 保存失败、占用、缺失素材 |
| EmptyState | 给一条真正可执行的起步动作 | 新工程、没有素材、无存档 |
| ActionMenu | 单对象次要动作，风险区分隔 | 槽位、场景、素材 |
| StatusLine | 少量安静的真实状态 | 保存、当前场景、语言 |
| ImportReview | 差异、阻断原因、整体提交 | 素材与翻译 |
| PublicationWizard | 可返回步骤、产物历史 | Web/Windows 构建 |
| PlayerOverlay | 冻结推进，退出恢复来源状态 | 存档、历史、菜单 |

同一个弹层系统管理桌面 Drawer、Dialog 与手机全屏页。弹层内选择不是第二个 modal；操作栈记录父草稿、滚动、焦点和结果。所有业务变更只在显式提交或既有直接编辑事务中进入 Canonical Project。

## 4. 动效

- 按钮与选择反馈 100–140 ms，抽屉和内容切换 160–220 ms。动效解释开合和对象关系，不装饰长时间工作区。
- 保存、输入、撤销与导航不等动效结束。新内容滚到插入位置；不让异步提示挤走用户正在点的控件。
- 减少动效时关闭位移，保留直接状态变化。不能全局取消玩家或其他实例的动画。
- 插入、移动或删除不隐去结果；关注的语句、路线节点与舞台对象保持稳定身份。

## 5. 可访问性与输入

- 页面有明确主标题，导航标记当前页。所有输入有真实 label；错误与输入关联，动态状态使用适量 live announcement。
- 弹层打开时聚焦标题后首个必要控件，Tab 留在弹层；关闭恢复发起按钮。Escape 只关闭最上层，不推进背后故事。
- 无法运行时在旁边解释原因，并提供去修复入口；不只给一个灰色按钮。
- 键盘、触控与菜单都有等价操作。拖拽排序附带上移/下移、章节移动附带目标选择，路线连接附带表单。
- 中文 IME 合成期间不提交/跳句；输入焦点的快捷键不穿透到预览或 Player。
- 验收包含长角色名、长中文对白、日文 Ruby、200% 缩放、320 px 和真实移动键盘。真实文字不适合时改布局，不压缩字号来塞内容。

## 6. 现有代码如何迁移

| 现有模块 | 接续方向 |
|---|---|
| `apps/editor/src/App.tsx` / WorkspaceHeader | 提取 AppShell、路由与 SceneEditorShell，清除岗位模式和重复任务导航 |
| SceneRail / SequenceView / ScriptView | 场景与正文页面；复用稳定 ID、事务、Undo/Redo、草稿服务 |
| PreviewPanel | 拆成纯 PreviewSurface、PreviewTransport、RunDialog；发行和报告移动到 PublicationWizard |
| Stage Director / Timeline | 复用演出投影与动作语义，仅改外层空间、选择与详情容器 |
| FlowView / RouteTargetPicker / RouteReviewPanel | 独立路线页面，目标选择用共用层栈；评审报告独立详情 |
| ProductionWorkspace | 分出 AssetLibrary、LocalizationPage、AdditionalContentPage；保持 Canonical/Blob 同源 |
| SettingsWorkspace | ProjectSettingsPage / EditorPreferences / PlayerDefaults 分离；事务逻辑保留 |
| DebugQaWorkspace | IssueListPage 与 DebugSessionPage 分离，复用正式 Compiler/Runtime/Source Map |
| Backup Panel | 独立 BackupPage + RestoreReview；保持原有恢复与保护协议 |
| `apps/player-shell/src/PlayerShell.tsx` | 页面化 Title、GameOverlay、Save、History、Extras；保持调度、媒体与存档权威 |
| `styles/tokens.css` / app.css / player-shell.css | 语义主题令牌和组件样式逐步迁移；Player 与 Editor 的颜色域分开 |

采用页面路由时，选中对象、草稿、历史、运行会话归业务服务，不归临时页面组件。重挂载或页面切换不新建工程、不丢未提交文本、不重复播放媒体。路径中的稳定 ID 用于定位；可读名称负责呈现。

## 7. 实施顺序

### 第一包：把日常写作做成真正的创作入口

交付项目首页、主导航、场景列表与写作/演出/脚本壳，三个主题、统一弹层和手机二级页。先把发布与技术材料从 PreviewPanel 移走。接通正文、添加内容、选项目标、媒体选择、真实保存与试玩返回。

验收：一部真实可编辑工程，从改对白到保存、试玩、返回、关闭重开；手机长输入与复杂选项；草稿、保存失败和占用状态。截图不能代替这条任务。

### 第二包：把长任务搬到独立工具页

迁移素材、角色/变量、路线、本地化、内容收录、外观与默认设置。统一对象详情、引用影响、导入差异、搜索与定位。复用业务层已有的能力，逐页做纵向流程。

验收：替换素材保引用，译文交换往返、路线回源修改、角色改名迁移、主题与游戏外观互不污染。

### 第三包：检查、发行与玩家完整体验

拆分检查和调试、实现发布向导和结果、页面化玩家存档/历史/回忆、保住冷恢复及媒体失败重试。依据真实平台能力展示支持状态。

验收：作者正式导出并交给另一设备使用，玩家保存/加载/回退/异常/返回完整链。长篇性能预算与既有存档兼容独立保留，不因为界面重做就放宽。

## 8. 本轮交付范围与待验证项

已经交付：视觉方向图、26 页可点击原型、三个可选主题与跟随系统、响应式布局、页面/二级面/弹层清单、五条作者任务与玩家旅程、状态合同、实现迁移表。

仍需后续验证：真人导航理解、真实触控与 IME、真实工程与大量素材、屏幕阅读器、200% 缩放、完整业务与进度保护协议接线。原型里成功提示、调试、导出结果等都标注示例，不能记作这些真实能力的验收。

原型浏览器验证只检查页面可以到达、没有脚本错误、布局不发生外溢以及局部交互和返回是否正常。具体结果记录在 verification.json。
