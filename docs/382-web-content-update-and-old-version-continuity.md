# 382 内容更新前备份与旧版接续

2026-10-17，接续 [#381](381-web-offline-download-and-recovery.md) 的下一批，按 [#304 Web 完整作品交付](304-web-complete-gal-delivery.md)处理玩家更新后如何继续旧剧情的问题。当前仍为《雨停之前》**1.9.0 内容候选**、技术基线 S0.41；没有新增剧情、素材、兼容回执或原生平台工作。

## 玩家更新与继续阅读

原流程只有“新版已下载，关闭所有窗口再打开”。真实 1.8.0 更新至实际 1.9.0 后，旧游戏缓存被删除，1.9.0 又正确拒绝旧剧情存档；仅留下 `.worldsave` 不能继续旧游戏。[原流程复现](../evidence/web-version-retention/baseline.json)保留了旧缓存删除与实际备份拒绝结果。

现在从标题或阅读菜单检查更新时先打开“更新前准备”。“备份游玩进度”直达原存读档的备份页，可导出当前进度或已有槽位；“显示本版入口”提供可选择复制的版本地址，移除其他查询参数及片段。玩家可以稍后继续本版，也可以确认后主动检查、下载；实际发现另一构建时重新确认，不能把检查前的勾选沿用为已经了解新版本。

新版下载后可以明确启用，在新窗口打开新版，当前窗口继续旧剧情。浏览器在所有窗口关闭后也可能自动激活 Worker；带 `world-release` 的旧入口仍取对应旧缓存，不因 Worker 更新而切换游戏内容。这是版本选择和原版接续，**不是把不兼容旧档迁移到新版**。新旧版保存仍使用同一作品的浏览器槽位，可能相互覆盖，界面明确要求先导出需要的进度。

版本入口只依赖同一浏览器、同一站点保留的缓存，不是可搬到另一台电脑的完整游戏，也不是永久备份。清理数据、浏览器逐出缓存或更换浏览器后仍需作者提供的原版游戏文件。旧缓存缺失或不完整时停止加载，说明未替换新版、未改写存档；玩家可明确选择查看当前线上版本，不会静默混用新文件。新旧缓存同时占用空间，当前不自动删除旧版本。

## 实现与审计发现

主要改动在 [网站导出与 Worker](../apps/editor/src/web-offline-export.ts)、[独立游戏启动](../apps/player-shell/src/export-startup.ts)和 [Player 备份入口](../apps/player-shell/src/PlayerPublicationTools.tsx)。各构建缓存保存自己的清单元数据；激活不删除旧缓存，导航按明确版本地址选取，后续脚本、图片及范围音频请求跟随发起窗口的版本。返回不带版本参数的当前线上入口视为明确的新导航，不能继承旧窗口的版本绑定。

初次进入无版本地址时，在挂载 Player 和打开存档前导航至本版地址。实际双窗口测试发现，仅用 history 改地址，替换后的 Worker 仍可能把旧窗口识别为新版；[修正前失败](../evidence/web-version-retention/before-fix-activation-failure.json)记录了地址和 Worker STATUS 的不一致。真实导航后，明确激活新版的旧窗口重新请求 HTML 仍逐字节属于旧版；同时限制 STATUS 回包的 Worker 身份与请求序次，防止迟到结果覆盖当前状态。

另一浏览器打开已经失效的旧链接、服务器返回新版 HTML 时，启动守卫会在解析游戏、挂载 Player 前拒绝打开。独立单文件 HTML 无版本缓存声明，保持原有启动方式；本批只更新其 Player 运行文件。原 Runtime、完整历史、存档格式和严格兼容判断不变。

## 实际验证

**91 项相关回归／13 文件**通过，[结果](../evidence/web-version-retention/related-tests.json)覆盖版本缓存、严格拒绝缺失／混用、旧回包顺序、备份桥接与清理、首次导航守卫及既有导出／阅读／存读档。另有 18 项 Node 工具测试通过。根类型检查、Editor／Player 构建与 118 个便携文件＋4 个 Node 适配文件的架构审计通过；Vite 大 chunk 警告保持，未执行全仓 check 或长期 soak。

[Chromium 八组实际流程](../evidence/web-version-retention/browser-checks.json)覆盖真实编辑器双源导出、备份／稍后／关闭全部窗口后的自动激活、旧入口断网重开／原槽位读取、另开新版且拒绝旧备份、两个版本全部缓存文件摘要、旧缓存部分丢失／新浏览器失效拒绝、原 1.9.0 同内容接续、双旧窗口明确激活，以及当前两条完整路线。两版本缓存逐项核对分别为 34 与 35 文件，这不是产品在每次打开时重新哈希全部缓存的承诺。

当前网站在 390×844 下断网完成“留下”，HTML 在桌面 file 地址完成“远行”，各 66 段正文、6 句静音观察的原生语音自然结束。公交站／新照片段快速保存、刷新、显式读取恢复原 hash，合计两结局；不是全格式与路线组合，手机尺寸不代替物理手机，静音不代替人工听感，loopback 不代表公网已上线。

复验命令：`npm run build --workspace @world-studio/editor` 后运行 `node tools/run-web-version-retention.mjs`，默认使用 5195 的 Editor 生产预览，支持 STUDIO_UI_URL；完整任务会重新导出本批游戏和更新报告。`--play-only` 使用现有导出，`--activation-only` 仅复测双窗口明确激活，不覆盖整批报告，`--baseline-only` 只复现原历史版本问题。重新导出前保存需要保留的交付。
