## 用户确认的范围

先完成 Web 编辑器和 Web 玩家，跑完完整作品制作与上线流程。Windows、Android 原生编辑器、原生播放器、安装包、签名和平台专属工作先搁置，保留现有代码与历史记录，恢复时间另行决定。

**完成标准：创作者能够使用编辑器制作一部完整 Gal 作品，生成可部署的 Web 游戏，发布后玩家能从标题进入、完成分支与结局、保存并继续游玩。**

此目标优先于旧计划的三端并行交付顺序。原三端 M1 保留为后续整体范围，其未完成项不阻断当前 Web 交付；此次范围调整不把既有失败测试或未验能力改记为通过。

| 环节 | 需要达到的实际结果 |
| --- | --- |
| 工程 | 创建自己的项目；建立章节、场景、角色与变量；保存、关闭、重开、导入导出工程 |
| 素材 | 导入作品的背景、立绘、CG、音乐、音效、配音和所用字体；通过编辑器选择、替换、预览与定位使用位置 |
| 剧情 | 写对白和旁白；配置演出、选择、变量、条件、场景跳转与结局；多视图修改同一内容 |

## 开发顺序

1. **先走完整创作任务。** 从工程开始，逐段完成作品。记录用户操作、期望结果、实际障碍，优先处理界面收纳、素材选择、分支编辑和保存重开的阻塞。
2. **再走正式发布任务。** 用同一工程配置发布、导出游戏并在静态 Web 环境完整游玩；补齐目录部署、错误解释和必要的作品配置。
3. **补齐实际运行问题。** 覆盖主要路线与结局、保存重开、音视频权限与失败恢复，以及连续游玩中出现的性能问题。先确定支持的浏览器，再验证对应环境。
4. **完成上线交付。** 交付可编辑源工程、部署包、上线说明、作品展示资料、已验证环境和已知限制；在实际部署地址完成最终回查。

界面与功能开发以这些任务中的实际问题决定优先级。保留能防止真实回归的必要验证；每轮记录已跑、未跑、失败和剩余问题，不要求先清空所有历史审计项才能记录或交付。
