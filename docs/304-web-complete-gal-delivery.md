## 开发顺序

1. **先走完整创作任务。** 从工程开始，逐段完成作品。记录用户操作、期望结果、实际障碍，优先处理界面收纳、素材选择、分支编辑和保存重开的阻塞。
2. **再走正式发布任务。** 用同一工程配置发布、导出游戏并在静态 Web 环境完整游玩；补齐目录部署、错误解释和必要的作品配置。
3. **补齐实际运行问题。** 覆盖主要路线与结局、保存重开、音视频权限与失败恢复，以及连续游玩中出现的性能问题。先确定支持的浏览器，再验证对应环境。
4. **完成上线交付。** 交付可编辑源工程、部署包、上线说明、作品展示资料、已验证环境和已知限制；在实际部署地址完成最终回查。

界面与功能开发以这些任务中的实际问题决定优先级。保留能防止真实回归的必要验证；每轮记录已跑、未跑、失败和剩余问题，不要求先清空所有历史审计项才能记录或交付。
