# 启动布局、长篇历史与 1.7.8 候选 · 2026-10-16

接续 `3bc08b8` / [#346](346-web-source-hashing-and-startup.md)，先处理启动和长篇阅读中的实际等待，再收尾历史浏览及保存接续。不扩展原生平台，也不将本轮改进记为全部性能问题关闭。

## 本轮产品修改

### 打开目录游戏：减少强制布局

目录包离线栏原先在脚本执行、MutationObserver、toggle 和 resize 中同步读取两次几何尺寸，再写入游戏高度。这会在首次绘制前强制计算页面布局。

现在优先使用 ResizeObserver 提供的 border-box 尺寸，在绘制前统一发布高度；尺寸没变就不重复写样式。初始仍保留 68 px 预算，展开、文字换行及横竖屏变化继续按真实高度留位。旧宿主没有 ResizeObserver 时按帧合并测量，保留功能回退。

实际目录包在本机 Chromium、Firefox、Windows WebKit 中均未发生离线栏启动同步测量；展开、320 px、收起和横屏的高度预算及页面宽度检查通过。这说明去掉了该处强制测量，不说明浏览器无需布局或首帧已经完全流畅。

### 长篇推进：优化规范编码的常见路径

120／240／480 段实际界面推进采样仍指向历史校验中的规范编码和 SHA。只优化编码中的常见情况：ASCII 字符无需 NFC／代理项逐字检查；没有高代理项的记录键使用原生排序；UTF-8 编码只在实际代理对处读取完整码点。

完整历史结构、每个 checkpoint／entry 的哈希、Unicode 标量排序、非 NFC／未配对代理项拒绝、最终 JSON 的 NFC 检查全部保留。没有缓存可变对象、丢弃历史或改变存档协议。补基本平面键排序对照，既有全 Unicode、字节边界与哈希向量继续通过。

### 查看剧情历史：分页并直接找到当前句

- 当前主线及每份归档各自每页最多显示 40 条，支持较早、较后和返回当前句／最新记录；完整 History 不被截断。
- 打开主线时进入当前句所在页，并滚到当前句；分页不会推动剧情。旧分支仍为只读，原回退、前进与不可逆边界保持。
- 历史内容独立滚动，关闭按钮保持可见；分页操作在列表区域保留。窄屏将中间按钮缩为“当前句”，辅助名称仍为“定位当前记录”。
- 桌面和 390 px 实图发现“到当前页但当前句仍在屏幕外”，据此补了滚动定位和固定关闭区。

## 性能结果如何理解

编码优化阶段使用相同 480 段夹具、同样附 CPU 采样的一次对照：推进总阶段 239.3→221.9 ms，但当前组仍有 54／112 ms 主线程任务；保存、读取和更短档位也有波动。该对照发生在最后历史滚动布局收尾之前，报告中的 bundle hash 标记当时实际代码，不当作最终候选的常规运行速度或全部卡顿解决。

离线栏对照固定 1.7.7 输入，仅替换当前 runtime／CSS 与实际新导出的 offline client，五次新上下文检查标题可用；1.7.8 实际 ZIP 单独测量。最终原包约 222–297 ms、当前组约 215–234 ms，实际候选约 191–245 ms；当前候选仍有 56–73 ms 主线程任务，不将五次观察当统计提速或首帧流畅证明。最后代码／实际导出的原始报告为 `startup-{baseline,current,candidate}.json`。

实际源代码收尾过程中还观察过较慢的中间组（候选约 254–335 ms、一次 99 ms 任务），没有以此关闭问题。中间报告因代码／产物变化重新生成，原始 CPU 细节未另存；从当时命令输出保留的标题及任务摘要在 `startup-iterations.json`，明确标记不同代码阶段，不伪装为同一版本的统计重复或声称中间完整原始数据仍在。

本轮没有两小时、物理内存、真实手机或所有旧性能预算的验收。分页上限是每组记录的显示数量，很多归档同时存在时仍需后续检查整体负担。
