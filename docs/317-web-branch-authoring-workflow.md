# Web 分支、变量和条件创作流程

2026-10-14；起点 `1f70d30`，接续 #316。按“编辑分支 → 写目标场景 → 返回 → 配置状态/条件 → 试玩 → 保存与导出”推进；原生继续搁置。

## 本批完成

- 选择编辑器支持增减选项、排序、文字和场景目标修改。作为一个原有 P0 源事务应用，一次撤销/重做恢复整组；存活选项保持原 ID，新选项有独立 ID。保留至少一个选项，空文字/失效目标不能应用，放弃不改正文。
- 选项目标只列真实场景，修复原目标列表混入标签，以及“当前场景有标签时新增选择默认指向标签”的问题。应用后可直接进入目标场景写作，再返回原分支的稳定语句；有未应用或缓冲输入时不能绕过它切走。
- 只展开当前编辑的选项，其余保留文字、去向和排序/删除操作；新增自动展开，放弃恢复。隐藏当前选择的重复正文摘要，使用现有主题/图标，实际 390px 下的网格溢出已修复。
- 数值变量支持设值/增加/减少，是否变量使用是/否，文本自动引用和转义。已有复杂表达式保留，显式生成才替换；条件比较按已声明类型配置，是否/文本不提供数值大小比较。手写表达式仍使用正式解析器检查语法、变量引用和结果类型。
- 修复生成表达式没有可靠标记未应用修改，以及放弃只重置原生表单、没有恢复受控表达式的问题；错误提示保留当前正文，不切走。条件说明明确成立时跳转、不成立时继续下一步。
- 修复底层表达式解析器越过 EOF：`(`、`(count +`、`1 +`、`!` 等未完成输入现在返回诊断，避免编辑时抛异常。合法表达式的语义、Compiler/Runtime/存档格式没有变更。

## 失败与修正

- 初始类型检查发现变量类型表推断过宽；添加准确类型。首次测试中浏览器工程 fixture 的临时写盘代码没有 Node 类型，改为把已生成 fixture 保存在证据目录，组件测试不引入 Node 环境。
- 首次模型回归真实发现 `(count +` 解析器越过 EOF，补结束 token 边界和 6 个测试。首次 UI 断言错误使用 `toHaveValue(StringContaining)`，改为检查输入的实际字符串；原始日志保留。
- 第一轮浏览器发现旧 fieldset 双列规则令手机选项输入溢出，改为选择卡单列、类型控件响应式网格。第二轮在重开后错误假设仍在入口场景；产品正常恢复最后场景，工具显式返回“车站选择”继续核对，没有改掉恢复行为。
- 首份 6 组通过后，实图仍显示选项全展开过长，改为按项收纳；最终构建/6 组浏览器和 7 项 UI 回归复跑。前一报告为 `before-option-disclosure.json`，不累计。
