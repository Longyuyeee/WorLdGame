## 玩家确认保存位置

手动、快速存档与当前进度直接备份，在触发时固定正文、舞台图片／Canvas／视频当前帧、当前布局和已加载字体，再异步编码、计算摘要和写入。自动存档在进入写入队列前固定同一份画面与状态；不等队列、槽位扫描或会话序列化完成后再读取页面。保存时间也取触发时，而不是排队结束时。

缩略图排除存读档、设置、历史、阅读菜单和操作工具条，保留当前剧情画面。桌面横向与手机纵向按实际阅读区域等比缩小，不把纵向画面强行拉成横图。它是阅读画面缩略图，不是带浏览器栏和系统层的整屏截图，也不承诺所有伪元素、滤镜和浏览器字体渲染逐像素一致。

每张图片最长边 512px，最终不超过 512 KiB；捕获最多两个同时进行、3 秒等待、256 个元素，样式图片与字体累计读取 8 MiB，现场媒体缩图编码累计 4 MiB，序列化图像输入上限 16 MiB。媒体没准备好、跨域无法取像、字体过大、编码不支持、超预算或捕获失败时不附图，不推迟剧情或冒用后续画面。普通存档继续沿原有会话／图片事务写入，截图不是进度权威。

剧情检查点是解释器的非可见边界，其后显示的句子不一定是该检查点本身。本批停止给检查点附当前画面，保留准确检查点会话，不用下一句截图装作检查点画面；后续若增加专用渲染，必须证明对应关系。

槽位同时显示保存时的正文或选择提示，去除注音标记、合并空白，最多 160 个 Unicode 字符；长摘录在卡片中限制行数。即使没有截图，玩家仍能区分同一场景内的不同保存位置。V3 存档新增可选 `readingExcerpt`，旧 V1／V2／无摘录 V3 继续由当前 Player 读取。新扩展存档需当前 Player；不保证旧版本应用识别新字段。

摘录和截图都是保存时的展示信息，保留当时语言，不决定读档是否合法。完整会话仍校验原始摘要、构建、场景和内容种类；切换显示语言不能因为摘录不同而拒绝有效进度。读取会合并当前已读／收集记录，因此加载后的运行哈希可能与保存时不同，不能把它当作“没有恢复原句”。备份保留原会话和图片摘要，实际流程另核对恢复后的历史位置与正文。图片读取或解码失败显示回退提示，读取进度仍可操作。

默认捕获仅接入 Web Shell；已有宿主捕获接口保留并接收触发时的运行哈希，宿主应在调用时固定画面。原生平台未扩展，也未把图片捕获放进 Compiler、Runtime 或 Player Core。

## 作者撤销的实际边界

顶部“撤销范围”持续说明：写作撤销针对当前场景已应用的修改，跨场景整批文字替换一起恢复，不撤销结构管理的新增、改名和删除。关闭工程或刷新后历史重新开始，已保存内容保留；错误草稿和未提交输入的保护沿用现有流程。

- 章节改名、移动及新增引用对象，没有改写原场景时，保留相应场景的撤销、重做和选择位置。
- 场景内容或脚本中的场景标题被结构页改写，该场景从新内容开始；删除角色、场景、变量或改变变量类型时，保守重建写作历史，避免撤销恢复失效引用。
- 跨场景整批替换中的任一成员被结构操作重建，该批其他成员的关联历史也一起重建；有关联的其他整批记录同样处理，不留下半批可撤销状态。没有关联、没有受到改写的场景仍保留原记录。

发生重建时，返回写作的通知列出场景，顶部说明保留最近一次重建的场景名称和原因，不随下一次写作通知消失。这里没有实现跨结构、跨刷新统一撤销，也没有悄悄回滚结构管理修改。

## 下一批按第四项推进

1. 先审查现有 `WebPlayerSkin`、标题／阅读模板与实际按钮处理，在同一契约内规划有边界的组件位置、尺寸、响应式锚点和安全区，不另建一套解释器。
2. 首批覆盖标题的作品信息／开始与读取入口，阅读的对白窗体／姓名头像／常用操作；动作只绑定现有正式 Player 功能，不执行任意脚本。
3. 作者能够配置、预览、撤销、保存重开并复用；手机和桌面各有合理约束与回退，避免把桌面绝对坐标直接压到窄屏。继续用原作品副本做实际操作与双格式检查。
4. 标题与阅读形成闭环后，再扩其他页面，不重新无限扩张皮肤装饰。剧情、发布和用户实际障碍持续沿 #304 处理；原生工作不恢复。
