# CL-03 Windows 编辑器壳选型证据契约

> 状态：证据契约已冻结，CL-03 尚未开始。本文只允许实现可抛弃的对照 Spike，不代表 Electron、Tauri 或任一安装/更新方案已经入选 M1。

## 1. 要证明的 Claim

在同一份编辑器前端、同一份工程数据和同一组故障注入下，至少一个 Windows 壳候选能够同时满足：

- WIN-L 目标设备上的启动、内存、容量和交互预算；
- 工程文件、WAL、备份和崩溃恢复不降级；
- 渲染进程/WebView 不直接获得文件系统、进程、Shell 或更新权限；
- 安装、签名更新、失败回退、卸载与便携版语义可解释且可测试；
- 诊断信息足以定位主进程/Core、渲染进程/WebView、IPC 和更新故障；
- 壳实现不污染 Domain、工程格式、编译器与 Runtime。

空白窗口包体、开发机体感、框架宣传页、Node 文件适配器和浏览器窄屏均不能证明该 Claim。最终结论必须来自[CL-01](62-cl01-target-device-budget.md)登记的 WIN-L 实体设备。

## 2. 候选与冻结方式

| 代号 | 候选 | 必测分支 | 当前只记录的环境观察 |
|---|---|---|---|
| E | Electron | Chromium 随应用分发；直接下载安装/更新链 | 2026-08-12 查询到 npm `electron` 43.4.0；Spike 必须在 lockfile 锁定实际版本 |
| T | Tauri v2 | WebView2 Evergreen；WebView2 缺失/离线安装；Fixed Version 成本测量 | 2026-08-12 查询到 `@tauri-apps/cli` 2.11.4；本开发机已有 WebView2 Runtime 151.0.4129.72 |

当前开发机有 Rust/Cargo，但没有 Electron/Tauri 产品依赖、代码签名证书或 WIN-L 设备，因此只能准备环境和契约，不能宣布 CL-03 通过。

## 3. 同功能垂直切片

两个 Spike 只能通过版本化的 `WindowsHostV0` 窄桥接提供下列能力：

1. 使用系统选择器创建或打开工程目录；
2. 通过既有 `ProjectFileStore` 语义完成读取、事务写入、WAL、备份、恢复和脏状态关闭确认；
3. 导入固定素材集并报告可取消进度，不把绝对路径写进工程；
4. 单实例/第二窗口写租约冲突提示；
5. 订阅窗口关闭、挂起和崩溃恢复事件；
6. 检查、下载、验证、暂存和重启应用更新；
7. 导出脱敏诊断包，不包含工程正文、签名凭据或用户绝对路径。

前端不得调用原始 Electron、Node、Tauri 插件或 Rust 命令。Domain、Compiler、Runtime 和工程格式包不得依赖任何候选壳。`revealPath`、任意 Shell、任意 URL 打开和通用文件 API 不进入本切片。

## 4. 不可补偿的安全红线

### 4.1 Electron Profile E

- `contextIsolation` 与 renderer sandbox 必须开启，Node integration 必须关闭；
- 仅由 `contextBridge` 暴露逐项、版本化 API，禁止透传 `ipcRenderer` 或通用 invoke；
- 每个 IPC 请求校验 sender、窗口身份、参数 Schema、工程根目录租约和相对路径；
- 默认拒绝导航、新窗口、权限请求和外部协议；允许项必须有窄白名单与用户确认；
- 使用限制性 CSP 和自定义本地协议，禁止远程可执行内容、`file://` 权限扩散和不安全混合内容；
- 审计 Electron Fuses，关闭不需要的 Node/调试入口；Release 包不得开启 DevTools 远程调试。

### 4.2 Tauri Profile T

- 每个窗口/WebView 只绑定显式 Capability、Permission 与 Scope；未列能力默认拒绝；
- 审计多个 Capability 合并后的权限并集，禁止用宽 Scope 抵消配置复杂度；
- Rust command 对参数、窗口身份、工程租约、规范化路径和资源上限再次校验；
- 不启用通用 Shell/Process/File System 插件；确需能力时必须改为单用途命令并增加威胁测试；
- 默认拒绝远程内容、导航、新窗口和外部协议；使用限制性 CSP；
- 不能把 ACL 当成 Rust Core 的自动保护，Core 中的路径、更新与反序列化代码仍需独立审计。

### 4.3 共同红线

路径穿越、junction/symlink 越界、伪造 IPC sender、任意外部导航、未签名/签名错误更新、更新降级重放、WAL 丢失或工程损坏，任一出现即判该候选失败；性能得分不能补偿这些失败。

## 5. WebView2 分发变量

Tauri 不能只在“开发机已安装 Evergreen Runtime”的理想环境测试：

- Evergreen 分支记录 Runtime 精确版本、缺失时的 bootstrap、离线失败提示以及 Runtime 独立更新后的回归；
- Fixed Version 分支记录额外下载/安装容量、补丁责任和 Runtime 切换后的可复现性；
- 同一证据批次必须保留操作系统、WebView2、GPU/驱动和壳版本指纹；
- Windows 预装状态不能替代安装器的 Runtime 覆盖策略。

Electron 自带 Chromium 的容量成本与版本控制收益必须在同一张结果表中呈现，不能只比较压缩后的空壳安装包。

## 6. 安装、更新与签名边界

- 每个候选选一个面向官网直接下载的主安装方案，另测 M1 要求的便携版；比较用户结果，不假定 MSI、NSIS、Squirrel 或 MSIX 等价；
- 安装包、应用二进制、更新元数据和增量/完整包都必须验证身份与完整性；无有效签名不得安装或应用；
- Spike 可用隔离的测试证书证明流程，但不得把私钥、口令或生产证书写入仓库、日志或诊断包；Stable 取证必须使用受信任发布证书；
- 必测 `A → B` 正常更新、下载中断、安装中断、磁盘不足、错误签名、篡改包、过期元数据、降级/重放和 `B → A` 回退；
- 便携版默认不静默自更新，更新能力和数据目录必须在 UI 中明确；
- 卸载默认保留用户工程，缓存/日志/更新暂存的删除范围必须可预览，不能触碰工程目录；
- CL-03 只验证客户端强制执行；完整制品来源、SBOM、签名保管和发布撤回仍由 CL-12 收口。

## 7. 故障与对抗测试矩阵

| ID | 场景 | 必要证据 |
|---|---|---|
| WS-01 | 冷启动、打开固定工程、到可编辑 | ETW/时间戳、进程树、版本指纹 |
| WS-02 | 正常事务保存并重开 | 写入阶段日志、文件 Hash、恢复报告 |
| WS-03 | WAL 各阶段强杀 renderer/WebView | 每个注入点结果；不得丢失已确认提交 |
| WS-04 | 强杀 main/Core、整机重启恢复 | 恢复选择、旧/新文件 Hash、无静默覆盖 |
| WS-05 | 磁盘不足、只读目录、权限撤销 | 稳定错误码、工程仍可读、可重试 |
| WS-06 | 第二实例/窗口争夺写租约 | 单写者成立；只读或显式接管 |
| WS-07 | `..`、绝对路径、junction/symlink 越界 | 全部拒绝并有安全日志 |
| WS-08 | 伪造 sender、错误 Schema、超大 IPC 消息 | 全部拒绝；主/Core 进程保持稳定 |
| WS-09 | 外部导航、新窗口、协议与权限请求 | 默认拒绝；仅白名单操作可确认执行 |
| WS-10 | renderer/WebView 崩溃与重载 | 脏状态不被静默当成已保存；可诊断恢复 |
| WS-11 | 固定素材集导入、取消与重试 | 无孤儿源文件；缓存可重建 |
| WS-12 | 有效签名 `A → B` 更新 | 更新前后版本/文件/设置证据 |
| WS-13 | 错签、篡改、过期、降级/重放更新 | 全部拒绝且仍能启动旧版 |
| WS-14 | 下载/安装中断、磁盘不足和回退 | 不进入半安装状态；恢复路径可重复 |
| WS-15 | 卸载与便携版数据边界 | 工程保留；缓存范围符合说明 |
| WS-16 | WebView2 缺失、离线、版本前移 | T 分支提示/恢复正确，数据不受影响 |
| WS-17 | 30 分钟固定编辑脚本 | 峰值/稳态内存、CPU、句柄、崩溃与泄漏趋势 |
| WS-18 | 诊断包脱敏检查 | 无工程正文、凭据、用户绝对路径与 token |

WS-02 至 WS-18 每个候选至少重复 3 次；性能场景重复 10 次，保留原始结果而非只保留平均值。

## 8. WIN-L 测量与硬门

测量必须在 CL-01 登记的 WIN-L 上进行，开发机结果只标记 `exploratory`。固定工程至少包含一条可编辑路线、脚本、舞台状态、音频以及足以触发真实文件/媒体路径的固定素材集。

| 维度 | CL-03 硬门 |
|---|---|
| 冷启动到可编辑 | P95 ≤ 4 s；任何一次不得超过 CL-01 10 s 硬门 |
| 内存 | 固定脚本稳态 ≤ 900 MB；峰值 < 1.5 GB |
| 分发容量 | 主安装下载 ≤ 250 MB soft / 400 MB hard；安装后 ≤ 650 MB soft / 1 GB hard |
| 数据正确性 | WS-02–WS-06 零静默丢失、零不可恢复损坏 |
| 安全边界 | WS-07–WS-09、WS-13 全部拒绝；零越权成功 |
| 更新恢复 | WS-12–WS-15 全通过；失败后旧版可启动且工程不迁移到不可回退状态 |
| 稳定性 | WS-17 零未预期崩溃；句柄与内存无持续无界增长 |
| 诊断与隐私 | 每个失败可关联批次/阶段；WS-18 零敏感泄漏 |

Soft 门超出必须有可执行优化或容量降级方案；Hard 门、安全、数据或更新红线不可豁免。

## 9. 选择规则与停止条件

先过硬门，再评分；未过硬门的候选不进入评分。

| 评分维度 | 权重 |
|---|---:|
| 最小权限与攻击面可审计性 | 25 |
| 数据正确性、故障恢复与单写者实现复杂度 | 20 |
| WIN-L 性能、内存和分发容量 | 20 |
| 签名更新、失败回退与 Runtime 分发可控性 | 15 |
| 调试、诊断和自动化测试能力 | 10 |
| 构建可复现性、维护与补丁响应成本 | 10 |

- 仅一个候选通过全部硬门：选择该候选并形成 ADR；
- 两个都通过：按原始证据评分；总分差小于 5 分时，不凭偏好决策，增加能区分维护/安全风险的定向测试；
- 两个都失败：只允许各做一次针对根因的受限修复复测；仍失败则 CL-03 阻断 M1，并提交替代壳 ADR，不降低 Windows 完整编辑目标；
- 任一候选需要向 renderer/WebView 暴露通用 Node、Shell、任意路径或远程代码执行才能完成切片，立即停止该候选；
- ADR 必须附原始证据、工具脚本、版本指纹、已知限制、拒绝另一候选的理由和回退触发条件。
