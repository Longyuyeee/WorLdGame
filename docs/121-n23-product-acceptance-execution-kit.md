> 当前状态：`pending-participants`（0/2）

> 权威协议：[`config/n23-product-acceptance-protocol.json`](../config/n23-product-acceptance-protocol.json)

## 1. 审计结论

N23-E1–E5 已形成可操作对象，但此前只有一句“两名非实现者运行五分钟作品”，没有冻结每个人要做什么、如何同时验证编辑器和独立产物、怎样记录严重度及何时允许关门。因此即使找到参与者，也可能出现两次演示口径不同、只跑一条路线、只看编辑器 Preview 或无证据回填的问题。

本执行包补齐 N23-E6 验收就绪门：固定两名不同的非实现参与者、六个顺序任务、两条准确路线、三类哈希产物、Severity 口径及机器审计。它没有真人结果，不能把 N21 或 N23 标记为通过，也不授权进入 N30。

## 2. 先后关系

必须严格按以下顺序执行：

1. `npm.cmd run audit:n23-content` 必须通过，确认验收对象仍满足五分钟内容量门；
2. 先完成 [`N21-HV-01`](114-n21-human-validation-execution-kit.md)，权威记录状态为 `pass`；
3. 再由两名不同参与者分别完整执行本协议；
4. 若两人全部通过且 Severity 0/1 为 0，在同一变更中关闭 `RA-N21-002`；
5. 运行 N21、N23、风险例外和全仓检查，提交、推送并等待 CI；
6. 只有上述证据全部成立，才允许把 N23 标记为“通过”并进入 N30。

N21 参与者可以同时成为 N23 的其中一名参与者，但必须满足两个协议各自资格，并分别保留记录。N23 的两名参与者之间必须使用不同匿名编号。

## 3. 参与者和主持人边界

每名参与者必须未参与本项目代码或设计、同意以匿名编号记录、独立操作设备。仓库不得保存姓名、邮箱、账号、录音或其他直接个人信息。

主持人只能朗读任务目标、计时和记录观察；不得操作编辑器，不得指出按钮位置、准确点击顺序或替参与者修复工程。参与者主动求助均计入 `helpRequestCount`，问题、误操作和阻塞必须原样登记。

## 4. 每名参与者的冻结任务

从项目首页开始，主持人只按顺序给出目标：

| ID | 目标 | 通过条件 |
| --- | --- | --- |
| P01 | 使用可见入口打开五分钟验收工程并进入编辑器 | 通过“打开五分钟验收工程”进入，不使用开发工具或代码 |
| P02 | 确认故事结构 | 能确认至少 3 场景、2 角色和 2 个不同结局 |
| P03 | 修改一处叙事文本，保存、关闭并重开 | 修改保留，工程仍可编辑和运行 |
| P04 | 在编辑器完整流程试玩中运行两条路线 | `benchmark_board` 到“驶向仍可抵达的清晨”；`benchmark_stay` 到“雨停以后重新出发” |
| P05 | 构建并下载独立试玩 HTML | 生成可在浏览器直接打开的单文件产物 |
| P06 | 脱离编辑器运行独立 HTML 的两条路线 | 两条路线均可交互并到达与 P04 相同的准确结局 |

不得提前透露选择对应哪个结局。P03 的编辑应避开改变路线结构和预期结局名，否则不再是同一冻结验收对象。

## 5. 证据与严重度

每名参与者必须填写起止时间、计算后的整数秒、设备、求助次数、阻塞、误操作、每项任务结果、编辑器与独立 HTML 路线结果。还必须保存并登记 SHA-256：

- 匿名观察日志；
- 修改后的工程 ZIP；
- 实际运行的独立 HTML。

严重度固定为：Severity 0 是崩溃、数据损坏、安全问题或全流程不可完成；Severity 1 是核心流程无合理绕行、错误结局或独立产物不可运行；Severity 2 是可绕行的重要体验问题；Severity 3 是不阻断任务的轻微问题。任何 Severity 0/1 都使本轮 N23 失败，必须登记缺陷、修复并重新验收，不能解释为通过。

## 6. 记录与机器门

执行前把准备验收的完整 40 位提交写入 `sourceBaseRevision`。完成后把记录从 `pending-participants` 改为 `pass` 或 `fail`，不得部分填写后仍保留 pending。运行：

```powershell
npm.cmd run audit:n21-human-validation
npm.cmd run audit:n23-content
npm.cmd run audit:n23-product-acceptance
npm.cmd run audit:risk-acceptance-policy
npm.cmd run check
```

审计器会验证协议哈希、两个参与者的独立身份、任务与路线顺序、准确结局、时间一致性、主持人边界、Severity、三个产物路径与哈希，并在 `pass` 时强制要求 N21 已通过及 `RA-N21-002` 同步关闭。

当前合法输出是 `PASS`、`recordStatus: pending-participants`、`participants: 0/2`。这里的 `PASS` 仅表示待验收记录真实且协议未漂移，产品状态仍是未通过。
