## 1. 用户反馈与审计结论

产品负责人在实际查看当前页面后指出：“有些地方样式很原始，而且有些地方的 UI 已经开始摊大饼”。生产页面、源代码和既有视觉规范三方对照后，该反馈成立：

- 首页标题继承了工作区全局 `h1` 的 22 px 行高，却使用最高 64 px 字号，实际发生标题与说明重叠；
- 首页把新建/打开/导入与 N23、N42 固定验收工程放在同一首层，内部验证入口抢占正常创作层级；
- 首页和工程结构页输入框、选择器、按钮大量保留浏览器原生灰色外观，与内容工作区的现代深色语义系统断裂；
- 内容工作区已有现代多彩方向，但 `.app-shell` 只有 `min-height`，内容仍能把整页撑高；三栏虽然声明 `overflow:auto`，实际没有形成受约束的独立滚动容器；
- Sequence 中 Stage Track、剧情步骤、参数 Inspector，以及 Preview 中 Runtime、导出、Transport 仍持续纵向叠加。本轮只先关闭壳层失控，不把信息架构完全收敛伪报为完成。

这不是产品方向错误，而是开发节奏偏移：N30–N42 工程能力持续进入同一个技术工作区，用户可见的层级治理没有同步成为逐切片退出门。

## 2. 本切片范围与非范围

### 已实施

- 修正首页标题排版和视觉层级，统一 Semantic Dark Token、圆角、边框、悬停、禁用与主操作样式；
- 日常入口保留新建、打开目录、示例和导入；N23/N42 固定工程移入默认折叠的“开发与验收工程”；
- 统一工程结构页输入、选择、按钮、状态、卡片和主操作语言；
- 桌面 `.app-shell` 锁定 `100dvh`，Header/Main/Footer 构成固定视口，Scene/Authoring/Preview 各自滚动；820 px 以下恢复自然文档流；
- 保持 Preview 默认 16:9 和既有可调尺寸语义，不修改 Canonical Script、Compiler、Runtime、Stage 命令或媒体资产。

### 明确未完成

- 没有实现 N43 七模式、Beginner/Pro、手机任务模式或完整三级动效；
- 没有把 Stage/Runtime/导出重组为最终渐进展开架构；
- 没有关闭 N21/N23 真人参与者证据、D1 用户验证或 N42 Product Acceptance；
- 没有宣称当前首页、结构页或内容工作区已达到商业成品最终视觉；
- 没有借 UI 修正进入 Player、Gal Settings、Gallery、Android 或三端构建。

## 5. 需求对齐与下一步

本切片直接响应“现代化、极简、动效多、平滑过渡、色彩丰富、表达清晰”和“方便编辑但保持专业性”的原始要求。极简在这里体现为隐藏内部 fixture、建立主次和限定滚动上下文，不是删除稳定 ID、诊断、Runtime 或专业参数。

方向纠偏后仍有两个黄色风险：

1. Sequence/Preview 的专业信息虽然被限制在独立栏内，但 Stage、Inspector、Runtime、Build 仍以纵向堆叠为主；下一 UI 切片应基于当前任务和选中对象做渐进展开，而不是继续增加永久可见卡片。
2. 首页和结构页已经脱离原生工具外观，但尚未完成高保真动效、移动布局和真实目标用户任务验证；不得用本轮开发者浏览器证据替代 D1/N21/N23 真人证据。

因此下一工程动作仍须遵守 N42 有界授权：优先完成关键帧在生产浏览器中的保存重开与 Formal Runtime 可见闭环；若同时调整 UI，只允许减少当前 N42 工作区的认知噪声。N42 出口后的新治理授权应把七模式与任务化信息架构作为显式退出条件，避免工程能力再次无界堆入同一页面。
