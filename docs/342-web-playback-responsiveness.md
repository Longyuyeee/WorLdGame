## 实际问题与修复范围

使用当前 1.7.3 完整作品、390×844 窗口、正常动效，从开场走到“远行的约定”，六句真实 voice 自然结束；在第 10、30、50 段附近分别快速保存/显式读取。每次完整路线 66 段文字、126 次推进操作，包含长文揭示/滚动，不把一次点击等同一段文字。记录主线程 longtask、long-animation-frame、首轮 CDP CPU 栈与堆采样。

CPU 采样指向 `createRuntimeSessionSaveV1`：恢复记录不断对完整 History 做结构/哈希校验，重复的字段名、状态字符串和哈希字符串被反复 NFC 检查、转义；UTF-8 又分别扫描代理项和计数字节。历史越长，后段阅读点击出现的长任务越多。没有把这一观察外推为旧 #304 约 616.6 ms 长帧的全部原因。

本批修改 `packages/runtime/src/canonical.ts` 与 `session-save.ts`：

- 在**一次序列化内部**复用相同不可变字符串的验证/JSON 转义。表最多 256 条，只留不超过 512 UTF-16 单元的短字符串，不跨调用存活、不缓存历史或对象身份。
- 同一次 Canonical 输出统一生成字符串与 UTF-8 字节，供 Hash/Session Save 使用。UTF-8 把代理项验证合入字节计数，少一次全段扫描；所有原始 key/string 与最终 JSON 仍经过严格 NFC 检查，不提供公开“跳过验证”编码入口，不可信读档检查保持。
- 审计发现若继续调用输入数组的自定义 `map`/species，不能保证输出都经过内部验证。因此数组按原有索引/空位语义内部遍历，不执行输入自定义 map/join/species，并增加相应边界测试。没有通过信任上一次保存过的对象来跳过本次校验。

没有删减历史、取消恢复保存、改变存档格式/哈希域/键排序、改用宿主编码 API，或减少语音等待。旧记录仍须通过结构、身份、链、状态/条目和全会话哈希检查。

## 本机对照，不是手机性能验收

基线使用 #341 正式目录中的原始 `player.js`；初次采样时生产源码构建与该文件逐字节一致，隐藏 source map 仅供本机 CPU 定位。修改后重新跑三次相同路线，第一轮同样附加 CPU profiler；其余两轮不附加。测量与构建/回归不并跑，未降低动效、注入假媒体事件、强制 GC 或修改播放状态。

最终测量在 `evidence/web-playback-responsiveness/{baseline,current}.json`；CPU 原始大文件在未提交的 `.browser-diagnostic/playback-profile`，提交报告保留必要来源定位/long frame/内存采样。`baseline-failure.json/png` 是最初脚本误判保存后菜单状态，按实际已打开菜单修正；不是当前产品失败，也不计通过次数。第一次优化后又补数组边界防护，表内只使用最终源码重跑的结果。

## 旧档、完整路线与产物边界

本批**不覆盖或重发 1.7.3 候选**：可编辑源/HTML/目录/独立校订记录仍在 `evidence/web-audio-compatibility`，剧情、25 媒体、来源台账和 11 条人工待复核记录不变。本批运行时修复进入源码，编辑器重新正式导出时会带入；打开旧 HTML/旧 ZIP 不会自动得到源码改动。

验证器内存使用原 1.7.3 正式 payload/媒体和当前生产 runtime/CSS，未改剧情 JSON，未冒充作者重新保存重开/正式导出。报告的原包摘要和 runtime 摘要可核对实际所测代码；隐藏 map 构建与默认无 map 生产构建 JS 摘要必须一致。

`tools/run-web-runtime-continuity.mjs` 验证三引擎原运行时→新运行时的快速槽位读取、原 `.worldsave` 导入与显式读取，比较完整 serializedSessionSave、Session Artifact Hash 和 Runtime State Hash；每引擎再跑两条完整路线，分别 60 段旁白/6 句真实语音自然结束、正确结局、无残留声音。实际输出与摘要见该目录 `continuity.json`、九份 `.worldsave` 和 `audit.json`。这里只读取/导出/导入真实 UI 存档，没有直接填充数据库或伪造语音结束。

最终三引擎 **3 项接续 + 6 条完整路线全部通过**，没有页面异常。每次打开/重载还实际比较浏览器收到的 `player.js` 响应字节摘要，不能只看服务器准备了什么文件。`node tools/audit-web-playback-responsiveness.mjs` 另核对原包、基线、当前生产构建/隐藏 map 构建、三引擎报告及九份实际备份的身份/字节/哈希一致性，通过；其中 `passed` 是功能与报告身份通过，不是性能门槛已验收。

本批不重新执行离线升级矩阵、真实公网或实际 Safari。Windows Playwright WebKit 在线用例不能代替 macOS/iPhone；#341 的严格离线音频未通过状态保持。

最终审计否决了“各原始字符串 NFC 正确就可省略最终 JSON NFC 检查”的初版优化：换行后接组合重音的原文可以合法 NFC，但 JSON 转义后的 ASCII `n` 与重音可能组成非 NFC 文本。独立反例和两项回归先失败；恢复最终 NFC 检查，代理项检查仅与计数字节合并，保留旧编码器的接受/拒绝规则。随后重跑测量、三引擎接续和回归；上文仅应使用该修正后的结果，先前较快版本不能计入交付。数组方法防护保留，仍不执行输入自定义 map/species。

## 回归与审计

最终 `npm run audit:web-playback-responsiveness`：#341 的 334 项基线，加五个 Runtime 文件 86 项，共 **45 文件/420 项**通过；另完整 Player Core/Runtime Host 十文件 63 项通过，其中四项旧档兼容重复，去重合计 **54 文件/479 项**。本批新增六项回归，另扩展既有 Unicode 全标量用例。根类型、Editor/Player 双构建、工作区/架构/需求/交付基线四项审计通过。既有 jsdom 原生媒体未实现提示及大 chunk 警告保留，不当真实媒体播放或构建失败。

过程先有数组 species 测试缺静态返回类型/override 的类型错误，补完整声明后通过；全 Unicode 扩展用例曾因逐字节深度断言超过默认 5 秒，改用原有同等字节覆盖的 `Buffer.equals`，未扩大超时或删标量。JSON 转义反例的失败是审计抓到的真实初版兼容问题，不能混入最终通过。完整全仓、生成语料分片、两小时 soak、人工听感/阅读定稿和真实手机不在本批通过范围。
