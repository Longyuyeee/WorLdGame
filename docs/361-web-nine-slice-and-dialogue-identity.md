## 作者使用流程

在“游戏外观 → 皮肤与动效”展开“按钮九宫格”，开启后按原图像素调整上、右、下、左切边。四种按钮状态共用一组切边，中心和边段随按钮伸展，边角保留尺寸；不再将整张边框一起拉宽。

在“阅读与选项”选择“窗体九宫格图片”，开启“对白窗体九宫格”。它与原“对白框图片”是同一字段，两处同步，不会生成两套窗体。姓名可保留行内样式，也可改为独立姓名框，选择背景、对齐、间距、圆角及姓名框九宫格。

切边只接受 **0–64 的整数像素**，左右及上下必须分别给原图留下中间区域；所有已选择的按钮状态都会核对尺寸，越界时阻止应用或导入。没有图片时保留常规样式。九宫格使用图片自身的边角，圆角应绘入素材，不再用额外圆角裁掉图片边缘；这不是自由组件布局。

“显示角色头像”按实际说话角色绑定图片，并可设置姓名左/右侧、32–144px 尺寸、圆角和填满/完整显示。最多 **8 个角色绑定**；关闭显示保留绑定，清空某个角色的图片才移除该绑定。旁白与未绑定的角色不显示头像，不从舞台立绘猜测。头像加载失败用当前姓名首字回退，不使用上一位角色的图片。

姓名与头像保持在对白内容区内，长姓名可以换行。高对比阅读关闭装饰边框和图片，保留黑底白字与姓名首字；原推进、滚动、键盘焦点和减少动效行为保留。

## 跨工程复用与缺失修复

`.worldskin.json` 和 `.worldskin.zip` 共用新模板契约和素材引用映射，仍保留图片 8 MB / 400 万像素、字体 32 MB、整批 **24 项 / 64 MB** 限制。新字段可选，旧工程和旧皮肤不必补字段；新模板需当前应用版本读取。

带素材包导入新增“对应说话角色的头像”：

1. 相同稳定角色标识可沿用；其他角色必须从目标工程列表明确选择，或选择“不使用这个头像”。不按同名猜测，不创建、复制或替换源角色。
2. 不允许两个来源头像同时对应同一目标角色。改变头像对应会使已检查的计划失效，需要重新检查并预览。
3. 不使用的头像若没有其他引用，其专用文件不会进入工程。图片选择明确回退时也移除对应头像绑定，原故事与角色保持。
4. 包内缺图仍需补齐、对应已有文件或明确回退。检查、预览、取消不写素材；确认后沿用现有整批素材事务，再按正常流程保存工程。

只导入配置 JSON 时，图片沿用已有摘要对应；来源角色不在本工程会显示待修复选择，可在阅读页从列表重新对应或移除，应用前必须修正。导出时头像对应名称取当前工程角色名，玩家仍使用实际说话人的姓名，不依赖包内名称快照。

来源台账、公开许可与玩家包剥离边界沿用 #359：内部台账默认不随包，导入记录仍需复核。功能成功不等于确认素材发行许可。

## 代码与审查

新增可选 `WebPlayerSkin.template`，严格检查三组切边、姓名框及头像参数；`webPlayerSkinImageReferences` / `remapWebPlayerSkinReferences` 包含姓名框和头像图片。角色对应独立于图片摘要对应，既不写入人物库，也不改写剧情。

正式 Player 复用现有 CSS 图片来源，用 `border-image` 显示九宫格；文字按钮继续排除对白、历史正文和画廊图片。`PlayerDialogueIdentity` 仅负责当前对白的姓名与头像，不新增解释器或播放状态。媒体失败不阻断剧情；预览仍使用正式 Player 并静音隔离存储。

两份早期 `failure-*.json/png` 保留：一次是创建角色入口与演出按钮重名的脚本定位问题；一次是脚本把已展开的九宫格说明再次折叠后等待隐藏控件。已限定弹窗范围、按实际展开状态操作，均不计入最终通过。截图另等待原有入场动效稳定，没有用改写 Player 状态或禁用演出来替代真实操作。
