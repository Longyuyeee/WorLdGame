继续优先 Web：让普通创作者能够从空白工程完成一部 Gal 作品，使用自己的素材、字体、界面与演出，保存并继续制作，导出可独立运行的游戏。Windows / Android 原生工作继续搁置。当前不需要先选定发布平台。

## 后续开发顺序

### 1. 动效预设的普通作者流程

先做人物入场/退场/强调/呼吸和文字强调等分类预设，接入现有演出工具。

- 用户能浏览效果、静音试播、一键应用到实际剧情步骤。
- 根据效果显示必要的时长、强度、缓动、循环等参数，避免展开无关设置。
- 能保存自己的预设并在其他场景复用，随后支持预设导入导出。
- 完成标准：用样章实际应用人物和文字效果，保存重开及正式导出后仍有效，减少动效时有可读回退。

### 2. 携带素材的皮肤包与缺失修复

在已有 `.worldskin.json` 基础上，让作者可以整体复用自己的游戏外观。

- 图片、字体、窗体与按钮素材能随包导入，保留来源记录。
- 导入前显示将使用/缺少的资源，集中完成对应、替换和恢复。
- 逐步补每页独立背景、按钮状态、九宫格和姓名框/头像等模板参数。
- 完成标准：在另一工程导入一套皮肤与素材，预览、保存重开、游戏导出一致；不要求用户编辑 JSON 或内部 ID。

### 3. 真实存档缩略图与连续制作

- 当前正式导出仍显示“预览不可用”；接通实际画面捕获，使缩略图对应所保存的那一句，而不是后续推进后的画面。
- 缩略图失败时仍能正常保存、读档；核对重开与备份恢复时的表现。
- 明确跨章节/场景结构操作后的撤销范围，避免用户以为之前的修改仍可统一撤销。
- 完成标准：作者与玩家从真实操作中能确认“保存了哪里、恢复到哪里”，失败有清楚反馈。

### 4. 自由组件与响应式布局

在逐页模板已经可用的基础上，推进组件位置、尺寸、锚点、安全区、按钮状态与已有运行功能的动作绑定。先覆盖标题与阅读，再扩展其他页面；桌面/手机都能预览并继承合理布局。

### 持续处理的成品问题

沿当前短篇处理实际使用障碍；长篇卡顿继续依据 #353，不能用短篇成功关闭。人工作品定稿、自然阅读/听感、真机/Safari、素材发行依据和实际公网交付仍待独立完成。暂不把这些事项扩展为每轮必须重跑的全仓审计。
