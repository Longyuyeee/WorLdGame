# Web 制作交付包与恢复 · 2026-10-14

接续 `063fa68b`（#319）。本批处理创作者定稿后需要分别保存游戏、源工程和校订记录的实际交付步骤。当前《雨停之前》仍为 1.5.4，原正文、素材和发行产物保持。

## 用户操作

1. 发布 → 导出方式：选择 HTML 或目录 ZIP，可勾选“同时生成制作交付包”。这项默认关闭。
2. 如需携带问题清单，再勾选“附带校订记录”；默认不附带，并显示当前记录数量。
3. 生成时先等待正在进行的保存，再保存当前内容；从同一份工程快照生成游戏和制作交付包。保留普通“下载游戏”，另提供“下载制作交付包”。
4. 首页导入整个制作交付 ZIP，即可恢复源工程及原素材。附带记录时选择“合并校订记录”或“保留本机记录”；同内容不重复，同标识的不同版本拒绝覆盖。
5. 修改工程、导出格式或附带内容后，旧下载失效；取消构建不留下半成品下载。已处理的记录提示在正常重开时不再出现。

桌面、390 px 和浅深主题使用生产页面核对。入口与说明直接位于现有发布步骤、下载结果和首页导入，不增加独立设置页面。

## 包内内容

| 路径 | 用途 |
| --- | --- |
| `game/index.html` 及目录格式的相邻文件 | 玩家游戏；目录包的网站部署仅使用 `game` 内容，保持相对路径 |
| `source/project.zip` | 可编辑剧情、设置、素材索引与原始媒体，可单独导入 |
| `review/playtest-notes.worldreview` | 用户明确选择附带的校订记录；不进入玩家游戏 |
| `开始使用.txt` | 试玩、恢复制作、记录和网站文件的说明 |
| `delivery.json` | 作品/版本、源工程与游戏语义摘要、入口及其他文件的大小/SHA-256 |

游戏使用发布名称，源工程保留内部项目名称。因此两份语义摘要可以不同；构建时核对游戏是否由当前工程应用发布名称后生成。恢复时先检查完整文件清单、大小/摘要、源工程和发布信息，再写入工程。附带记录同时检查格式和工程身份。

使用现有 stored ZIP 交付，解包总量上限 512 MiB，最多 8,192 条目；大作品需分别导出。逐文件摘要用于发现损坏，不是签名或来源认证。包不包含玩家存档；校订记录仍属于本机个人制作资料，未实现云协作或多窗口同时写入的原子保证。源工程保存和备份使用既有流程，没有新增跨存储原子事务保证。
