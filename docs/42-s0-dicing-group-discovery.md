# S0.23 自动 Dicing 分组与源去重成本审计

## 问题与需求对齐

S0.22 证明了精确切块和逐字节重建，但把所有候选图片作为一个聚合组，也按每个 Asset ID 重复计算 Original RGBA。正式自动切图不能依赖人工先分组，也不能在两个稳定 ID 已复用同一内容寻址源时重复计算原图成本，否则会夸大收益并制造过大的 Atlas 候选。

S0.23 解决自动相似组发现和源去重感知成本。仍只生成分析报告，不发布 Atlas 或改写源素材。

## 相似度契约

每张图使用 S0.22 的 64px 精确 RGBA Cell 计划。自动相似度只比较尺寸完全一致图片的非零块多重集合，使用 weighted Jaccard：每个摘要计数的最小值之和除以最大值之和。

全零透明块不参与相似度，避免仅因大面积透明画布把无关立绘误判为同组。不同尺寸直接视为不兼容；完全透明图保持独立。

默认最低两两相似度为 35%，每组最多 8 张。聚类采用确定性的 complete-link 合并：两个组只有在所有跨组图片对均达到阈值时才能合并。这样 A≈B、B≈C 但 A≉C 的传递桥不会形成巨型误组。分数相同时按稳定 Asset ID 组合排序，输入顺序不影响 `discoveryDigest`。

## 成本修正

Original RGBA 成本现在按包含宽高的解码像素摘要去重。多个 Asset ID 若解码结果完全相同，只计一次 Original RGBA，并在分组报告中显示 `duplicateDecodedImageCount`。Manifest 仍按每个逻辑图片和每次放置计费，因为运行时映射不能省略。

这项修正避免与内容寻址 Blob 去重重复计算。它仍是 RGBA/Manifest 代理，不代表最终编码包、GPU 纹理或加载成本。

## Worker 与 UI

隔离 Worker 解码候选后返回 `lossless-rgba-dicing-discovery/v1`：已评估图片数、阈值、严格候选组、未分配图片和确定性摘要。每组包含成员、最低两两相似度以及经逐字节重建验证的 S0.22 收益报告。

资源保险库至少有两张已检查 PNG/JPEG/WebP 才允许运行。结果逐组显示“建议 Atlas 候选”或“保持 Original”、成员、最低相似度、重复放置、重复源、代理节省和计划摘要。分析仍可取消且不写资源存储。

## 测试与反例

- 两个完全相同的解码源只计算一次 Original 成本；
- A/B 与 B/C 达阈值、A/C 不达阈值时，只形成确定的严格二元组；
- 不同尺寸、全透明图片和阈值不足图片保持未分配；
- 候选输入顺序变化不改变发现摘要；
- Worker 报告必须与请求图片数量一致，并递归验证每个组的数值、摘要与重建状态。

## 非声明范围

S0.23 尚未利用文件名、标签、章节和同时加载范围，也未实现用户固定/排除组、Atlas 排布、Padding/Extrusion、真实编码成本、派生发布、增量重建或目标设备内存验证。下一阶段必须先冻结 Atlas/Manifest 与运行时回退契约。

## 审计证据

- `npm run check` 通过：34 个测试文件、218 项测试全部通过，生产构建、架构约束、脚本性能与资源性能门禁均为 PASS；
- 8 张 512×512 RGBA 候选图的严格分组、收益分析与逐字节重建为 1069.77 ms，低于 3000 ms 预算；测试结果为 1 个严格组、441 个重复放置、85.83% RGBA/Manifest 代理净节省；
- 浏览器实机确认资源保险库显示 S0.23 分组能力，历史未检查资源不进入候选且按钮安全禁用；
- 浏览器实机确认即时预览默认仍为 16:9 / 1920×1080，并保留 16:10、4:3、21:9、9:16 与自定义尺寸选项。
