# Web 发布更新与已核对旧档

2026-10-14；起点 `ee753b7`；接续 #313。

## 本批设计

发布设置增加可收起的“旧版存档兼容”步骤，上传上一版完整工程 ZIP，核对作品内容；不导入或替换当前工程。仅允许发布版本变化，其他实际交付的 canonical 工程内容必须完全相同。工程内部名称最终按发布名称替换，因此指纹按发布后的名称计算；发布名称或图标变化也会失效。核对结果随工程保存，后续内容变化自动失效，可主动移除。继承之前仍有效的版本核对，最多 32 个。

兼容声明不参与编译执行身份；播放器从当前完整内容和已核对旧版本重新计算旧构建身份，不接受用户提交的任意 Build ID。只在严格加载报构建不符时，允许这些核对过的身份再次进入原 Runtime 的完整校验。保持存档原字节、旧执行身份、所有检查点/历史/分支归档与哈希；不就地改写旧槽位。继续保存和恢复记录使用实际 Runtime 身份，当前显示和媒体使用新版一致内容。

UI 呈现核对状态、失效原因和旧档读取反馈；标题恢复入口允许已核对旧版本，其他版本继续明确拒绝并保留当前进度和旧档。离线更新不强制重载。Web 交付包将记录兼容范围。

## 必要验证计划

领域核对和失效边界、Player Core 完整历史读取/再保存/拒绝损坏与异项目、Shell 槽位与恢复身份、类型和 Web 构建。浏览器实际上传上一版工程、导出并更新旧目录、离线读旧档/继续保存/刷新恢复，以及未核对版本的拒绝。两路线已有 #313 整链记录，本批只复查受影响步骤。

## 结果

### 交付

- 核对入口、通过/失效/不一致提示、手动移除随工程保存；正文、设置、变量、UI、本地化、素材与布局等完整指纹参与校验。拒绝的核对不会变更当前工程或已有有效核对。
- Player Core 仅对核对过的版本重算的 release 构建身份启用兼容，原 Runtime 完整解析、Project/Runtime/IR/格式、历史和哈希校验继续执行。未改变 Runtime 保存格式或校验器，不接受任意 Build ID 别名。原执行与构建身份留在加载的历史内，检查点/手动/自动/快速/恢复与内存保护写入使用实际 Runtime 身份；未自动改写原槽位。
- 旧版恢复入口可用；读取成功提示核对过的旧档，未核对则可见拒绝并保留当前状态。手动存档的本地时间误带 UTC 后缀也已修正。
- 修复明确导入同一 Project ID 时旧本机快照覆盖新 ZIP 正文的问题。导入的新 workspace 首次打开优先使用导入源，普通最近项目仍沿已有快照恢复；结构返回契约保留。此修复在实际 UI 重导出的内容变化测试包中得到验证。
- 当前 1.5.3 源工程、HTML 和目录在 `evidence/web-save-updates`。相对 #313 的 1.5.2 全部 62 源条目中只修改 manifest 的发布版本并增加核对声明；全部正文/语句/分支/布局/媒体字节保持。声明核对 1.5.1、1.5.2；目录附 `save-compatibility.json` 和实际范围说明，浏览器报告记录三产物大小与 SHA256。

### 实际验证

相关 **10 文件/162 个不同测试通过**：8 文件/157 项 (`regression-final.log`) + 导入/结构连续性 2 文件/5 项 (`import-regression-final.log`)。覆盖核对保存/继承/失效、完整分支归档的读取/前后退/再保存、损坏哈希拒绝、发布名称替换、Shell 旧档/检查点/恢复身份、导出/离线、编译器冻结构建身份及旧格式 museum。类型检查 (`typecheck-final.log`)、Editor 最终构建 (`editor-build-final.log`) 和 Player 构建 (`player-build-final.log`) 通过；两应用仍有 >500kB chunk 提示。

Chromium **155.0.8059.41** 的 **7 组实际生产浏览器流程通过** (`browser-third.log`、`browser-checks.json`)，错误为空：

1. UI 核对 1.5.1/1.5.2，拒绝变动正文的上一版 ZIP，重导源媒体/正文保持。
2. 同一作品的实际变动正文重新导入，原核对失效，测试目录不声明可读旧档。
3. 原 1.5.2 下载完整离线缓存、断网重开并读快速档。
4. 更新等待保留原窗口，关闭后启用 1.5.3；旧恢复点和快速档可以读取，断网重开和缓存音乐正常。读取前后原快速槽位（含压缩数据）的字节摘要相同。
5. 旧会话继续推进，另存手动槽位，在 390px 视口原生弹窗内保存/刷新/断网读取同一进度，原快速档保持。
6. 实际编辑器导出的内容变化测试包 1.5.4：关闭后正常启用，旧恢复禁用、旧快速读取可见拒绝，当前标题状态及原槽位摘要保持。
7. 当前单文件 HTML 在本地 file 地址打开、快速保存、刷新并读取同一进度。

本轮没有重跑两条完整结局，沿用 #313 两路线记录，不将其计入这 7 组。1.5.1 本轮验证工程核对/声明，实际离线跨版本读取链是 1.5.2→1.5.3；不声称各历史版本/引擎均已运行。内容变化包仅在工具下载临时区内作为拒绝测试，不是交付的 1.5.3 成品。

### 失败与修正

- 初次类型检查发现 readonly JSON 数组不能由 Array.isArray 完成类型收窄；增加对象守卫。首次核对测试使用了不合法的 Gal settings 字段，改为真实历史设置变化。测试未放宽产品校验。
- 新 Shell 测试误用 Playwright 的 `exact` 参数给 Testing Library，类型/初次构建失败，移除无效参数后通过。
- 浏览器第一轮没先从项目菜单回“所有项目”，导入输入不存在；修正工具。第二轮实际发现同一作品的 ZIP 新正文被旧快照替代，记录 `import-source-failure.json` / `import-overridden-source.png`，修复来源优先级后第三轮 7 组全链通过。
- 导入回归第一次普通重开时误等固定“保存到本机”文字，实际按钮显示恢复后的状态；改等真实保存按钮可用，导入新正文与普通重开断言均通过。原失败日志保留。

### 未执行与边界

未跑全仓/全部 Editor/完整 check、全部历史 golden、其他浏览器引擎、物理手机/旋转、长期运行/旧长帧、自然阅读与配音听感、授权或实际公网。手机尺寸不是物理设备。Editor 的源码优先级还未对所有旧工程/版本做全量矩阵。

本轮是**同内容、同编译器/Runtime/IR/存档格式契约下的版本号兼容**，不是剧情编辑后的存档迁移。旧引擎/格式/编译身份无法重算一致时继续拒绝。未提供跨域名/设备的存档携带，也未提供玩家自行切换原包。读取不改写原槽位，但玩家明确快速保存或确认覆盖手动槽位仍按原保存规则替换该槽位。

后续仍按 #304 推进用户实际使用的作品定稿与交付，补存档携带/备份、自然节奏、真机和素材来源；原生平台搁置，不要求选择发布平台。
