# 启动来源哈希与 1.7.7 候选 · 2026-10-16

接续 `d4e3362` / [#345](345-web-startup-and-long-session.md)，按 [#304](304-web-complete-gal-delivery.md) 处理玩家打开游戏时的实际等待。剧情、素材、画幅和存档协议不变；Windows/Android 原生仍搁置，不新增公网部署或授权声明。

## 实际原因与实现边界

Core 原来先完整编译当前工程，再核对兼容回执；每个已核对版本还要完整序列化同一份正文、布局、设置等文件，并从头计算来源 SHA-256。发布版本越多，启动工作越多；不能通过减少已核对版本、信任外部 Build ID 或跳过校验来解决。

这批保留相同规范 JSON、UTF-8、SHA-256 和编译身份：

- Domain SHA 压缩轮使用八个标量，不在每个 64 字节块解构/创建状态数组，保持独立可移植实现，不引入浏览器/Node 加密提供者依赖。
- 只在同一次兼容核对内序列化完整工程一次。对规范文件映射建立快照，复用 manifest 值之前的 SHA 压缩状态；每个指纹/版本仍加入自己的完整 manifest 和其后的全部文件，使用完整输入字节长度及标准 padding。不是“前缀哈希再拼哈希”的新协议。
- 前缀快照只显式持有八个状态字、至多 63 个尾字节；后续文件字符串仍按需保留，不能说成整个工程零内存。调用者修改原字节或文件映射不污染快照，各后缀独立；无跨调用的工程对象缓存，原地修改后重新计算并使旧回执失效。
- 回执精确字段、32 版本上限、重复/非法版本、指纹和发布设置照旧检查。内部许可材料/回执不进入运行身份，公开署名及所有未知源字段仍进入。作者内部标题与公开名称的原有指纹归一化规则保持，非规范 manifest 路径别名沿原序列化覆盖顺序回退计算，不擅自改变身份。
- Core 根据这些完整来源哈希重新推导旧 Build ID，正式读档仍完整验证 History、哈希和版本；#345 的前后台受控线程、持久化协调器和错误保护保留。

启动全工程编译和至少一次来源计算仍在主线程；没有变成异步启动，也不保证超大工程没有等待。

## 验证设计

独立 Node crypto 对照空串、已知向量、百万字符、多块/所有 padding 边界、全部 Unicode 标量、组合字符/未配对代理项；字节前缀/后缀覆盖 193×129 组合、非零 byteOffset、跨 UTF-8 字符边界、输入修改与重复调用。规范文件哈希覆盖首/中/尾路径、数字键、`__proto__`、引号/反斜线/中文键及可变输入快照；1/8/32 个版本逐一对照原完整序列化，并真正构建/保存/读取全部 32 个旧版本，保存字节保持一致。

实际作品的五次新上下文冷启动用固定 **1.7.6** 包作基线：旧组使用原归档，当前组仅替换 runtime/CSS，payload/25 媒体不变。首次附主线程 CPU 采样；只在归档 JS 与当前映射构建摘要一致时映射源码，不用新偏移解释旧包。最终 1.7.7 实际包另测并核对 ZIP 摘要，不把增加兼容版本后的候选冒充相同输入。

另用同一实际工程构造 1/8/32 个有效版本列表，每档五个新浏览器上下文，计时公开 `createPlayerCore`；回执准备在计时外，因此这是版本扩展性探针，不是冷页面启动、统计基准或物理手机验收。两组全部 15 个当前/旧 Build ID 列表逐项一致。480 段合成文本仍实际逐句点击到 120/240/480 再保存/推进/读取；基线四个变更模块冻结在 `d4e3362`，对子 Worker 同样覆写，重建 bundle 必须与 #345 最终当前组完全一致。未注入私有 History、填数据库、伪造媒体结束或强制 GC。

## 实际候选与回归

**最新候选 1.7.7，四产物在 `evidence/web-source-hashing`：**可编辑工程、HTML、目录 ZIP、独立 `.worldreview`。实际编辑器导入 1.7.6、应用版本/核对上一版、保存、返回首页刷新重开，再正式双导出，不在脚本中直接改源工程版本。除 manifest 的版本/兼容回执外，64 个源条目和 25 媒体字节保持；九场景/两结局、9,672 字符/74 演出不变。原 1.7.6 不覆盖。

核对列表 1.7.0–1.7.6，本批现场快速槽位/`.worldsave` 来自 1.7.6，不宣称全部已发行旧版均现场重跑；合成 32 版回归也不是 32 个真实发行包。1.6.0/更早已变剧情仍用原游戏。25 项 permission=pending、11 条 fixed / checkedSourceHash=null 的原校订文件字节保持，未代写人工 verified。

相关 98 个 Vitest 文件/789 项与三个 Node 工具文件/18 项，共 **101 文件/807 项**通过；相对上批新增 40 项。类型、Editor/Player 双构建、工作区/架构/需求/交付基线审计通过。大 chunk 和 jsdom 原生媒体未实现提示保留，不当全仓/生成语料/历史所有预算通过。

本机 Chromium 151、Firefox 153、Windows WebKit 26.5 完成实际声音失败/按轨恢复、无声阅读/旋转、1.7.6→1.7.7 多窗口等待更新/离线旧档及实际备份读取，各两条完整在线路线，加 Chromium 本地 HTML。最终作者制作与矩阵 **17 项**，`sourceReused=false`；作者的一次检查已计入，不重复加。六条路线各六句自然结束语音、60 段旁白，结局独立恢复落盘后刷新、显式恢复完成，再核对同一状态和画面。前台/恢复 Worker 均实际完成且无 fallback/失败。#345 一次间歇 WebKit 点击稳定性超时这次未复现，不宣称找到或修复了其根因。

同一 Chromium 页面交替八轮约 **271.9 秒**，528 段文字/48 句自然结束语音；544 个恢复任务与 9 个前台任务完成，553 个自有 Worker URL 创建/撤销相等，原生 Worker 峰值 2。每轮回标题时计账、计算、URL 与声音收尾归零；画面计账峰值 47,437,942 B / 64 MiB。没有每轮关页或强制 GC，不作为物理内存无泄漏/两小时证明。已查看 320 px、横屏无声阅读及 WebKit 结局截图，原布局保持；不是物理手机验收。

最终审计逐字节核对源码默认/隐藏 map 构建、双游戏与四产物摘要，重建冻结旧/当前夹具并核对报告；完整状态和边界见 `audit.json`。

## 接续顺序与边界

1. 在这批身份/旧档回归保持的基础上，继续定位首次离线栏布局及长篇推进、checkpoint/内存压力长帧；本批没有改这些路径，也不关闭旧约 616.6 ms 长帧或两小时门槛。480 段无媒体夹具不替代真实长篇多分支媒体作品。
2. 有真实 Safari/macOS/iOS 与物理主流手机后补系统键盘、后台/锁屏、低内存和严格离线媒体；Windows Playwright WebKit 的原生媒体绕过 ServiceWorker，JS Range 缓存成功仍不当离线音频通过。
3. 所有者补齐 25 项来源许可（含系统 TTS 再分发）、身份/联系方式及获准 HTTPS 地址，再进行实际站点发布/更新/回退。11 条 fixed / checkedSourceHash=null 人工记录、全文阅读/听感/美术/计时、Stable/M1 均不代填通过。
