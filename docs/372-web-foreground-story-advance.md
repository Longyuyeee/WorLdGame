# 372 长历史普通推进与可取消计算

2026-10-17，接续 [#371](371-web-reading-paint-and-recovery.md)。目标仍是 [#304 Web 完整 Gal 制作与交付](304-web-complete-gal-delivery.md)：玩家持续阅读时，计算下一句不应把菜单、滚动和取消操作一并卡住。本批处理普通手动推进的主线程整链校验，不增加装饰模板、发行范围或原生端。

## 普通推进的事务边界

正式独立 Web Player 在已有原生 Worker、当前为正文展示、没有记录未来／回想且历史达到 480 条时，把用户的普通推进交给既有前台计算 Runner。480 是本轮实测覆盖的启用范围，不意味着较短故事或所有主流手机都很快。短篇、启动、回退后的记录未来、选择、等待媒体输入、Auto／Skip 和作者预览继续使用原路径。

[线程任务](../apps/player-shell/src/story-advance-task.ts)仍调用公开 `advancePlayerCore`，每次完整校验当前历史及所有旧检查点，执行相同规范编码、SHA、内部演出、检查点和纯 Host 协调。不引入跨调用的对象／摘要／校验缓存，不把校验前提带回主线程继续执行未经校验的 Runtime 追加，也不改 Core、Runtime 或存档协议版本。

发送保留全部实际 Core 输入和完整历史，只排除不属于 Core 的宿主扩展。返回十一项执行字段及本次来源信息，不送回或替换主线程的编译产物、语言、作品信息和策略对象。若本次公开 Core 调用没有改变回想数组，主线程保留原数组引用，避免仅因传输换引用而重复同步读取／校验回想档案；新捕获的记录照常安装。此信息不是历史校验标志。旧回想及检查点候选均保留，完整历史仍双向复制，没有把传输成本当作已经解决。当前 Worker 的输入和结果是同版本应用内部计算，不是开放给第三方的可信结果接口。

主线程检查请求 ID、原检查点身份、工程／构建／执行身份、游标、数量、版本计数和封闭结果字段；失败保留当前句。真正安装结果前还必须确认同一 Runner、同一个未改变的私有 Core 对象、相同交互权限和未取消请求。下一次公开推进、保存或读取照常完整校验，没有持久信任标志。

## 玩家等待和恢复操作

[交互协调](../apps/player-shell/src/use-story-advance.ts)在计算期间保持原句，明确显示“正在继续故事”，提供至少 44px 的取消按钮，暂时禁用正文按钮。重复点按不排队，也不会在计算完成后突然多跳几句。取消只丢弃尚未提交的计算，当前状态和存档不改变。

打开菜单、设置、历史、存读档或欣赏画面，保存／读取当前句，切换工程／语言／策略，宿主暂停和压力事务都会使旧结果失效。显式保存先取消未提交推进，保存玩家仍然看到的那一句，不偷偷保存尚未显示的新句。新一代状态不会被迟到回复覆盖。

失败或五秒计算超时后显示可理解的提示，可以重试，或明确选择“使用兼容模式继续”。不会自动在主线程重复执行失败任务。兼容模式仅在当前 Runner 作用域内保持，新工程／作用域重置；没有 Worker 或创建受限时保留既有兼容计算，不能承诺相同性能。

普通推进复用原前台线程池，不创建第三个常驻计算通道。新增的外部取消信号只取消这一项推进，不取消排在其后的显式保存；监听在完成后移除，取消和失败销毁正在使用的线程，正常完成仍由原闲置策略释放。Worker 不播放音视频、不创建舞台解码对象、不直接写入存储，真实媒体只在主线程确认结果后按原 Host 数据更新。

## 验证方法

证据单独位于 `evidence/web-foreground-advance`，不覆盖 #371 或旧产物。基线冻结 0ecab62 的 Runtime、Shell 生产源码及 CSS，主线程与子 Worker 使用相同覆盖。新增等待提示样式是本批有意变化；基线与最终 CSS 各自保存并核对摘要，不伪称 CSS 字节相同。

报告中的 `head` 是采样时的基底提交，不是宣称未提交的 current 改动已经属于 0ecab62；最终 current 由本批提交和各自重新构建核验的 bundle 摘要定位。

两种夹具均通过真实按钮读到 120／480／960 条；每点三轮保存、实际推进和读取。脚本必须等到推进任务结束且真实状态改变，不能把一次翻页／等待语音／启动计算当成已经到达下一句。比较规范存档字节与摘要、状态／正文／游标和完整历史，分别记录主线程长任务、CPU、消息发送及恢复落盘。所有计时为同机串行样本，不是统计性能、物理手机或两小时运行结论。

CPU 只采样主线程；Worker 内仍执行同一份完整计算，不能由主线程采样下降推断总 CPU 减少。`initial-*`、`pre-replay-current.json`、`pre-menu-current.json` 和早期专项报告保留中间过程，不计作最终验证；部分中间性能采样与独立回归重叠，不用于收益对照。最终代码固定、回归与浏览器检查结束后，再单独串行重测两种 current，对照独立运行的冻结 baseline。

额外交互检查复用真实混合媒体和真实 Worker，只在测试侧暂存其已计算完成的回复，再用公开按钮取消／保存／读取，释放捕获的旧回调，或注入一次传输失败。它验证事务与恢复，不是正常速度或主线程计算性能测量。受控单元测试的短工程强制进入线程协调路径，不能冒充真实长历史；长历史由浏览器自然读到。

十二次 480／960 条最终普通推进均未观测到浏览器报告的 ≥50ms 主线程长任务。960 条文字基线三次为 82／97／99ms，混合为 253／95／109ms，最终均为空；480 条基线本来就没有这种长任务，不把它写作新增收益。保留本批的理由是长计算期间主线程能响应菜单和取消，不是新句更早出现：完整历史新增一次往返，480／960 的总等待、新正文帧和恢复落盘均更晚，尚未达到整体流畅性通过。

960 条前台发送本身仍同步花费约 18.6–22.8ms，后台恢复发送约 16.7–19.9ms，均非完整复制或总线程计算成本。快速保存文字 545.0→546.0ms、混合 593.9→545.1ms；读取文字 661.5→743.2ms、混合 665.1→680.1ms。存读档没有因本批路径发生有意提速，顺序样本有波动且部分变慢，不宣称总体性能改善。120 条未启用推进线程，其变化也不能归因于线程化。

十八个对应快速槽的规范字节数／SHA、Session artifact hash、状态／正文／游标及完整长度全部与基线相同，最终分别为 6,427,956 和 6,641,623 字节。公开压力保护先保存完整 960 条，再缩为 64 的内存窗口；刷新显式恢复回到完整 960 条和原 hash，快速槽保持。两组线程所有权并发峰值 2，保护和卸载后为 0，页面／媒体错误为空。混合夹具使用仓库小尺寸 PNG／WAV，背景、两个立绘、BGM 和有限语音均按原生媒体运行；冷恢复后舞台／音轨相同、静音语音自然结束，不代表真实大素材、视频或人工听感。

两组 baseline／current 的主线程及子 Worker bundle、CSS、夹具和冻结源摘要已分别重构建核验；最终空闲截图也各自与基线逐字节相同并已查看。新的等待提示样式有意改变 CSS，空闲像素相同不等于 CSS 字节相同，更不等于手机或长期验收。本批没有运行全仓测试、三引擎完整矩阵、严格离线升级整链或两小时稳定性。
