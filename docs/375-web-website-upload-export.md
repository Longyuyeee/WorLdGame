# 375 网站上传包与同版交付

2026-10-17，接续 [#374](374-web-source-review-workflow.md)，继续 [#304 Web 完整作品制作与交付](304-web-complete-gal-delivery.md)。作者现在能直接从编辑器生成只含公开文件的网站上传 ZIP，不必先安装 Node.js、下载带助手的目录包再生成纯网站文件夹。实际上传、素材发行确认和公网验收仍由各自任务完成，生成包不会创建网站或自动批准发布。

## 用户任务与导出用途

原目录包已提供本地预览、纯网站目录生成与只读远端核对，但普通作者必须先装 Node.js，才能按推荐流程取得可上传目录；制作交付包的说明又容易让人把整个 game 文件夹或内部包误当网站文件。本批补齐直接导出，并同步生成摘要、下载按钮、制作包与准备清单中的说明，不新增托管平台或上传权限。

| 编辑器选择 | 文件用途 | 网站发布时如何使用 |
| --- | --- | --- |
| 单文件 HTML | 直接试玩和分享，媒体内嵌 | 要目录部署时另选网站上传 ZIP |
| 网页目录 ZIP | 分离媒体，附本地预览及部署核对助手 | 使用助手生成纯网站目录，或直接另选网站上传 ZIP |
| 网站上传 ZIP | 仅同版公开文件，无本地助手 | 完整解压，上传其中内容，不多套一层文件夹；包含 build-info.json，最后更新 sw.js |

“同时生成制作交付包”仍是独立的作者备份选项，不是第四种公开游戏格式。它包含可编辑工程、游戏、内部来源清单和明确勾选的校订／试玩资料，不可整包上传。网站用途的制作包中 game 已是同版纯网站内容；普通目录用途的 game 仍含本地助手，说明不再让作者直接整目录上传。

网站包文件名包含作品名与发布版本，例如 `雨停之前-1.7.14-website.zip`；原 HTML 和本地目录文件名保持兼容。三种选择会随本机工作位置记住，检查、定位修复和试玩后返回仍保留网站用途；刷新重开回到生成步骤，不恢复失效下载链接或自动构建。原 html／directory 位置记录继续可读，未知格式仍拒绝，不把个人选择写入源工程。

## 同版文件与取消边界

网站用途复用正式目录导出器，重新读取和验证当前工程与素材，沿用原优化、公共工程摘要、媒体相对路径和离线清单。公开文件及 build-info.json 生成后，只有本地目录用途才增加五份助手／说明；网站包不是重读旧 ZIP 后按扩展名删文件，也不重写玩家数据。用途分支位于原媒体优化与离线文件生成之后，不改变优化算法，未增加新 Runtime、Core、存档或制作包协议。

网站包和本地目录包的同版公开文件逐字节一致，差别只有 `preview.mjs`、`deployment-check.mjs`、`check-deployment.cmd`、`start-preview.cmd` 和 `使用说明.txt`。保留同版普通目录包时，其检查器仍可对实际站点只读核对。直接生成网站包不要求 Node.js；运行这个可选本地检查器依旧需要 Node.js，二者没有混为一项能力。

构建沿用工程／发布用途代次和取消控制。未应用的发布设置隐藏旧链接；应用版本或切换格式后释放旧游戏、内部包 URL，必须重新生成。制作包先等待同次源工程保存，保存失败不提供半成品，可明确重试。取消、卸载和切换到其他用途使迟到结果失效，旧网站计算不能覆盖后来生成的 HTML。网站包直接生成，不为二次筛选常驻另一份目录 ZIP，计算线程机制沿用原实现。

原《雨停之前》1.7.14 的实际网站包共 **36 文件**：35 个原目录清单文件加 build-info.json；全部公开字节与同版本地目录一致，少五份助手／说明。本批验证副本只在一项待确认来源依据中写入内部测试标记，其余 64 个源工程条目逐字节保持；所有剧情、素材和来源事实保持。标记仅在制作包的源工程和内部清单保留，网站文件中不存在。新浏览器资料导入制作包后能继续编辑并读回依据，25 项仍待确认、确认人和日期没有被填造；原候选工程没有被改写或重发。

纯网站包完整解压后，原检查器本地核对 36 文件通过；仅用这些公开文件启动本机 HTTP 子目录站点，再用原只读检查器核对 36 文件通过，私有源路径返回 404。Chromium 触屏尺寸下实际开始故事、快速保存、主动下载离线内容，断网刷新由 Service Worker 响应，显式读取恢复原 hash，并等待背景／立绘就绪。此处验证的是同版缓存与已保存位置，不是公网、物理手机、自然听感或旧版升级整链；没有将初始“正在准备画面资源”的截图当作画面已就绪。

## 复跑入口

在 `http://127.0.0.1:5195/` 提供生产预览后，执行 `npm run audit:web-website-export:browser`。可用 `STUDIO_UI_URL` 更换地址、`STUDIO_BROWSER_ENGINES` 选择作者操作引擎。工具先核对当前页面及 JS／CSS，再使用原工程，实际导出和断网部分只在 Chromium 执行；只读核对只访问自己启动的 loopback 站点，不访问外部账户或上传文件。

完整作品沿用 `tools/run-web-contextual-review.mjs`，设置 `STUDIO_CONTEXTUAL_OUTPUT_DIRECTORY=evidence/web-website-export/work`、`STUDIO_VERIFY_SESSION_LOAD=1`、`STUDIO_CONTEXTUAL_DIRECTORY_PURPOSE=website`；默认仍是原 directory 用途，不改变其他历史复跑命令。两种工具仅删除自己创建的确切临时验证目录，仓库原工程与素材保留。
