# 373 长历史结果的无损回传与读取

2026-10-17，接续 [#372](372-web-foreground-story-advance.md)。仍按 [#304 Web 完整 Gal 制作与交付](304-web-complete-gal-delivery.md) 推进：玩家读到长篇后，既要能取消等待，也要减少下一句和读档结果出现前的等待。本批只处理前台计算结果回传，不扩展装饰模板或原生端，不改变原完整作品剧情版本。

## 完整结果与无损传输

既有 Worker 每次仍调用公开 Core 推进／读取，完整检查输入历史、全部旧检查点、规范编码、SHA 和旧档兼容；成功之后才执行[结果传输编码](../apps/player-shell/src/history-result-transport.ts)。不编码输入、不保留上次源或结果，也不持有跨调用的“已验证”结论。

历史达到 480 条时，推进和读取的成功结果将每个检查点的已读、画廊解锁、结局三个有序 ID 列表表示为与本包前一个检查点相同的前段、后段和中间内容。接收端重新构造全部列表与检查点。它不是只发新增历史：第一份内容包含在本包内，任何引用都只指向本包的表，不使用主线程的旧历史补前缀，也不要求前一次请求成功。取消、重新建 Worker 和冷读档都不依赖前一次传输。

同包的检查点表覆盖主历史和所有中途自动检查点候选，共享检查点只传一次，接收后仍指向同一份重建对象。当前 Runtime 状态也恢复为当前检查点的同一个状态对象。历史事件、演出、输入墓碑、归档、完整未来、回想、所有候选及来源信息均保留；下一次公开推进、保存、读取仍照常完整校验。存档格式和规范存档字节不改，不把传输格式写入工程或存档。

短历史、失败、保存、压力保护及无 Worker 的既有兼容路径保持原传输／计算。原完整工程输入仍整份发送；后台恢复输入仍完整复制，#371 的慢复制避让规则保持。Auto／Skip、媒体等待、回退未来和作者预览不因本批结果编码而扩大到异步推进。

## 失败与资源边界

解码检查包版本与成员、表大小、整数索引、列表前后段边界、新增项类型和稀疏项，拒绝错误编码包，不把它当普通结果重试。每个列表和检查点表沿用 Runtime 的数量上限；单包重建总量最多八百万个 ID 引用单元，避免小包造成无界展开。合法结果若超过这一编码预算，发送端使用原完整普通传输，不减少历史、不新增 Runtime 容量限制。此预算不是内存占用或手机容量承诺。

请求 ID、工程／构建／执行身份、来源检查点和当前代次仍由原前台协调检查；取消、菜单、显式存读档、暂停和工程切换沿用 #372 的事务保护。[前台客户端](../apps/player-shell/src/foreground-session-client.ts)在触碰结果前先拒绝已经结束的回调，迟到的大包不会再被无意义地重建。解码错误进入原失败提示并释放线程／URL，不从事件回调抛出未处理异常，不自动在主线程重复执行。五秒超时、明确兼容模式与最多两个计算通道保持。

这是同版应用内部 Worker 的结构检查，不是接受第三方历史的可信接口，也不代替下一次公开入口的完整历史与 SHA 校验。

## 验证口径

证据位于 `evidence/web-history-result-transport`，不覆盖 #372。性能基线冻结 9951317 的 Runtime、Shell 生产源码和 CSS，主线程和子 Worker 使用同一冻结源。两组夹具保持，当前只读额外传输标识与检查点数量，不在计时回调内做 JSON 序列化或模拟传输。

报告 `head` 是采样时基底，不表示 current 改动已属于 9951317；最终代码由本批提交与重新构建核验的 bundle 摘要共同定位。全部回归／浏览器检查结束后才串行采样，不与构建或测试并行。

两种夹具分别用真实按钮自然读到 120／480／960，每点三轮快速保存、实际推进和快速读取。规范槽字节数／SHA、Session artifact hash、状态／正文／游标／完整长度、压力保护和冷恢复必须对应基线；当前的 480／960 次推进／读取还必须实际收到编码包，不能只证明单元编码器可调用。计时为同机串行样本，主线程 CPU 采样不包含 Worker CPU，发送耗时也不等于完整复制成本。

专项回归使用公开 Core 自然生成 480 条历史，并实际经过两个中途自动检查点；重建结果和所有候选保存字节与原公开调用核对。回退后保存／读取确实包含记录未来。少量专门构造的列表、候选与超预算形状只用于编码分支／异常边界，不作为有效 Core 历史、性能或真实容量证明。

960 条正文帧回调文字 198.6→180.4ms、混合 216.9→212.5ms；恢复落盘观察文字 629.8→617.7ms、混合 661.4→667.4ms。帧回调不是物理呈现，落盘含存储与轮询。快速保存文字 512.6→527.7ms、混合 544.7→572.7ms；保存路径未启用此编码，没有有意提速。120 条完全未启用结果编码，其波动不能归因于本批。480 条总推进稍慢、读取只在混合 480 有较大差异，960 条收益小，不能由顺序样本宣称总体性能改善或手机达标。
