## 已开发

### 减少反复创建线程

前台存读档队列、独立恢复队列分别拥有一个可复用 Worker，任务仍串行。每个请求继续发送实际输入、使用唯一请求 ID、执行同一公开完整校验；不缓存工程、历史或验证结论。完成后移除请求的事件处理器/取消监听/超时，队列尾不保留大结果。

每个队列最多保留一个闲置线程，15 秒无任务即释放。超时、取消、无效回复或线程错误会丢弃该线程，下次重新创建。单次公共调用和内存保护继续使用一次性资源；不支持 Worker 时保留原完整校验回退。

更换工程/存储上下文或卸载会释放所属闲置资源；前台旧代请求仍取消。宿主暂停、内存保护请求释放闲置线程，在途计算正常完成后也不再停放旧资源；已经开始的物理 IO 不冒充可撤销。两个播放器的资源分别归各自宿主所有。

### 保存反馈跟随用户任务

- 自动保存和检查点失败在故事中显示非模态提醒，说明旧档保持不变；可以继续阅读、明确关闭提醒，或直接进入手动保存当前进度。
- 提醒不抢焦点，不在存读档、菜单、设置、历史、收藏、欣赏画面或回想里叠加；不会超时自行消失。当前进度成功保存后收起提醒。
- 后台保存结果不再修改手动/快速存读档的“写入中”状态或覆盖其面板提示；后台列表刷新失败也不抢前台状态。自动保存/检查点成功使用现有短暂回执。
- 快速/手动保存原有回执、覆盖确认、读档确认和失败后进入存档面板的路径保持。
