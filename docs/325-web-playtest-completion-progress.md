# Web 结局试玩进度与定稿接续 · 2026-10-15

接续 `872a1b2`（#324）。本批从创作者“试玩不同结局 → 记录问题与改稿 → 重新试玩 → 返回生成游戏”的流程推进。

## 已完成

- 检查页和发布生成步骤增加结局试玩进度。自动累计同一版本从故事入口实际运行到达的不同结局，显示当前数量、待试玩结局、场景和首次到达时间；明细默认收起，每页最多八项，支持主题和手机布局。
- 目标来自正式 Compiler 结局目录，不将未连接的草稿结局列为必跑目标；按稳定结局 ID 区分同名结局。同一结局重复观察不会增加数量。
- 当前版本与旧版本分开。改稿后旧记录保留，当前计数重新计算；局部场景/语句复测、尚未结束、版本不一致的运行不计入完整结局进度。
- 修复新进度统计中的关键误判：兼容热更新会在机器中回放旧路线，保留位置，但不能视作创作者重新试玩。Preview 单独保留本次启动版本，应用热更新即取消本次完整试玩资格，从头重启后才恢复。没有改变正式 Runtime/玩家存档格式。
- 从检查页或发布页一键从故事入口重启；校订记录仍走明确标注的局部复测。发布发起的试玩返回原生成步骤与 HTML/目录选择，不要求重复选择项目或导出方式。
- 按工程保存在当前浏览器，正常主页/刷新/重开继续保留。坏记录保留不覆盖；保存失败保留本次内存记录，离开原完成状态后仍可重试。写前合并已有记录并接收同源通知，不承诺跨窗口同时写入原子性。
- 这份进度是编辑器运行记录，不是人工验收或全路径覆盖；不增加导出门禁，未跑完仍可生成有效工程。它和问题清单分别保存，不进入工程、制作包或玩家游戏。
