# 可运行流程审计与验收顺序纠正

> 审计日期：2026-08-15
>
> 当前节点：N23 产品验收就绪；N30-E1 Compiler 工程候选
>
> 产品结论：N23-E1–E7 工程、验收协议与一键启动环境已贯通；真人记录仍为 N21 `0/1`、N23 `0/2`。N30-E1 已建立正式 Compiler 最小内核，但 N30 尚未整体验收，正式 Runtime/Player、构建与发布仍未进入

## 1. 为什么原验收顺序不成立

此前计划要求先执行 N21 非程序用户人工验收，再开始 N23。真实代码审计表明，这会让参与者面对一个只能按脚本行前后移动的 Preview：选择项是不可点击文本，`set`、`condition`、`jump`、`call`、`return` 没有执行语义，也不能从入口场景跨场景走到结局。用户无法判断自己创建的故事是否真正可玩，因而人工验收缺少必要前提。

产品负责人已明确：至少开发到能够运行一个完整流程后，才进行人工测试，并在参与者仍不可用时反复要求按顺序继续核心引擎开发。该决定由 `RA-N21-002` 固化；旧的、只允许开发到 N22 的 `RA-N21-001` 已关闭。当前例外只允许推进至 N30 Compiler 工程候选，仍然阻断 N21 Product Acceptance、N23/N30 Product Acceptance、N31、M1 Stable 和 Public Release。

## 2. 真实代码审计

| 流程节点 | 审计前 | 本轮结果 | 证据 |
| --- | --- | --- | --- |
| 从入口场景启动 | 只能查看当前场景当前行 | 按 `entrySceneId` 启动 | `playable-preview-runtime.ts` 单元测试 |
| 对白、旁白、演出、等待 | 只能线性定位，旁白/等待无舞台呈现 | 可逐节点继续并显示 | 编辑器集成测试 |
| 选择 | 选项为不可点击 `<span>` | 可点击选项并进入目标场景 | 双路线运行时测试、浏览器验收 |
| 变量与条件 | 无运行语义 | 安全解析、类型检查、赋值和条件跳转 | 变量/条件测试 |
| 标签、跳转、调用/返回 | 无运行语义 | 支持标签定位、跳转、调用栈和返回点 | 调用/返回测试 |
| 结局 | 只能手动定位到 `end` 行 | 流程状态明确为完成并显示结局名 | UI 集成测试 |
| 非法流程 | 无流程级错误模型 | 缺变量/标签、无结局和超过 1000 控制步时安全中止 | 失败路径测试 |

这是一条编辑器内可运行纵向切片，不等同于 N31 正式 VM、Player、存档系统或可发布游戏包。当前实现的价值是让创作者能验证“我写的分支确实跑得通”，并为真人验收提供可操作对象。

## 3. 冻结后的交付顺序

1. **N23-E1 可运行引擎闭环**：从入口启动，显示叙事节点，选择路线，跨场景并到达结局；自动化和浏览器证据必须通过。
2. **N23-E2 从空工程创作闭环**：在产品 UI 内建立最小故事、两条路线和两个结局，保存、关闭、重开后仍可运行；不得用硬编码样例代替。
3. **N23-E3 自包含资源工程**：源 Blob、Asset Index 与 Canonical Project 随同一 ZIP 迁移，新工作区导入、运行和重开均通过。
4. **N23-E4 独立试玩产物**：当前工程可构建为自包含离线 HTML；确定性、非法输入阻断和双路线到结局必须可复跑。
5. **N23-E5 五分钟内容量**：同一产品链可打开、编辑、运行并导出 3 场景、2 角色、2 结局且每条路线不少于 300 秒的作品；不得靠 Wait 灌水。
6. **N23-E6 验收协议**：冻结两名参与者各自的编辑、保存重开、编辑器双路线、独立 HTML 构建与双路线任务，并以机器门禁止伪造或漂移。
7. **N23-E7 验收启动器**：从仓库根目录双击后锁定安装、生产构建、固定本地 origin 并自动打开编辑器；真实 HTTP 烟测进入根门。
8. **N21 真人产品验收**：非程序参与者完成 T01–T07 创作/持久化任务，并执行新增 T08“完整流程试玩到结局”。失败必须登记缺陷，不得解释为通过。
9. **N23 产品验收**：按 `N23-PA-01` 由两名未参与实现者分别完成 P01–P06，Severity 0/1 为 0；关闭 `RA-N21-002`。
10. **N30/N31 正式运行时**：把编辑器验证运行时替换/提升为共享确定性 VM 和 Player Runtime，加入存档、兼容、性能及跨端契约。
11. **构建与发布**：只有需求矩阵、Golden、安装包、迁移、安全和发布门全部通过后才能进入 M1 Stable。

## 4. 每个节点的完成定义

### N23-E1（本轮工程候选）

- Goal：让现有合法工程在编辑器里走完一条真实路线；
- Implementation：执行状态、变量、控制流、选择、跨场景、结局和错误边界；
- Tests：运行时单元测试、React 集成测试、全仓 `npm run check`；
- Browser：真实浏览器中分别走到两个结局，无控制台错误；
- Audit：证据注明基线提交、分支、命令、结果和未覆盖范围；
- Gate：只允许标记“工程候选”，不能标记 N21/N23 产品通过。

本轮浏览器结构化记录为 [`evidence/n23/playable-flow-browser.json`](../evidence/n23/playable-flow-browser.json)：项目首页打开的真实示例包含 3 个场景、2 名角色，两条选择路线分别到达“留在电波里的名字”和“晚风知道答案”。

### N23-E2（工程候选已完成）

- 从空工程而不是示例工程创建内容；
- Writer/Sequence 能完成选择、变量、条件、演出和两个结局；
- 保存、关闭、重开后，文本、顺序、稳定 ID、Inspector 数据和资源引用不丢失；
- 重开后从入口完成两条路线；
- 导出的权威工程快照有哈希，浏览器操作日志可复现。

本轮从产品首页新建 `N23 Blank Flow Audit`，未打开示例工程；在结构管理器中建立 3 个场景、2 名角色和 1 个字符串变量，在 Writer 中建立对白、变量赋值、条件、标签、二选项、背景、音频和两个结局。保存并返回首页后重开，入口 8 个步骤、2 项资源及稳定 ID 均恢复，并再次到达“晨光抵达”。自动化 Golden 还覆盖导出/导入语义哈希 `56c361a9b16d1fd532e280f4f21ee5e131d9bdaef7765365c6d88d4f3d7cb0e1` 和两条路线。详见 [N23-E2 空工程可运行闭环审计](116-n23-e2-blank-project-flow-audit.md)与 [`evidence/n23/blank-project-flow-browser.json`](../evidence/n23/blank-project-flow-browser.json)。

### N23-E3（工程候选已完成）

工程 ZIP 现在包含 Canonical 文档、Asset Index 和经 SHA-256 校验的唯一源 Blob；旧文本 ZIP 仍可导入。浏览器已通过原生文件选择器导入新工作区，观察到 2 项资源 / Index r2、真实 Canvas 背景和 BGM 播放，两条路线到达两个结局；页面重载后从最近工程重开仍能读取资源。详见 [N23-E3 自包含资源工程 ZIP 审计](117-n23-e3-portable-resource-bundle-audit.md)。

### N23-E4（工程候选已完成）

即时预览区可把当前工程构建为一个自包含 HTML，文件内含经安全转义的工程快照、预编译表达式 AST、离线交互 UI 和最小运行器。`demo:empty-to-web` 已从“复制编辑器壳”升级为从空临时目录生成真实游戏文件，并执行左右两条路线到结局。详见 [N23-E4 独立单文件试玩 Web 审计](119-n23-e4-independent-playable-web-audit.md)。它仍是 N23 候选，不宣称 N30/N31/N50/N80 完成。

### N23-E5（工程候选已完成）

Benchmark 已扩充为原创短篇《末班电车前的五分钟》，项目首页可直接物化为新的 Canonical 工程。冻结内容量模型下两条路线为 366/370 秒，各 27 个可读节点且 Wait 贡献为 0；同一作品的独立 HTML 双路线执行通过。详见 [N23-E5 五分钟内容审计](120-n23-e5-five-minute-content-audit.md)。

### N23-E6（验收就绪已完成）

[`N23-PA-01`](121-n23-product-acceptance-execution-kit.md)现已冻结两个不同匿名参与者各自的 P01–P06：从产品入口打开、核对结构、编辑并保存重开、编辑器双路线、构建独立 HTML、独立 HTML 双路线。策略门同时校验准确结局、Severity 0/1、主持人边界、证据哈希、N21 前置与风险例外关闭条件。权威记录仍为 `pending-participants`、`0/2`，不代表真人通过。

### N23-E7（验收启动器已完成）

仓库根目录现有 Windows 双击入口；首次使用执行锁定安装，随后生产构建并在固定 localhost origin 自动打开。机器门真实拉取入口与全部 JS/CSS，并确认冻结产品入口存在。详见 [N23-E7 一键验收启动器审计](122-n23-e7-acceptance-launcher-audit.md)。它不宣称完成 Windows 壳、安装、签名或发布。

### 真人验收（E7 后执行）

- 参与者未参与代码/设计且不了解脚本语法；
- 主持人只能读目标和记录观察，不能操作或教具体控件；
- 20 分钟内完成 T01–T08；
- 记录求助、误操作、阻塞、设备、开始/结束时间和保存重开结果；
- 只有全部任务通过、证据哈希有效且 `RA-N21-002` 同步关闭，才能标记 N21 通过。

## 5. 当前仍缺少什么

- N21 一名及 N23 两名合格验收者的真实任务记录；当前分别为 `0/1` 与 `0/2`；
- 正式共享 VM/Player、确定性存档与恢复；
- 游戏 UI 模板、完整舞台/镜头/动画、输入映射；
- 桌面/移动构建、安装、签名、补丁和发布验证。

因此当前软件已经能从空工程创作、保存、以自包含 ZIP 搬到新工作区、重开、运行编辑器内故事流程，并导出可独立离线执行的单文件试玩；N30-E1 还可把 Canonical Project 编译为冻结 Hash 的 Runtime IR，但尚无正式 Runtime 消费该 IR，所以它还不是完整游戏引擎或正式发行包。详见 [N30-E1 审计](123-n30-e1-project-compiler-audit.md)。当前没有真人资源时保持产品门未通过；有参与者后先执行 N21，再严格按 [N23 双参与者执行包](121-n23-product-acceptance-execution-kit.md)完成 N23并关闭例外，随后才能进入 N31。
