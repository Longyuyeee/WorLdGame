# 可运行流程审计与验收顺序纠正

> 审计日期：2026-08-15
>
> 当前节点：N23 工程实现
>
> 产品结论：已形成编辑器内最小可运行流程；尚未完成真人产品验收、正式 Player Runtime、构建与发布

## 1. 为什么原验收顺序不成立

此前计划要求先执行 N21 非程序用户人工验收，再开始 N23。真实代码审计表明，这会让参与者面对一个只能按脚本行前后移动的 Preview：选择项是不可点击文本，`set`、`condition`、`jump`、`call`、`return` 没有执行语义，也不能从入口场景跨场景走到结局。用户无法判断自己创建的故事是否真正可玩，因而人工验收缺少必要前提。

产品负责人已明确：至少开发到能够运行一个完整流程后，才进行人工测试。该决定由 `RA-N21-002` 固化；旧的、只允许开发到 N22 的 `RA-N21-001` 已关闭。新例外只允许 N23 可运行纵向切片的工程工作，仍然阻断 N21 Product Acceptance、N23 Acceptance、M1 Stable 和 Public Release。

## 2. 真实代码审计

| 流程节点 | 审计前 | 本轮结果 | 证据 |
| --- | --- | --- | --- |
| 从入口场景启动 | 只能查看当前场景当前行 | 按 `entrySceneId` 启动 | `playable-preview-runtime.ts` 单元测试 |
| 对白、旁白、演出、等待 | 只能线性定位，旁白/等待无舞台呈现 | 可逐节点继续并显示 | 编辑器集成测试 |
| 选择 | 选项为不可点击 `<span>` | 可点击选项并进入目标场景 | 双路线运行时测试、浏览器验收 |
| 变量与条件 | 无运行语义 | 安全解析、类型检查、赋值和条件跳转 | 变量/条件测试 |
| 标签、跳转、调用/返回 | 无运行语义 | 支持标签定位、跳转、调用栈和返回点 | 调用/返回测试 |
| 结局 | 只能手动定位到 `end` 行 | 流程状态明确为完成并显示结局名 | UI 集成测试 |
| 非法流程 | 无流程级错误模型 | 缺变量/标签、无结局和超过 1000 控制步时安全中止 | 失败路径测试 |

这是一条编辑器内可运行纵向切片，不等同于 N31 正式 VM、Player、存档系统或可发布游戏包。当前实现的价值是让创作者能验证“我写的分支确实跑得通”，并为真人验收提供可操作对象。

## 3. 冻结后的交付顺序

1. **N23-E1 可运行引擎闭环**：从入口启动，显示叙事节点，选择路线，跨场景并到达结局；自动化和浏览器证据必须通过。
2. **N23-E2 从空工程创作闭环**：在产品 UI 内建立最小故事、两条路线和两个结局，保存、关闭、重开后仍可运行；不得用硬编码样例代替。
3. **N21 真人产品验收**：非程序参与者完成 T01–T07 创作/持久化任务，并执行新增 T08“完整流程试玩到结局”。失败必须登记缺陷，不得解释为通过。
4. **N23 产品验收**：补齐计划规定的五分钟内容量、3 个场景、2 名角色、2 个结局和两名未参与实现者验收；关闭 `RA-N21-002`。
5. **N30/N31 正式运行时**：把编辑器验证运行时替换/提升为共享确定性 VM 和 Player Runtime，加入存档、兼容、性能及跨端契约。
6. **构建与发布**：只有需求矩阵、Golden、安装包、迁移、安全和发布门全部通过后才能进入 M1 Stable。

## 4. 每个节点的完成定义

### N23-E1（本轮工程候选）

- Goal：让现有合法工程在编辑器里走完一条真实路线；
- Implementation：执行状态、变量、控制流、选择、跨场景、结局和错误边界；
- Tests：运行时单元测试、React 集成测试、全仓 `npm run check`；
- Browser：真实浏览器中分别走到两个结局，无控制台错误；
- Audit：证据注明基线提交、分支、命令、结果和未覆盖范围；
- Gate：只允许标记“工程候选”，不能标记 N21/N23 产品通过。

本轮浏览器结构化记录为 [`evidence/n23/playable-flow-browser.json`](../evidence/n23/playable-flow-browser.json)：项目首页打开的真实示例包含 3 个场景、2 名角色，两条选择路线分别到达“留在电波里的名字”和“晚风知道答案”。

### N23-E2（下一步）

- 从空工程而不是示例工程创建内容；
- Writer/Sequence 能完成选择、变量、条件、演出和两个结局；
- 保存、关闭、重开后，文本、顺序、稳定 ID、Inspector 数据和资源引用不丢失；
- 重开后从入口完成两条路线；
- 导出的权威工程快照有哈希，浏览器操作日志可复现。

### 真人验收（E2 后执行）

- 参与者未参与代码/设计且不了解脚本语法；
- 主持人只能读目标和记录观察，不能操作或教具体控件；
- 20 分钟内完成 T01–T08；
- 记录求助、误操作、阻塞、设备、开始/结束时间和保存重开结果；
- 只有全部任务通过、证据哈希有效且 `RA-N21-002` 同步关闭，才能标记 N21 通过。

## 5. 当前仍缺少什么

- 空工程端到端创作并运行的浏览器 Golden；
- 五分钟内容量与两名独立验收者；
- 正式共享 VM/Player、确定性存档与恢复；
- 游戏 UI 模板、完整舞台/镜头/动画、输入映射；
- 桌面/移动构建、安装、签名、补丁和发布验证。

因此当前软件从“只能看预览”推进到“可以运行一条编辑器内故事流程”，但还不是可交付的完整游戏引擎。下一开发动作必须继续 N23-E2，不得转向平台包装或把本轮工程候选误报为产品完成。
