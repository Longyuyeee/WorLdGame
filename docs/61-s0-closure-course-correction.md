# S0 收口与方向纠偏审计

> 决策日期：2026-08-12
> 决策类型：阶段治理变更，不是 `S0.42` 功能里程碑
> 产品代码冻结基线：`f16f34dc67a72c6888fcb3fa330decde47bc8d86`
> 当前判定：方向正确，执行顺序发生偏移；D1、S0、M1 均未通过。
> 当前仓库能力、缺口、规模与下一开发入口见[《WorLd Studio 当前开发状态快照》](66-current-development-status.md)。

## 1. 纠偏结论

WorLd Studio 的产品定位、现代多彩视觉方向、Windows/Android 完整创作、Web/Windows/Android 发布、专业叙事能力和自动资源优化仍然有效，不缩减 M1 的商业级目标。

需要修复的是开发顺序。S0.1–S0.41 已形成有价值的 Web 技术证据原型，但连续扩展编辑器功能，使 S0 从“验证最高风险假设”偏移成了“提前开发 Web 编辑器”。代码数量、测试数量、界面完整度和文档编号均不能替代阶段退出证据。

因此立即执行以下决定：

1. `f16f34d` 冻结为 **S0.41 Web 技术证据原型**，不称为 M1 Alpha、M1 基础版或产品功能完成；
2. 在 S0 收口门通过前，不创建 `S0.42`，不继续横向增加 Stage、搜索、资源面板或其他编辑器功能；
3. 已有实现按“采用候选、部分证据、待替代”重新审计，只有形成 ADR 并通过目标平台证据后才能进入 M1；
4. 下一阶段只执行本文件登记的剩余高风险 Spike、D1 用户验证和治理收口；
5. Draft PR #1 保持 Draft。产品代码基线不再增长，只允许加入纠偏文档和必要的证据索引；是否拆分、归档或合并由 S0 收口评审决定；
6. S0 通过后仍需产品负责人再次批准，才可以建立 M1 产品分支和正式 Backlog。

## 2. 偏移审计

### 2.1 保持正确的方向

- 同一 Canonical 内容投影为 Route、Sequence、Script 和 Stage；
- Windows 与 Android 都能完整创作，手机端不是只读预览器；
- Web、Windows、Android 玩家共享确定性剧情语义；
- 自动路线图、画廊、回放、音乐室、可调快进、逐句前进/后退属于 M1 P0；
- Lossless Dicing/Delta、逐像素验证、无收益回退和预算驱动优化属于 M1 P0；
- 现代、极简、色彩丰富、动效平滑，同时保持专业密度与表达清晰；
- 无账户、无云构建、本地优先、工程可导出且不锁定。

### 2.2 已发生的执行偏移

| 偏移 | 证据 | 风险 | 纠偏 |
|---|---|---|---|
| S0 被连续功能编号驱动 | 已扩展至 S0.41 | 低风险 Web 功能挤占最高风险验证 | 停止新增 S0.x 功能切片 |
| Web 原型代表性被高估 | 当前主要证据来自浏览器与模拟移动视口 | 无法证明 Android IME、沙箱、后台恢复、低内存和 Windows 壳 | 必须在真实目标平台取证 |
| 语义编辑领先于 Narrative VM | 已有编辑、预览运输和资源状态，但未冻结 VM Step/Effect/Save/Barrier | 回滚、前进、快进和跨平台存档可能后期推翻模型 | 先完成最小确定性 VM Spike |
| 编辑器领先于发布链 | 尚无三平台最小玩家产物和完整构建证据 | 无法证明“可发布”架构成立 | 优先贯通 Web/Windows/Android 最小构建 |
| 技术自测领先于用户证据 | D1 至少 5 名目标创作者验证未完成 | 可能把未经验证的信息架构固化 | 恢复 D1 正式任务测试 |
| 单一 Draft PR 过大 | 原型历史集中在 PR #1 | 难以独立审阅、回退和建立 Claim/Evidence | 冻结 PR；后续一项风险一个 PR |
| UI 集成文件持续膨胀 | `App.tsx` 已成为大型集中式组合层 | 后续平台适配与独立测试成本上升 | M1 准入前给出模块拆分设计，不在收口期做装饰性重构 |

## 5. 修复后的执行路线

### Wave A：治理与目标冻结

1. CL-01 已冻结能力矩阵与预算；登记实体设备并跑基础基线后才转为“通过”；
2. 按[《S0 Claim / Evidence 登记表》](63-s0-claim-evidence-register.md)维护 CL-02–CL-12 的 Claim、Owner、阈值和证据；具体排期在设备可用后冻结；
3. 准备 D1 测试工程、招募和同意材料；
4. PR #1 记录为冻结证据原型，不再接受产品代码。

退出条件：每个剩余风险都有明确假设、通过阈值、失败替代、证据位置和批准人。

### Wave B：平台与发布链

按 CL-02、CL-03、CL-05、CL-06、CL-12 执行。先证明编辑器壳和三端最小玩家能成立，再扩展编辑器能力。

退出条件：Windows/Android 最小编辑壳可保存恢复；Web/Windows/Android 玩家跑同一固定路线；构建产物可追溯；平台选型形成 ADR。

### Wave C：叙事语义与跨平台确定性

执行 CL-04，并让最小 VM 驱动 Wave B 的三个玩家。最低覆盖变量、条件、选择、调用栈、随机种子、Save、Rollback、Forward、Skip、异步取消和不可逆 Barrier。

退出条件：同一输入在三端产生相同剧情 State Hash；回滚/前进和存档迁移没有未解释差异。

### Wave D：规模、渲染与资源

执行 CL-07、CL-08、CL-09、CL-10。Dicing 证据必须进入真实三端资源管线和最低档 Android，而不是只验证算法正确性。

退出条件：Route、渲染、资源和 Soak 均有目标设备数据；失败项已采用明确替代方案。

### Wave E：D1 与 S0 关闭

执行 CL-11，汇总全部 ADR、契约 v0、威胁模型、Golden/CI 计划和证据包，召开 S0 收口评审。

退出条件：D1 与 CL-01–CL-12 全部为“通过、替代或经范围审计批准的取消”，不存在“未开始、进行中、有条件通过”；之后由产品负责人决定是否批准 M1 产品编码。

## 6. 强制工作规则

从本文件生效起：

- **一项风险一个 PR**：PR 标题、测试和文档必须引用一个 CL ID；跨风险变更必须说明不可拆分原因；
- **小批量审阅**：非生成代码目标不超过 800 行变更；超过 1,500 行必须在合并前拆分或取得书面例外；
- **先写证据契约**：编码前写假设、环境、阈值、失败替代和取证命令；
- **只做可抛弃 Spike**：S0 不承诺生产结构，不以美化、抽象升级或功能数量为目标；
- **真实平台优先**：浏览器窄屏不能替代 Android 真机，Node 适配器不能替代 Windows 壳，单端输出不能证明跨平台确定性；
- **失败必须收敛**：失败结果要选择“替代、推迟或取消”，并解释对 M1 P0 和 Stable 门的影响；
- **禁止阶段冒充**：没有通过阶段门，不得使用“已进入 M1”“商业级完成”“生产可用”或“平台已支持”等表述；
- **文档随证据更新**：每个 PR 同时更新本登记表、ADR、命令与原始证据链接，不能只写总结性审计记录；
- **禁止以测试数量代替覆盖**：自动化测试必须映射 Requirement/Claim/Risk；缺少真机、用户或发布产物证据时仍判未通过。

## 7. S0 收口评审清单

评审人必须逐项回答，任何“不知道”都阻断进入 M1：

1. D1 是否由至少 5 名目标创作者完成，而不是内部自测？
2. 目标 Android 和 Windows 设备、预算与原始结果在哪里？
3. Windows/Android 编辑器壳的选型和失败方案是什么？
4. Web/Windows/Android 玩家是否由同一 VM 和工程构建？
5. 回滚、前进、快进、存档和异步 Barrier 的状态哈希是否确定？
6. Android 直接构建的结论是采用还是明确回退到 Windows 本地构建？
7. 10k Route、资源格式、Dicing 和低内存 Soak 是否在目标设备验证？
8. SBOM、Provenance、哈希、签名和 Manifest 是否对应同一 Source Revision？
9. Command、Schema、VM、Store、Asset、Capability、Build 是否都有 v0 契约和 ADR？
10. 是否仍有产品代码躲在“原型”名义下绕过 M1 准入？
