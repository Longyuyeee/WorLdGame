# 容量、性能与运行稳定性优化规格

> 当前 M1 不建设账户、云同步或云构建；涉及云端分发、同步和多租户的条目是未来设计储备，不进入当前实施。

## 1. 产品承诺

容量、速度和稳定性属于产品能力，而不是项目完成后由开发者手工救火：

- 编辑器持续显示资源、构建、内存和运行性能预算；
- 安全优化可自动完成，高风险优化必须预览并经用户确认；
- 源工程与原始素材永不被构建优化覆盖；
- 每次优化都提供优化前后数据、画质/音质差异和回退方式；
- M1 的 Windows、Web、Android 使用各自适合的产物，不强求一个文件格式覆盖所有设备；iOS 在未来接入时沿用同一规则；
- 体积优化不能以增加崩溃、内存峰值或运行卡顿为代价。

## 2. 统一成本模型

“更小”不能只看源 PNG 的大小。Optimization Center 同时计算：

### 2.1 容量

- 源工程容量；
- 构建上传量；
- 商店/网页下载量；
- 安装后占用；
- 首次可玩包与后续章节包；
- 补丁差分量；
- 磁盘缓存和离线内容占用。

### 2.2 运行成本

- 图片/音频解码后的系统内存；
- GPU 纹理内存；
- 瞬时双份内存：解码、上传、切场景和替换资源；
- CPU 解码、脚本执行与布局时间；
- GPU 上传、Draw Call、滤镜和过度绘制；
- 网络请求数、并发、缓存命中和失败重试；
- 电量、发热和后台恢复成本。

### 2.3 稳定性

- 崩溃、OOM、未处理异常和资源泄漏；
- 卡死、无限等待、长帧和输入无响应；
- 下载损坏、版本不匹配和缓存污染；
- 保存损坏、迁移失败和前后台状态丢失；
- 弱网、断网、磁盘不足、权限撤销和音频设备变化。

优化报告必须展示上述影响，禁止只显示一个压缩百分比。

## 3. Optimization Center

### 3.1 工作方式

Optimization Center 是项目级控制台：

1. 扫描工程和目标平台；
2. 建立资源依赖、加载范围和实际使用清单；
3. 运行多个安全候选策略；
4. 预测发布体积、峰值内存、加载时间与质量差异；
5. 给出自动应用、建议确认、不建议三类结果；
6. 构建后使用真实产物和设备遥测校正预测；
7. 保存 Profile，后续构建检测回退。

### 3.2 预设 Profile

| Profile | 优先目标 | 适用场景 |
|---|---|---|
| Quality First | 最高画质/音质，仍去除无意义重复 | PC、展示版、高端设备 |
| Balanced | 画质、容量、内存和速度平衡 | 默认正式发布 |
| Small Download | 首包、下载和补丁最小 | Web、移动流量场景 |
| Low Memory | 降低纹理、预载和特效峰值 | 低内存手机 |
| Custom | 团队自定义硬/软预算 | 专业发行项目 |

每个平台可选择不同 Profile。运行时允许根据设备能力选择已构建好的质量档位，但不能现场进行不可控的有损重编码。

### 3.3 自动化等级

- **Safe Auto**：内容哈希去重、未引用派生产物排除、无损 Dicing、透明边裁切、代码/清单压缩、缓存复用；
- **Review Required**：有损图片/音频、字体裁剪、视频重编码、资源分包、分辨率降低；
- **Never Automatic**：删除源素材、移除可能通过插件动态引用的内容、改变对白/语音同步、修改色彩意图。

任何自动决策都记录原因、输入哈希、工具版本、参数和输出哈希。

## 4. 容量优化流水线

### 4.1 图片与 GPU 纹理

- 内容哈希去重，识别不同文件名的完全相同图片；
- 自动裁切透明边并保留原锚点/九宫格信息；
- 使用 Dicing/Delta 合并 CG、表情、口型、眨眼和序列帧差分；
- 小型 UI/角色资源在净收益为正时打 Atlas，避免巨型全局 Atlas；
- 为目标分辨率生成 1×/1.5×/2× 或自定义变体，避免低端设备加载 4K 纹理；
- 普通 Web 图片比较 PNG/JPEG/WebP/AVIF 的真实质量与解码成本；
- GPU 路径验证 KTX2/Basis Universal，并按平台转码或投递 ASTC、ETC2、BCn 等原生格式；
- 色彩关键 CG、文字 UI、透明边缘和噪点素材使用不同质量规则；
- 已压缩图片不再盲目套通用压缩，避免开销大于收益。

KTX2/Basis、ASTC/ETC2 等属于待 S0 验证的候选能力，不在调研阶段锁定为唯一技术实现。

### 4.2 音频

- Voice、BGM、SFX、Ambient、UI 分别设置编码、码率、声道和预载策略；
- 语音默认评估单声道，BGM/环境声保留需要的立体声；
- 自动检测静音头尾并提供非破坏裁切建议，同时保留对白时间锚点；
- 短音效可成组或常驻，长 BGM/语音采用流式读取；
- M1 为 Web/Android/Windows 选择各自兼容的 Opus/AAC 等变体与回退；iOS 变体留待未来平台接入；
- 波形、响度分析和编辑代理文件只属于派生缓存，不进入玩家包；
- 已经压缩的音频不进行无收益的二次通用压缩。

### 4.3 视频与序列帧

- 输出多分辨率和多码率 Profile，并保留可靠回退格式；
- 海报帧、首帧预热和关键帧间隔纳入首播等待预算；
- 纯透明短动画比较序列帧 Dicing、视频、Spine/Live2D 的实际成本；
- 视频按章节/场景分包，未播放内容不进入首包；
- 移动端验证硬件解码、前后台恢复、音画同步和解码器失败回退。

### 4.4 字体与本地化资源

- 按语言和实际字符集生成字体子集，保留动态文本、用户名和插件字符白名单；
- CJK 常用字、罕见字、Ruby、符号与 Emoji 分层打包；
- 语言专用 CG、语音和视频进入独立 locale/voice pack；
- 不将所有语言语音强制放入同一个首包；
- 字体子集缺字必须在构建时阻断，而不是运行时显示方框。

### 4.5 脚本、UI 与程序包

- 源脚本编译为紧凑、版本化 Runtime IR；
- Release 排除编辑器、源码、未使用主题、调试面板和未启用插件；
- 按使用到的命令、UI 模板和运行时服务进行模块裁剪；
- JS/CSS/JSON/文本清单进行 minify 与 Brotli/gzip 传输压缩；
- 图片、音频、视频等已压缩媒体不重复使用 HTTP 通用压缩；
- Source Map、符号和诊断清单单独安全上传，不进入普通玩家下载；
- 构建报告列出体积最大的资源、重复内容、无引用内容和新增回退。

### 4.6 分包、缓存与补丁

- 核心运行时、公共 UI 和第一章构成 First Playable；
- 章节、路线、语言、语音和高分辨率资源可以独立包；
- 支持 install-time、fast-follow/on-demand 或自托管等平台适配策略；
- 资源以内容哈希命名，长期缓存不会把旧内容误认为新版本；
- 补丁只传输变化对象；安装在临时区完成哈希验证后原子切换；
- 中断支持断点续传，失败保留可运行旧版本；
- 缓存清理按可重下、当前章节、最近使用和用户固定内容分级。

## 5. 加载与运行速度

### 5.1 启动路径

启动只加载：

- Runtime 核心；
- 当前语言最小字体；
- 标题 UI；
- 全局配置与最小清单；
- 继续游戏所需的存档元数据。

画廊缩略图、完整路线图、后续章节和非当前语言不能阻塞首屏。

### 5.2 预测预加载

Story Graph 为资源调度器提供安全预测：

- 当前场景立即资源为最高优先级；
- 下一句与无条件后继后台预载；
- 选择出现前仅预载分支公共资源，或在预算允许时预载高概率分支；
- 章节边界提前下载下一包；
- 预载任务可取消、去重和降低优先级，不抢占输入与语音；
- Debug/QA 可以显示“为何加载此资源”和预测命中率。

### 5.3 解码、上传与渲染

- 图片解析、哈希和可并行工作放到 Worker/后台线程；
- 控制网络、解码和 GPU 上传并发，避免瞬时内存翻倍；
- 场景切换前按预算预热纹理、字体、Shader/滤镜和首段音频；
- 静态画面不做无意义全屏重绘；
- 对象池复用高频对话、粒子和 UI 节点；
- 合理批处理同材质对象，监控 Draw Call、过度绘制和滤镜 Pass；
- 快进时完整执行剧情状态，但可以合并/抑制不会被玩家看到的中间渲染；
- 自动降级阴影、模糊、粒子、分辨率和预载深度，不能降低文本清晰度。

### 5.4 内存生命周期

资源管理器结合 Manifest 依赖、引用计数、LRU 和显式释放：

- 当前场景、回滚窗口和预加载窗口分别计算引用；
- CPU 解码缓存与 GPU 纹理缓存分开计量；
- 离开章节后释放无引用 Atlas、视频解码器、波形和滤镜中间缓冲；
- 支持引擎纹理 GC，但关键切场景点主动释放，不等待不确定的垃圾回收；
- 低内存信号触发紧急清理：取消低优先预载、降低质量档、缩短回滚缓存并保住当前保存点；
- 达到硬预算前阻止继续预载并记录诊断，不以 OOM 作为正常释放机制。

## 6. 编辑器性能

- 10 万行脚本增量解析，修改只影响依赖子图；
- Route Map、Sequence、资源列表和表格全部虚拟化；
- 缩略图、波形、字体预览和代理视频后台生成；
- 手机默认使用编辑代理和局部画布，不加载全分辨率生产素材；
- 搜索、Story QA、Dicing 分析和构建在 Worker/独立进程运行；
- 自动保存写操作日志，整理/压缩日志不能阻塞输入；
- 内容寻址构建缓存支持本机与云端复用；
- 内存压力时先清理可重建缓存，不驱逐未保存内容；
- 性能面板展示主线程长任务、内存、GPU 纹理、缓存和后台任务。

## 7. 稳定性工程

### 7.1 Runtime 状态纪律

- Narrative VM 单线程确定排序，异步工作通过版本化事件返回；
- 场景切换、快进、回滚和前进可取消旧的异步请求；
- 命令重复执行必须幂等，或通过执行 ID 防止重复副作用；
- 插件超时、异常和资源泄漏由隔离边界捕获，核心 Runtime 显示可恢复错误；
- 无限等待、循环、递归深度和资源重试均有上限与诊断。

### 7.2 保存与恢复

- 保存采用写前日志、临时文件、校验和与原子替换；
- 迁移前快照，失败自动保留旧存档；
- 定期检查保存能否重新加载，而不是只检查写入成功；
- 崩溃恢复区与正式存档分离；
- 磁盘不足时停止写入新数据并保护最后一个有效副本；
- 云同步冲突不覆盖唯一可用存档。

### 7.3 下载与缓存

- Manifest 版本、对象大小和内容哈希先校验；
- 下载进入临时区，完整校验后才进入可用索引；
- 重试使用指数退避、抖动、并发限制和取消；
- 弱网时显示已完成量、剩余量、可玩范围和继续/取消；
- CDN、服务器或新包失败时可回退本地旧包；
- 缓存数据库损坏时可从内容对象重建，不影响源工程或存档。

### 7.4 移动端生命周期

- 前台、后台、暂停、恢复、系统杀进程和旋转都有明确状态机；
- 进入后台前快速写入恢复检查点；
- 恢复时重新核验音频、GPU 资源、下载任务和系统权限；
- 电话、耳机、蓝牙和系统音频焦点变化不造成重复播放或永久静音；
- 横竖屏与安全区变化不修改剧情状态；
- 低电量/过热档可降低非关键视觉效果与后台预载。

### 7.5 长时间运行

- Benchmark Episode 循环播放、快速跳转、画廊浏览和存读档至少 2 小时；
- 大型项目执行跨章节、语言切换、语音包切换和多次前后台恢复；
- 记录内存基线、增长趋势、GPU 资源数量、句柄和任务数；
- 稳态内存持续增长、未结束任务和重复音频实例属于发布阻塞问题。

## 8. 性能预算与门禁

以下交互目标继续有效；设备分档、P95/P75 采样、内存软/硬门和 Benchmark Episode 容量预算已在[《CL-01 目标设备矩阵与预算冻结》](62-cl01-target-device-budget.md)冻结。实体设备尚未登记，因此这些数值是生效的证据契约，不是已通过的性能结果。

| 指标 | 生效目标摘要 |
|---|---|
| 编辑输入可见反馈 | P95 < 100 ms |
| Script/Sequence/Stage 热更新 | P95 < 500 ms |
| 10 万字全局搜索 | P95 < 300 ms |
| 目标档运行帧率 | WIN-L/AND-R 60 FPS；AND-L 简化档 P95 ≤ 33.3 ms，直接操控优先 60 FPS |
| 普通对白推进主线程长任务 | 不出现 > 50 ms 的非必要任务 |
| 已预载场景切换 | P95 < 300 ms |
| 冷资源场景切换 | P95 < 2 s，并显示可解释进度 |
| Crash-free sessions | Stable ≥ 99.8% |
| 2 小时 Soak | 0 崩溃、0 OOM、无持续内存增长 |
| 无损资源优化 | 重建结果逐像素/逐样本等价 |
| 构建可复现 | 相同输入与工具链生成相同 Manifest/对象哈希 |

每个项目还必须定义：目标设备、首包预算、完整下载预算、安装预算、软/硬内存预算和可接受画质阈值。没有目标设备和预算时，Optimization Center 只能给建议，不能声称“已优化完成”。

## 9. 自动回退规则

- 压缩后体积更大：回退；
- 下载更小但峰值内存越过硬预算：回退或拆组；
- 解码/转码导致场景切换超预算：换格式或预转码；
- 画质/音质超过项目阈值：提高质量或使用原始变体；
- 设备不支持目标纹理/编解码器：选择已构建回退变体；
- 新版本崩溃、OOM 或存档不兼容：停止发布并保留上一稳定产物；
- 自动策略无法确定动态引用：保留资源并报告，不擅自删除。

## 10. Golden Projects 与测试场景

新增：

- **Size**：重复 CG、多语言语音、字体、视频、未引用派生资源和章节包；
- **LowMemory**：低内存预算、大 CG、回滚窗口、画廊与连续切场景；
- **Delivery**：弱网、断网、断点续传、损坏对象、旧包回退和磁盘不足；
- **Soak**：2 小时自动游玩、快进、回滚、前进、语言切换和前后台恢复；
- **Capability**：不同纹理、音视频和渲染能力的设备回退矩阵。

正式发布前必须输出一份可归档的 Performance & Stability Report，包含预算、设备、产物哈希、体积构成、帧时间、内存曲线、加载数据、崩溃/OOM 和回退验证结果。
