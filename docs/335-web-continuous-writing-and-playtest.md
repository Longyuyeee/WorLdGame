# Web 连续写作、试玩回改与保存接续 · 2026-10-15

接续 `6c16eb9`（[#334](334-web-story-refinement-and-leave-protection.md)），按 [#304](304-web-complete-gal-delivery.md) 的顺序推进连续制作体验。先核对当前 1.6.0 九场景工程、写作输入、源命令、试玩接续及保存实现，再用真实工程操作。**本批交付编辑器连续文字编辑，不扩平台、不重发剧情版本，也不以多写验收材料代替产品修改。**

## 用户实际遇到的问题与修改

1. 原先对白停止输入或失焦后会应用，旁白却必须点击“应用修改”；旁白草稿会锁住后续步骤，页面说明却声称文字都能自动应用。现在两者共用同一文字编辑器，停止输入 350 ms 或失焦后应用，也保留立即应用入口。旁白换行及首尾空格原样保留，不在应用时悄悄 trim。
2. 校读长场景时，原先每改一段就要重新寻找下一张文字卡。现在可点击“上一段文字／下一段文字”，或使用 Alt+PageUp／PageDown；先提交当前输入，再定位并聚焦下一段。文字间的演出 Cue 不被修改或删除，浏览顺序仅限当前场景，不推断剧情分支，不替用户切换下一场景或新增内容。
3. 中文组合输入中不提交半成品、不响应上述段落切换、保存或 Esc；空白正文和当前语言不支持的直接多行对白保留在原输入框，给出中文修正说明。错误不能借段落导航静默丢弃，可补写或用 Esc 撤回尚未应用的输入。组合输入是组件事件测试，不声称已覆盖物理手机输入法。
4. 较早一批输入的确认返回时，原输入组件会把较新的本地文字覆盖。本批保留新缓冲，只清除确已确认的脏状态；重复失焦/快捷应用不产生同一批的重复命令或撤销历史。
5. 80 段长场景检查发现：从第 64 步跨过卡片窗口，输入框先聚焦到临时 Inspector，再被窗口重建卸载，导致焦点落回页面。已改为等待目标进入最终窗口后再聚焦；前进及退回、末尾改稿均有回归。

输入按稳定语句 ID 管理，自动应用不重新挂载文本框、不中断光标；仍通过原源命令修改权威脚本，撤销/重做、预览、保存和导出读同一正文。“已应用到工程”与“保存到本机”明确区分，本批没有添加关闭后自动恢复尚未应用输入的承诺，#334 的离开提醒继续生效。
