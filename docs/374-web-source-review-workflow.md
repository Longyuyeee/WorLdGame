# 374 发布前素材问题处理与连续核对

2026-10-17，接续 [#373](373-web-history-result-transport.md)，按 [#304 Web 完整 Gal 制作与交付](304-web-complete-gal-delivery.md) 推进。作者现在可以从发布页的具体素材问题进入核对，在不丢失其他填写内容的情况下修复错误、连续应用、保存重开，并导出保留内部资料的制作包。原《雨停之前》1.7.14 的剧情、素材和发行条件不改。

## 主线审计与本批取舍

#370–#373 处理了长篇推进、主线程响应及结果回传，但完整输入复制、后台恢复、公开校验和接收端重建仍有成本。它们继续开放，不把下一批固定为增加传输协议，也不以重复微基准代替成品交付。

实际发布代码已有来源搜索、待处理过滤、替换后重核和内部资料隔离；本批没有重复建设这些功能。发现的缺口是：发布页只提供总数，不能按问题进入；某一项确认资料不完整会阻止整本台账应用，却不指出具体素材；应用后必须关闭窗口，批量核对反复进出；窄屏列表挤占详情，获得焦点的字段也不一定可见。这批优先完成这段作者任务，不扩大原生、装饰模板或 Runtime 范围。

## 作者处理流程

1. 在作品信息、生成游戏或试玩部署页展开“按问题处理素材”，按未填写、文件更换、待确认、需替换、缺公开署名和已记录依据分类进入。每类给出数量与处理方向，直接选中该类首项；零项和外围未应用草稿期间不能误跳转。
2. 来源窗口保留搜索与只看待处理，增加事项分类。当前详情因筛选或编辑不再属于列表时明确提示，不自动丢弃草稿或偷偷改选；“已记录依据”与“只看待处理”不叠成矛盾筛选。
3. “下一项待处理”在全部素材间前进并跳过已记录项，保留尚未应用的填写；“应用并核对下一项”先完整验证整本台账，再应用并留在窗口。两者不把待确认素材标记为已确认，也不以浏览过某项作为完成依据。
4. 应用失败时显示素材名、缺失字段与未通过项数，清除遮挡筛选，切到出错素材详情，聚焦并滚动到实际字段。其余素材填写不丢失，不部分应用。尚无依据时可明确“保留填写，改为待确认”，不代填确认人或日期。
5. 手机窄屏在“选择其他素材”和当前详情之间切换；选中、继续核对或错误定位会返回详情。错误字段必须在滚动正文区域内完整可见，底部应用按钮至少 44px。桌面和宽横屏仍是双栏。

素材更换仍使用原素材页与“返回生成游戏”，新文件不沿用旧摘要确认；公开署名仍需明确单条加入致谢。损坏的导入台账仍先保留原文，只能明确重建，不因进入分类就覆盖。

## 应用保存与数据边界

“应用并核对下一项”更新工程和本窗口的已应用基准，不等于已经写入本机。提示要求关闭后保存或导出源工程；窗口打开期间继续锁住保存和跨页入口，避免把尚未应用的填写误当已保存。之后的“放弃修改”只丢弃本次应用后的新增草稿，先前已应用的内容保留。应用回调失败则不重置草稿、不解锁替换；重建台账后连续应用也不会重新锁回损坏状态。

最终应用仍经过原领域解析器，日期、字段长度和确认资料要求不放宽。没有新工程字段、台账版本、存档格式或 Runtime 协议。内部来源依据只保留在源工程与制作包的内部发布清单，玩家游戏继续剥离；来源填写不改变玩家构建身份与旧存档兼容。真正加入公开致谢则仍属于公开内容变化。

## 接续顺序

1. 继续原完整作品的具体剧情、演出与连续校订问题，把问题定位、实际复测和同版交付串起来；不要自动批准十一条人工记录。需要内容判断时以实际上下文为依据，不为了关闭清单改写故事。
2. 围绕公开交付继续检查作者是否能明确区分游戏、内部制作包与网站上传目录，以及同版保存、恢复和更新提示。优先修真实流程问题，不扩成自动授权或虚构部署验收。
3. 长篇输入复制与总等待成本保留在 #373，后续优化必须有对应玩家痛点及同条件测量，保留全量校验、全部历史与旧档。Auto／Skip 异步扩展需另审时钟、媒体和停止边界。
4. 25 项发行条件、物理主流手机／Safari、长期稳定性、获准的实际公网部署与离线升级整链仍待完成；Windows／Android 原生继续搁置，不宣布 Stable 或整体 M1 完成。
