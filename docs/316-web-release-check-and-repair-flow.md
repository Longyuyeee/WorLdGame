## 本批交付

- 发布第三步改为“检查当前作品并生成游戏”。自动运行正式 release 编译、发布信息/图标和外观校验，并读取全部源素材核对登记信息、字节大小和 SHA256；有进度、重新检查和明确的阻断状态。不增加人工审批或平台选择。
- 多个故事/文件问题集中显示中文名称、场景名和步骤位置；详细原始诊断收起。阻断问题每页 6 项，警告另行收起且不阻止合法导出；不允许 QA 抑制记录隐藏实际导出错误。
- 故事问题直接定位稳定语句 ID；文件问题直接打开对应素材的替换界面并锁住原 Asset ID。修复、查看路线或试玩后可“返回生成游戏”，保留 HTML/目录 ZIP 选择并重新检查。作品信息问题回到发布第一步。
- HTML 和目录导出共用这套源校验。生成时重新读取源文件，检查后又丢失/损坏的文件不会被缓存掩盖；失败转为同一可操作问题清单。切换格式清除旧下载；发布信息有未应用修改时，下载与打开试玩均隐藏。
- 展示最近一次本会话试玩，区分无记录、当前局部试玩、当前入口到结局、过期记录；不累计成全分支覆盖。真实浏览器发现兼容声明使试玩被误标过期，已统一路线评审/生成页与 Compiler 的摘要口径，仅剔除非执行的旧档兼容声明，正文/版本等变化仍使记录过期。
- 使用现有图标与主题颜色，问题/通过状态更清楚。实图复查后压缩作品卡、统计与操作留白，适配 1440/1180/800/390px；没有另做设计稿。

## 失败与修正记录

- 首轮两个单元测试失败来自测试数据：纯数字 Asset ID 另外触发正式资产诊断，手工追加场景未更新路径。修正为合法 fixture 后通过。
- 新 UI 测试把 Playwright 的 `exact` 参数用于 Testing Library，类型/构建失败；去掉后通过。
- 两次生产浏览器等待局部试玩状态超时，发现了真实的兼容声明摘要口径问题；修复并加正式 Compiler 对照回归。
- 浏览器工具曾错误要求重导 HTML 字节相同。UI 应用设置后的对象与从 ZIP 载入的对象存在 JSON 键顺序差异；项目语义/完整 payload、原播放器和源媒体均保持。改为对应语义及文件摘要校验，**不宣称整个重导包字节相同**。
- 故障 fixture 首次用压缩 ZIP，但现有导入器只接受 stored ZIP；改为工具生成 stored fixture。既有压缩 ZIP 导入限制没有在本批改写。
- 工具曾在“放弃修改”后的 effect 完成前断言链接恢复，及点击产品隐藏的旧 `Script` tab；改为等待真实链接、使用实际“故事工作区 → 脚本”。这些是工具错误，不记为作品运行失败。
- 第一份 5 组通过后，根据实图压缩生成页留白，重新构建和复跑浏览器；前一报告保留 `before-spacing-refinement.json`，不累计。

## 当前产物与边界

本批交付编辑器和共享的正式导出校验，Player/作品正文/演出/原媒体不变，不增加发行版本。当前可交付源工程、HTML、目录仍是 `evidence/web-save-backup` 的 **1.5.4**，既有文件未改写。浏览器本轮的重复导出保存在系统临时目录，报告记录大小/SHA256，仅用于核对，不替换已交付包。

自动检查不证明所有条件路线可走通、阅读节奏或配音听感适合，也不确认授权或网站已上传。本轮未重跑完整两结局（沿 #313）、全部 Player/Editor/全仓、其他引擎、真机/旋转/后台、长期运行/旧长帧、人工定稿、许可和公网；没有恢复原生开发。后续继续实际写作/分支演出与作品定稿流程，不要求先选择发布平台。

复现：Editor 生产页面启动后，`npm run audit:web-release-readiness:browser`；可用 `STUDIO_UI_URL` 和 `STUDIO_CHROME` 指定地址/Chromium。故障注入只操作工具创建的隔离浏览器上下文，不使用用户浏览器资料。
