# S0.38 范围选择、整轨筛选与大场景性能审计

## 阶段目标

S0.38 提升演出轨道在长场景中的选择效率，但不增加任何新的写入权限。桌面作者可通过 Shift 范围选择快速建立同类 Cue 批次；手机与触屏作者通过“填充首尾范围”和 BG/CHAR/AUDIO 整轨按钮获得明确的等价入口。所有操作只更新 Writer 的临时选择，不直接修改 `.world`、revision 或持久化 schema。

批量删除、跨场景选择、隐藏式自动提交和超过 256 条后的静默截断继续关闭。

## 冻结选择语义

### 范围锚点

- 进入多选时，当前 Direction Cue 同时成为首个选择和范围锚点。
- 普通点击一个 Direction Cue 会切换它的选中状态，并把它设为新的范围锚点。
- Shift+点击或 Shift+Space/Enter 以当前锚点和目标为首尾，按场景源顺序计算闭区间。
- 首尾必须使用同一种 Directive 命令；区间内只收集与锚点同命令的 Cue，因此结果天然满足批量参数同类约束。
- 成功范围选择替换当前选择；失败时保留原选择和锚点。

### 触屏等价入口

- 作者可先普通点选同类首尾，再按“填充首尾范围”；系统用场景顺序中的首项与末项执行同一纯函数。
- BG、CHAR、AUDIO 按钮会用该轨道的全部 Direction Cue 替换当前选择。
- 选择空轨道得到空选择并明确提示，不创建 revision。
- “选择本场景同类”继续保留，适用于已经有单个类型锚点的快速选择。

### 上限与可见性

- 范围和整轨选择均受 256 条上限约束；超过上限时整次拒绝，结果中不返回或应用部分 ID。
- 选择基于完整场景投影，而不是当前横向滚动视口；滚动区外但属于范围或轨道的 Cue 仍会入选。
- 当前阶段没有折叠或过滤隐藏状态，因此不存在“隐藏后是否保留”的歧义；未来增加过滤器前需重新冻结该规则。

## 快捷键安全

- 多选中 Direction Cue 暴露 `aria-keyshortcuts="Shift+Space"`。
- 多选中 `Delete`、`Alt+ArrowLeft` 和 `Alt+ArrowRight` 被显式拦截，不会绕过工具栏禁用状态执行删除或移动。
- 范围和轨道选择反馈通过 `role=status` 与 `aria-live=polite` 宣告。
- 手机布局中三条轨道按钮均保持至少 44 px 高；范围、清空和同类选择按钮使用可换行网格。

## 纯函数与失败语义

`stage-selection.ts` 提供两个无副作用入口：

- `selectStageDirectionRange`：验证锚点、目标、命令类型和数量上限，返回按场景顺序排列的同类 ID。
- `selectStageDirectionLane`：收集完整命令轨道并在返回前验证数量上限。

失败代码区分目标失效、混合命令和超限；失败结果不包含部分选择。这两个函数与 React 状态分离，可独立做边界、属性和性能测试。

## 审计结论

1. Shift 范围、触屏填充和整轨选择共用确定性纯函数，没有三套不同选择算法。
2. 选择只操作投影中的稳定 ID，不触发 source command、自动保存或 Undo 历史。
3. 多选模式的键盘结构操作已在 Cue 入口处锁定，不再只依赖工具栏按钮禁用。
4. 反向范围、跨越其他轨道、失效锚点、混合首尾、空轨道和超限均有明确测试或拒绝语义。
5. 大场景选择计算远低于预算，当前下一风险已转向 10,000 Cue 的 DOM 渲染与可视区域管理。

## 验证证据

- `npm run check`：46 个测试文件、306 项测试、TypeScript、生产构建、34 个可移植文件 / 3 个 Node adapter 架构边界，以及脚本和资源性能门全部通过。
- 10,000 条 Cue 的整轨选择加同类范围选择共 2.24 ms，冻结预算 100 ms；结果各为 3,334 条，证明按完整场景顺序计算。
- 256 条 Directive 预检 4.71 ms / 500 ms，原子 Patch 328.48 ms / 2,000 ms，未因选择层引入写入性能回归。
- 真实 Chromium 验证：复制得到 3 条背景 Cue 后，普通点击建立锚点、Shift+Space 选中 `#1、#2、#3`；Delete 没有删除且 revision 保持 r5；“填充首尾范围”成功；选择 AUDIO 空轨道后选择归零且 revision 仍为 r5。
- Preview 回归保持 `landscape-16-9`、1920×1080 与 16:9 Balanced。

## 下一阶段入口

S0.39 应审计并实现大场景轨道的窗口化渲染/可视区域管理，重点冻结焦点在卸载前后的恢复、屏幕阅读器可达范围、滚动定位、拖放目标占位和选择状态不依赖 DOM 存活。没有这些契约前，不直接引入第三方虚拟列表。
