# 视觉体验与商业制作基准

## 1. 已确认的产品硬要求

以下要求由产品负责人确认，属于产品定位，不是后期美化项：

1. 编辑器界面必须现代化、图形化、多彩，并具有高质量强动效；
2. 编辑过程必须比传统脚本工具更直观、便捷，同时保留高速文本与批量生产路径；
3. 专业能力至少对齐 Naninovel 的脚本/可视化双轨和 Utage 的表格化生产、本地化、资源校验能力；
4. 编辑器生成的不是“能运行的 Demo”，而是能达到商业发行标准的完整 Galgame；
5. 最终作品的演出、音画、界面、稳定性和多平台一致性，需要以市场头部视觉小说为基准持续验收。

“现代、多彩、强动效”与“专业、精确、高密度”必须同时成立。界面不能退化成炫技概念稿，也不能为了专业性停留在灰色表格和传统 IDE。

## 2. 编辑器视觉方向

### 2.1 视觉关键词

- **Cinematic Workspace**：工作区像导演台，而不是办公表单；
- **Color with Meaning**：颜色代表语义、状态和层级，而不是随机装饰；
- **Depth without Noise**：通过层级、光影、材质和空间过渡建立深度，但不牺牲信息密度；
- **Professional Density**：桌面端允许高信息密度，关键数据不隐藏在多层弹窗后；
- **Touch-first Precision**：触屏交互大而清楚，精确数值、吸附和对齐仍然可用；
- **Content is the Hero**：角色、场景、文本和实际预览始终比编辑器装饰更醒目。

### 2.2 色彩系统

默认主题采用低饱和深色中性底，配合高纯度语义色、渐变和局部辉光；后续提供同等级浅色主题。颜色通过 Token 管理，并允许团队主题化。

| 语义 | 建议色相 | 使用位置 |
|---|---|---|
| 对白与文本 | 靛紫 | 对白块、文本定位、当前语句 |
| 角色与表情 | 品红 | 角色轨道、立绘、表情状态 |
| 画面与摄像机 | 青色 | 背景、镜头、构图、视觉效果 |
| 音频 | 橙色 | BGM、Voice、SFX、Ambient、波形 |
| 选择与可达路线 | 绿色 | 选项、有效连接、覆盖路径 |
| 变量与逻辑 | 蓝色/黄色 | 条件、变量、函数、状态变化 |
| 错误与阻塞 | 红色 | 诊断、断链、构建失败 |
| 警告与待确认 | 琥珀色 | 溢出、性能预算、缺少审批 |

规则：

- 同一语义在 Route、Sequence、Script、Stage、Debugger 中保持同色；
- 颜色不是唯一状态表达，必须同时有图标、文字、线型或形状；
- 中央内容区避免同时出现超过 5 个高饱和主色；
- 错误色只用于问题，不被品牌装饰占用；
- 支持色弱友好调色板和用户自定义强调色。

### 2.3 材质、排版与图形

- 使用清晰的层级表面、细边框、柔和阴影和有限的半透明；不以大面积毛玻璃降低可读性；
- 节点、轨道和卡片拥有可识别轮廓，不依赖悬停才能看懂；
- 项目树使用缩略图、角色头像、资源状态和场景色签提升扫描效率；
- 正文、脚本、数值、状态分别使用适合的字体样式；中日韩字体回退必须经过真实文本验证；
- 画布网格、吸附线、关键帧、波形和曲线是第一类视觉元素；
- 图标遵循统一笔画和视觉尺寸，重要操作同时保留文本标签。

## 3. 强动效系统

强动效不是“所有元素一直在动”，而是让操作关系、空间变化和运行状态更清楚。

### 3.1 动效目的

每个动效至少服务一个目的：

- **空间连续性**：从 Route 进入场景，画布聚焦并过渡到对应 Sequence；
- **因果反馈**：连接节点后，目标与影响路径短暂点亮；
- **运行同步**：预览执行时，当前语句、轨道、舞台对象同步脉冲；
- **层级变化**：Inspector、底部 Sheet 和嵌套分支通过连续形变展示来源；
- **直接操控**：拖动、吸附、对齐、缩放和关键帧修改有实时物理反馈；
- **状态变化**：保存、同步、构建和诊断使用可追踪的阶段动画；
- **叙事理解**：路线覆盖、变量传播和结局可达性以动态路径解释。

装饰性循环动效只能出现在空状态、欢迎页和品牌展示，不能持续干扰写作或占用大量 GPU。

### 3.2 时长与响应预算

| 类型 | 建议时长 | 原则 |
|---|---:|---|
| 按钮、选中、悬停 | 80–160 ms | 立即响应，不等待动画结束 |
| 卡片插入、折叠、排序 | 140–220 ms | 保持对象连续性 |
| 面板、Drawer、Sheet | 180–280 ms | 进入快、退出更快 |
| 视图/模式切换 | 240–400 ms | 展示空间关系，可被输入打断 |
| 路线追踪与构建阶段 | 300–700 ms | 允许分段展示，但不阻塞操作 |

- 目标为 60 FPS；高刷新率设备允许以原生刷新率呈现；
- 动画不能阻止保存、输入、撤销或切换上下文；
- 连续拖动优先保证帧稳定，必要时降低阴影、模糊和非关键特效；
- 提供“完整、简化、减少动效”三级设置；系统减少动态效果设置必须被尊重；
- 眩晕风险较高的缩放、视差、闪烁和大范围移动默认克制使用。

### 3.3 标志性交互

- Route 连线像能量路径一样流向目标，完成后收敛为清晰静态线；
- 当前运行语句在 Sequence、Script 和 Stage 上同步定位，而非各自跳变；
- 拖动角色时，Stage 显示磁吸线，Sequence 对应演出块实时更新；
- 调整关键帧时，运动轨迹、缓动曲线和实际预览同时反馈；
- 打开 Inspector 时，从选中对象位置建立短暂视觉关联；
- 构建中心以“校验—编译—优化—签名—打包”展示真实进度和可展开日志；
- Story QA 选择问题后，以动画追踪变量来源和受影响路线。

## 4. 方便编辑的七种工作模式

所有模式读取和写入同一套 AST/IR。模式是工作区布局与操作策略，不是不同工程格式。

| 模式 | 首要用户 | 主要能力 |
|---|---|---|
| Writer 写作模式 | 编剧、独立作者 | 沉浸式文本、键盘优先、连续录入、对白与旁白批量编辑 |
| Director 导演模式 | 演出、美术 | Sequence + Stage + 多轨时间线、关键帧、摄像机、音画同步 |
| Flow 路线模式 | 叙事设计、策划 | 章节/场景 Route Map、条件、变量传播、结局与覆盖路径 |
| Production 生产模式 | 制作人、翻译、配音 | Utage 式表格批量处理、状态列、资源映射、本地化与审阅 |
| Debug & QA 模式 | 程序、测试、策划 | 运行时状态、断点、变量、路线求解、错误与覆盖报告 |
| Mobile Focus 移动模式 | 手机/平板创作者 | 单任务页面、底部 Sheet、大触控目标、列表式分支替代方案 |
| Quick Start 快速模式 | 新手 | 模板、语义化表单、常用演出预设、渐进披露高级参数 |

此外提供 Beginner 与 Pro 两套默认布局：Beginner 减少可见参数，Pro 展示轨道、ID、诊断、资源状态和批量命令；两者之间可随时切换，不迁移数据。

### 4.1 Naninovel 级专业基线

- 脚本与可视化编辑同一内容；
- 全局 Route 与场景内 Sequence 两级结构；
- 当前运行语句同步、高速搜索、撤销/重做、脏状态和安全保存；
- 重命名时语义更新引用，而不是简单文本替换；
- 运行时服务化和插件扩展；
- 完整的视觉小说运行系统，而非只提供对话中间件。

### 4.2 Utage 级专业基线

- 类电子表格的批量录入、粘贴、过滤、状态列和导入导出；
- 对白 ID、语言列、语音列、角色列和资源列可统一管理；
- 日文禁则、Ruby、Emoji、文本溢出和字符集验证；
- 资源配置、命名校验、缺失检测、章节/下载内容和日志；
- Utage Dicing 级差分图切块、重复/透明块消除和图集重建，并增加自动收益与质量验证；
- 批量本地化、配音交付和多角色团队生产；
- UI、命令和运行时可被专业团队深度定制。

## 5. 商业 Galgame 的演出能力基线

市场头部作品不是单靠高分辨率立绘实现质量，而是依靠镜头、分层素材、动画、声音、文字节奏和界面共同构成演出。官方资料显示，《月姬 -A piece of blue glass moon-》明确将进化后的画面、动画和音乐作为重制表现重点；《魔法使之夜》重制版则提供全语音与 Full HD 画面。这些作品用于定义质量维度，不作为美术风格或内容的复制对象。

### 5.1 Scene Director

生产版必须拥有面向导演的多轨时间线：

- 背景、前景、角色、特效、遮罩、字幕和 UI 轨道；
- 摄像机位置、缩放、旋转、震动、景深模拟和镜头切换；
- 角色位置、分层表情、服装、口型、眨眼与动画状态；
- BGM、Voice、SFX、Ambient、UI 五类音频轨道和波形；
- 关键帧、缓动曲线、事件标记、节拍标记和可复用镜头预设；
- 淡入淡出、遮罩转场、粒子、滤镜、颜色分级和屏幕特效；
- 视频、序列帧以及许可隔离的 Live2D/Spine 插件；
- 从任意时刻实时预览，并能回到产生画面的源语句。

### 5.2 玩家产品完整性

每个正式玩家包必须可配置并完整提供：

- 标题、继续、章节选择、存档、读档、历史、设置、帮助、退出；
- 自动播放、可调速 Skip Read/Skip All/Hold/Toggle、逐句后退/前进、快速保存/读取、文本速度；
- CG 鉴赏、场景回想、音乐室、结局与解锁条件；
- 从故事与资源自动生成创作者路线图、玩家流程图、画廊和附加页面；
- 多语言、语言内字体与排版配置、字幕和语音策略；
- 鼠标、键盘、触摸和基础手柄输入；
- 分通道音量、语音自动压低 BGM、淡入淡出和语音续播策略；
- 横竖屏/窗口/全屏/安全区/异形屏适配；
- 崩溃恢复、存档迁移、补丁和版本兼容提示。

### 5.3 排版与音频

- 中文、日文、英文均使用真实长文本测试，不以 Lorem Ipsum 验证；
- 支持 CJK 禁则、标点挤压策略、Ruby/注音、可配置行距和字距；
- UI 文本、正文、角色名、旁白和强调文字有独立样式；
- 音频生产基线为 48 kHz 工作流，发布时按平台 Profile 转码；
- Voice、BGM、SFX、Ambient、UI 分总线混音，支持 ducking、crossfade 和响度检查；
- 语音文件以稳定对白 ID 映射，脚本改行不造成整批错位。

## 6. 商业生产级验收样片

“功能完成”不等于“可生产”。M1 是首个正式 Stable 版本；验收前必须使用 WorLd Studio 制作一个 20–30 分钟的原创校园短篇 Benchmark Episode，并生成通过正式发布门禁的 Windows、Web、Android 分发包。故事结构保持简单、素材规模受控，但必须完整验证工具能力。

### 6.1 内容要求

本节是 D1 的候选内容基线。具体角色、路线、结局、语言、配音和素材数量将在 D1 根据分镜与预算冻结，目前不视为已经确认的制作订单。

- 至少 3 个视觉风格不同的场景；
- 题材为原创校园短篇，建议围绕一次放学后的事件展开，避免宏大世界观和高素材成本；
- 至少 2 条有效路线、3 个结局和一个状态型回收分支；
- 至少 1 段 60–90 秒的高密度电影化演出；
- 角色分层表情、镜头、粒子/滤镜、视频或序列帧至少各有一次真实使用；
- 完整 BGM、Voice、SFX、Ambient 与 UI 音效混音；
- 完整标题、设置、历史、存读档、回想、鉴赏与结局界面；
- 简体中文、日文或英文中的任意两种完整本地化；
- 使用手机与桌面共同完成至少一次真实修改闭环。

### 6.2 技术门槛

- 目标设备以 60 FPS 呈现，P95 帧时间、卡顿和资源峰值符合平台预算；
- 关键输入不能等待动效结束，连续输入无丢字；
- Web、Windows、Android 固定路线的变量、存档、回滚和解锁状态一致；
- 断网时可完成本地编辑、预览和 Web 导出；
- 崩溃、断电和迁移演练后不丢失已确认保存内容；
- 发布包不存在阻塞级崩溃、断档、死路、缺失资源和本地化溢出；
- Stage 预览与最终包通过视觉回归，关键画面不能产生肉眼可见结构偏差。

### 6.3 体验门槛

- 由编剧、演出、美术、翻译、QA 和目标玩家分别评审；
- 与选定的 3–5 部商业参照作品按同一维度评分，而非比较题材和美术预算；
- 重点比较镜头清晰度、节奏、文本可读性、声音层次、UI 完整性、输入反馈和稳定性；
- 不允许用“素材不足”掩盖工具不能表达或预览的问题；
- 任何需要编辑项目文件或外部写代码才能完成的常见 Gal 演出，必须记录为产品能力缺口。

## 7. 设计阶段交付物

在软件编码前，D1 必须先交付：

1. 编辑器视觉方向板与设计 Token；
2. 桌面、平板、手机三套关键工作区高保真原型；
3. 七种模式的信息架构与切换规则；
4. Route 连线、视图切换、Stage 操控、实时预览、QA 路径、构建过程六组动效原型；
5. 完整动效与减少动效两套可测试方案；
6. Benchmark Episode 的分镜、素材清单和验收评分表；
7. 至少 5 名目标创作者的任务测试和至少 5 名目标玩家的成品观感测试计划。

D1 未完成视觉方向、工作模式、Benchmark Episode 规格和用户验证前，不进入 S0；D1/S0 均未通过且产品负责人未明确授权时，不进入产品编码。

## 8. 参考基准的使用边界

- Naninovel、Utage 等工具用于比较生产流程和专业能力；
- 商业视觉小说用于比较最终成品的体验维度；
- 只学习能力、流程和质量标准，不复制受版权保护的 UI、美术、剧本、素材和品牌特征；
- 参照池需要覆盖电影化演出、传统长篇、本地化、多端发布和独立团队作品，避免被单一风格绑架；
- 每个版本复评参照池，具体作品不是永久绑定的需求。
