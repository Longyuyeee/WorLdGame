## 作者如何调整

进入“游戏外观 → 标题画面”或“阅读与选项”，展开“自由组件与响应式布局”，启用本页布局。未启用的页面继续使用原模板；开启与关闭不改写剧情，也不会删除素材。

标题分为“作品信息”和“开始与作品操作”两组；阅读分为“对白与姓名头像”和“阅读常用操作”两组。对白中的姓名／头像随窗体移动，仍按实际说话角色显示；尚未拆成独立浮动层。开始、读取、菜单等原有入口保留，不能通过新组件删掉。

选择组件后，可设置九个锚点、水平／垂直偏移、宽度与高度。偏移以安全区尺寸为基准，正值向右／下、负值向左／上。偏移 **-50～50**、宽度 **12～100**、高度 **8～90**，均为整数百分比；安全间距为 **12～40px**，另尊重设备安全区。操作按钮至少有 88×44px 区域，主组件也有最低可读尺寸，因此窄屏下的实际尺寸不一定等于填写的百分比。

每页最多六个自定义组件：

- 文字：最多 200 字的静态装饰文字，不替代剧情正文。
- 图片：从已检查图片中选择，可完整显示或填满；没有文件或加载失败时显示图片说明，不阻塞剧情。图片和装饰文字位于正文下方，不拦截点击。
- 功能按钮：最多 48 字。标题支持开始、读取、设置、制作名单和附加内容；阅读支持菜单、保存、读取、历史、设置和欣赏画面。只绑定已有正式 Player 操作，不接受脚本、任意 URL、CSS 或 JavaScript。

可调整组件顺序、删除、撤销／重做；“恢复本页默认布局”只关闭并清空本页布局，可撤销恢复。配置先进入外观草稿，应用后写入工程，再保存到本机。非法参数阻止应用和真实预览，并给出自由布局的具体范围说明。

## 手机与冲突保护

桌面和手机可分别配置。手机未单独设置主组件时，采用正文和操作入口优先的安全布局，不直接缩小桌面坐标；自定义组件默认按比例继承桌面锚点，也可为每个组件另设手机位置。窄屏或矮屏使用手机配置，含横屏手机。真实预览仍可切换桌面／手机和放大查看。

越界组件会收回舞台安全区。主组件相互重叠时使用安全布局；自定义按钮与主组件或已放置按钮冲突时，移入本页操作区，不能盖住正文或原有入口。操作区和对白允许滚动，按钮不靠裁掉文字强行挤进窄屏。安全区不足 240×220px 时回到原模板，不硬塞自由布局。

编辑器预览显示布局保护提示，正式游戏不增加调试条。分支选择、结局、其他面板仍使用原布局，新增阅读控件只在对白／旁白时显示，不覆盖选项。高对比模式隐藏装饰图片、保留可读文字；减少动效设置优先；欣赏画面时新增控件也隐藏。

设置、存读档、历史、菜单和附加内容沿用原流程及能力限制。没有存档存储时，相关新按钮禁用；回想隔离、恢复确认、忙碌状态和悬挂保护不绕过。关闭面板尽量返回触发按钮，按钮因旋转／布局回退而不再存在时使用原入口兜底。键盘和触屏均走已有输入策略。

## 契约与审查

新增可选 `WebPlayerSkin.layout`，严格限制页面、组件种类、动作、数量、ID、尺寸与字段；旧皮肤无需补字段，含新字段的配置需当前版本读取。配置、皮肤包和预览共用 `webPlayerSkinImageReferences`／`remapWebPlayerSkinReferences`，组件图片也参与对应、缺图回退和实际字节携带。既有图片 8 MB／400 万像素、字体 32 MB、整批 24 项／64 MB 限制不变，来源与许可仍需按原流程复核。

`player-layout.ts` 只计算安全区内几何位置，不解释剧情。`PlayerLayout` 负责显示和尺寸变化；功能按钮调用 PlayerShell 既有操作。Compiler、Runtime、Player Core 未增加另一套解释器。存档缩略图包含阅读中的静态界面装饰，排除新增操作按钮，继续固定触发时的实际画面。

实际测试修复了旧存档空容器截住标题点击、旧标题对齐边距叠加、新手机工具条仍使用固定定位、旧居中对白变换干扰锚点的问题。新入口补齐焦点返回和欣赏画面隐藏；附加内容回归还发现无焦点触发时错误尝试聚焦 body，已保留原菜单回退。

## 下一批接续

第四项继续围绕作者可用性，不无限增加装饰参数：

1. 基于当前契约做可视化组件选择、拖动和键盘微调，让作者不必反复换算百分比；仍保持草稿、撤销、边界保护及真实 Player 预览，不能直接写运行中的游戏状态。
2. 补布局冲突的更直接定位／修正与手机可见性控制，优先解决“小屏不需要大装饰”“改了参数却被安全布局接管”的理解成本。
3. 标题／阅读的操作体验稳定后再覆盖菜单、存档等其他页面；复用既有动作与存档权威，不新增自由脚本执行。
4. 完整作品主线继续依据 #304；原 0.4.0、长篇 1.7.14 与既有证据保留。需要自然阅读、听感、真机或实际发布时按真实结果单独记账，不由功能检查代替。
