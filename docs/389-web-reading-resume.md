## 现在的续读行为

成功校验并明确读取正式槽位或独立恢复点后，如果本浏览器还保留相同边界的阅读记录，会回到原先读到的文字附近。旋转、改字号和返回原布局继续沿用 #379 的文字锚点，不以滚动百分比替代。恢复点还包含下方未读内容时，Auto 仍须等待读完；显式读档／恢复关闭 Auto 与快进，不沿用中断前的旧时钟。恢复到段内时直接显示该段全文，不重新逐字动画后再寻找位置。

界面说明“已回到本机记录的阅读位置”，可选择“从段首重读”或“知道了”。旧存读档通知让位，菜单、计算／媒体错误等操作不被这条辅助提示覆盖。截图审查发现普通顶部提示在手机横屏压住正文首行，已把横屏续读提示移入底部阅读说明区，给右侧存读档按钮留位；320px 竖屏保留原画幅和正文区域。补实际矩形交叠检查，不能只以锚点位于正文滚动容器内就认定文字没有被覆盖。

这项记录是**同一浏览器最近保留的、该准确剧情边界的阅读位置**，不是“保存槽位时冻结的段内快照”。例如保存后继续向下读，再读取同一槽位，可以接到最近读到的地方；选择段首后，再读旧快速槽或刷新恢复也应保持段首。普通开始、历史回退／前进、新段落和回想不主动取用这份缓存，仍从对应段落开头显示。

没有匹配记录、记录已淘汰／损坏、宿主禁用存储，或文字锚点不适用于实际正文时，合法剧情照常读入，从段首开始。这不是读档失败，也不丢弃、覆盖或放宽正式进度校验。

## 实现与审计边界

- 可选记录独立存于 `world-player.reading-resume.v1:<projectId>`，不进入 Runtime、工程、手动／快速／自动／检查点／恢复存档或 `.worldsave` 备份，不改变 IndexedDB 和 Host 协议。它不承诺换机、不同浏览器、清理站点后或系统强制杀进程前未落盘位置的接续。
- 匹配项目、实际 Runtime buildId、**正式存档在合并 Meta 之前已校验的 Runtime hash**、语言和当前呈现文本的 SHA-256。不能只凭句子 ID 或合并后的新 hash 匹配，也不能把已读／解锁知识回退来迁就缓存。正文变更、另一语言、构建或剧情边界不能误套记录。
- 合法旧档读入可能合并较新的已读知识。仅在同一阅读表面内，同时维护原保存 hash 和当前合并 hash 对应的辅助位置；主动滚动和段首重读都同步，防止旧槽位重新跳回旧位置。换段、换语言／内容或新的显式读取解除原归属。
- 每项目最多八份最近写入的记录；读取字符串上限 32,768 字符，严格检查字段、版本、hash 和锚点数值范围。锚点只含段首／段尾、文字偏移与相对位置或受限像素回退；实际 DOM 再拒绝越界文字偏移，缺少文字几何时不冒充成功恢复文字。
- 主动滚动以 150ms 合并写入；隐藏、pagehide、卸载和显式读取前冲刷已捕获的记录。缓存权限、配额和 JSON 异常均被隔离；坏的本项目缓存可在后续正常记录时修复，不清理正式存档或其他存储键。生命周期通知是尽力保存，不等于移动系统一定会发送事件。
- 只有已有加载流程完成完整校验、归属检查后才准备恢复；待应用记录还须属于将提交的同一 Core 状态，旧结果不能作用于另一个状态。没有另一套叙事权威、历史截短、已验证缓存或后台绕过。

代码集中在 [reading-resume-store.ts](../apps/player-shell/src/reading-resume-store.ts)、[use-reading-resume.ts](../apps/player-shell/src/use-reading-resume.ts)以及原阅读表面和 PlayerShell 接入点。
