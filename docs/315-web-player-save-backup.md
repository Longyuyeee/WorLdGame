# Web 玩家存档备份与恢复

2026-10-14；起点 `67bcde3`；接续 #314。

## 本批设计

玩家打开存读档，进入独立的“备份”页：导出当前安全进度或一个已有槽位，得到可携带的文件。备份包含一份完整会话、历史/分支归档和可用截图，不批量铺开全部槽位。离线也能下载文件；旧版无法读取的已有槽位仍可原样备份，当前读取兼容不被放宽。

导入先校验文件格式/限额/摘要/截图、作品、完整 Runtime 存档和元数据。展示作品、场景、保存时间、原槽位和版本兼容状态后，再选择 12 个手动槽位之一。优先空槽位，已有槽位单独确认覆盖；提交时原子核对目标未变化。导入只写选定槽位，成功后由玩家选择读取继续，不自动改变当前剧情。取消、坏文件、异作品、未核对版本、并发冲突或写入失败均保留原进度和旧槽位。

备份与设备本地偏好分开；不承诺所有旧引擎或剧情变化能迁移。Web 范围，原生继续搁置。

## 必要验证计划

备份字节/元数据/截图、损坏与格式/身份拒绝、相同或核对过的版本、原子空槽位与覆盖冲突、UI 取消/确认/导入后读取、当前进度导出。类型与 Web 构建；实际源工程/HTML/目录导出，通过两个隔离浏览器上下文和不同站点来源迁移，在手机尺寸/离线和本地 HTML 中复查。完整结局按影响决定，不重跑无关全仓。

## 结果

### 本批交付

- 存读档独立“备份”页可导出当前安全进度或一个已有手动/自动/快速/检查点槽位；不先写一个假手动槽位。`.worldsave` 包含 v3 槽位信息、原始 canonical 会话字符串、来源、摘要和可用截图。已有旧版槽位允许备份，导入仍按当前/已核对版本和完整 Runtime 校验；标题尚未开始或场景回想中不伪造可备份边界。
- 导入检查 UTF-8/格式版本/精确字段/96 MiB 文件上限、内容摘要、作品/构建、完整会话、存档元数据及截图 Base64/摘要/实际头部尺寸（最大 512×512）。只读检查阶段不写槽位、不切换故事，显示来源/场景/保存时间/版本，默认空手动槽位，可取消；已有槽位需单独确认覆盖。
- IndexedDB 增加原子 `writeIfUnchanged`：同一读写事务比较已确认的目标元数据再写进度和截图；两个适配器/窗口的并发写入不会误覆盖。同步截图写入失败会主动中止整个事务，保存/备份的写队列保留调用顺序。旧宿主没有这项可选能力时禁用导入，不退化成不安全写入。
- 成功后点击“读取导入的存档”才继续剧情。读取也核对导入的会话摘要，若槽位之后又被其他窗口更新，保留当前剧情并提示重新核对/导入空槽位；不会读入另一份会话。
- 实查 390px 后把导出区在文件核对通过时自动收起；玩家仍可展开它备份目标旧槽位。导入摘要/按钮更靠前，原生弹窗的背景阻隔、焦点、返回和滚动保留；异步处理期间阻止重复提交/换页/关闭。
- 1.5.4 源工程/HTML/目录在 `evidence/web-save-backup`。对 1.5.3 全部 62 源条目，仅 manifest 发布版本改为 1.5.4、继承核对列表加 1.5.3；其余 61 条目字节完全保持。声明 1.5.1/1.5.2/1.5.3，实际旧档来源为 1.5.3。目录说明新增备份与迁移操作。

类型 (`typecheck-final.log`)、Editor/Player 最终生产构建 (`editor-build-final.log` / `player-build-final.log`) 通过，保留 >500kB chunk 提示。Chromium **155.0.8059.41** 最终 **7 组实际生产浏览器流程通过** (`browser-final.log` / `browser-checks.json`)，错误为空：

1. UI 导入 1.5.3 源、改版本/核对旧工程、三导出；源正文/媒体保持。
2. 原 1.5.3 实际快速档在 1.5.4 中备份，原快速槽位字节摘要保持；读取并继续后离线直接备份当前进度，没有新手动槽位。
3. 两个隔离 Chromium 上下文、不同 localhost 端口来源迁移，在 390px 触控模拟页面先核对、导入空手动槽位，再显式读取；原进度哈希保持，实际原生音轨时间推进。
4. 目标游戏下载离线内容、断网刷新/读手动槽位并再导出：原 canonical 会话字符串与 Session Artifact Hash 相同；外层槽位/来源变化导致备份文件整体摘要不同，不宣称整个文件字节相同。
5. 取消覆盖保持目标原字节；另一真实 UI 窗口在确认后改写目标，当前窗口的原子导入拒绝过期确认，双方当前进度与最新槽位保持。
6. 重新核对目标后明确覆盖成功，尚未点击读取时当前故事保持；损坏文件和重新计算合法外层摘要的异作品文件可见拒绝，当前进度/目标槽位字节摘要保持。
7. 当前单文件 HTML 在本地 file 地址导入这份核对过的旧版备份，刷新后再读取相同进度。

四个实际下载备份 `legacy-quick.worldsave` / `current-progress.worldsave` / `recovered-progress.worldsave` / `later-progress.worldsave` 均为本工具隔离上下文的测试数据；报告含三产物和四份备份大小/SHA256。两端是在同一台 Windows 的隔离浏览器和不同来源，**没有物理跨设备或物理手机验收**。完整两结局沿 #313，本轮未重跑；#314 的 service worker 等待/启用整链不再次累计。

### 失败与修正

- 首次类型检查发现写队列只允许 Promise<void>、新 CAS 返回 boolean；改成保留顺序的泛型队列，并去掉未用导入。
- UI 测试的 URL 子类缺 override、下载 mock 未声明参数，类型检查失败；补测试类型后通过。三次原始类型日志保留，不把它们记成产品数据失败。
- 第一轮 117 项和浏览器 7 组已通过；目视手机实图后收起导出区、增加成功导入之后的读档摘要保护，重新构建/重导并复跑最终 118 项与 7 组。中间报告保留 `before-mobile-refinement.json`，不累计为新检查。

### 边界与接续

文件迁移保留一份进度的完整会话、已记录的解锁/历史，不批量备份所有槽位/独立恢复区或个人设置。需要保留多个槽位时逐份导出；每个文件只能用于相同作品、当前或作者核对过的兼容版本。内容改动后的迁移、旧引擎/格式转换、云同步和浏览器数据清理后的自动恢复未实现。96 MiB/64 MiB Runtime 限额不等于已验证极限长篇的备份性能。

未跑全仓/全部 Editor/完整 check、全部历史 golden、其他浏览器、物理设备/旋转、长期运行/旧长帧、人工阅读/配音听感、授权和公网。未声称所有自定义宿主实现支持 CAS。源码、必要日志、失败和截图随提交保留。
