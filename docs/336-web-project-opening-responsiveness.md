## 先定位，再修改

使用生产压缩构建附 source map，在本机 Chromium 151.0.7922.34 对当前 31 MB、九场景/25 素材的《雨停之前》工程采样。先记录 `d4717eb` 的三次独立浏览器上下文，再测试修改后的相同任务；每组含导入、九次纯场景切换、返回首页刷新重开。仅第一轮启用 CPU 采样，主线程长任务及 16 ms 心跳全程记录。

CPU 栈映射到实际代码：导入时 `project-persistence/sha256.ts` 约 1,176 ms 采样 self CPU，ZIP `crc32` 约 325 ms；素材入库方法约 607 ms inclusive。切“再一次见面”时摘要计算约 145 ms self CPU，其中素材读取约 102 ms inclusive。**这些是采样归因，不是独立可相加的阶段耗时；inclusive 栈有重叠。** 主要问题不在增加更多编译缓存：

- 外层识别 ZIP 和内层源工程导入器重复解析同一包，重复完整 CRC 遍历及内存复制。
- 素材入库前、素材读取及素材卡预览的纯 JS SHA-256 在 UI 线程执行，等待 IndexedDB 并不意味着之后的校验也不阻塞。
- 原首页只显示“正在打开项目”，长校验期间不能取消；校验失败常是技术原文，没有重新获取完整工程包的指引。

## 实际实现与保护

1. **后台校验工程包。** 专用 Worker 接收 File/Blob，在后台读取并使用原解析器完成路径、CRC、工程 schema、素材 SHA-256、清单和总量校验；校验后的 Blob buffer 转移回主线程，Worker 完成/失败/取消/超时均终止并清理监听。Worker 不打开 IndexedDB、不写工程，也不把不可信数据标记成“已验收”。普通源包复用已解析条目，不重复扫描 CRC；仍重新施加源包自己的 4,096 条、单项 64 MiB、总量 512 MiB 限制。制作交付包的外层清单和内层源包仍分别核对。
2. **阶段反馈和安全取消。** 首页区分读取、后台校验、保存到本机和准备编辑器；前两步可取消，取消后可选同一文件重试，并把焦点交还导入入口。后台校验拒绝/取消时不建立新工作区或发布素材。写入开始后禁用取消，保留既有事务/租约和失败处理，不在中途终止数据库事务或遗留写入资格。进行中增加原生离开提醒，不承诺关页或系统强杀后能完成写入。
3. **校验不降级为跳过。** 入库前按唯一摘要用 WebCrypto 异步核对；在首次 await 前复制输入与索引，防止调用方在校验途中改写字节后把坏数据入库。现存 Blob 在原写事务内的校验继续保留。素材读取及图/音预览也使用异步摘要，不建立“上次验过所以永远可信”的缓存；原摘要、大小、索引版本及租约检查保留。异步预览完成时再检查是否已卸载，避免清理后又创建无法回收的 URL。
4. **失败可理解、可重试。** 路径不安全、CRC/格式损坏、素材不完整、展开大小/数量超限和不支持的压缩方式给出中文恢复指引，同时保留原始诊断。Worker 启动/加载/结果传输失败或超过 90 s deadline，终止本次校验并留在首页，不偷偷在 UI 线程重跑大包。

读取前新增 520 MiB 文件上限，为原 512 MiB 内容预算及 ZIP 目录/头部开销留余量；不是扩大源包或交付包的展开预算。缺 Worker 时仅保留不超过 2 MiB 的小工程兼容回退，大包明确提示环境能力不足。无 WebCrypto 时仍执行原确定性摘要校验，并在请求之间让出事件循环；**单份大 Blob 的回退校验、事务内现存 Blob 校验仍可能阻塞，未宣称所有环境同样快。** 未增加压缩 ZIP 支持，原解析器对非 stored 压缩方式的拒绝保留。
