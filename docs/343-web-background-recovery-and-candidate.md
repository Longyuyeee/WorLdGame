# 后台恢复保存、连续游玩与 1.7.4 候选 · 2026-10-16

接续 `4e196d7` / [#342](342-web-playback-responsiveness.md)，按 [#304](304-web-complete-gal-delivery.md) 的 Web 连续使用问题继续，不转向原生平台或另建运行引擎。上一批减少重复字符串处理后，独立恢复区仍在 React 被动 effect 中同步完整校验/序列化 History，后段翻页仍会被占用界面线程。本批处理这一路径，并把两批修复正式带入新的可交付候选。

## 实际实现与保护边界

- 只有**独立自动恢复保存的会话校验/序列化**移到专用 Worker；仍调用公开的 `createPlayerCoreSessionSaveV1` 和原 Runtime 完整校验器，不删历史、不缓存可变对象或跳过链/身份/哈希检查。Core 参数类型收窄到本来实际读取的四个字段，传输不附带回想档案、截图或整个无关宿主状态。
- 每个 Shell 的后台计算与物理恢复写入共享原来的一项在途保护。正在处理时不为每句建立队列，结束后只捕获最新现场；正式的手动/快速/自动槽位、剧情检查点及内存压力保护路径不旁路原有策略。它们仍可能有主线程成本，本批不宣称所有保存或 Runtime 推进都已移到线程。
- 校验任务结束、失败、5 秒超时、取消时都解绑监听、终止线程并撤销自己持有的 Blob URL。审计发现普通内联 Worker 包装器依靠线程启动后自撤销 URL，不能覆盖早停/构造失败；因此使用构建期生成的自包含源码，由 Shell 明确持有/释放 URL，而不是改写全局 Worker 或依赖线程自己清理。生产 HTML 不需要另下载一个 worker 文件。
- 显式读档、清除恢复点、换工程/恢复存储、卸载会取消尚未完成的计算；写入前和完成后仍核对 generation/项目/存储，旧结果不能写回已经被取代的进度。物理 IO 不伪装取消，仍走串行协调器；8 秒慢 IO 提示、迟到成功后的显式重试、quota 错误与原恢复点保护保留。
- 不支持 Worker 或构造被拒绝时仍使用完整校验的原主线程兼容路径，诊断明确计为 fallback，不当后台通过。已启动线程报错、传输/结果错误或超时，会保留旧恢复点并提示重试/手动保存，不悄悄接受结果或无限重试。

## 审计与过程纠偏

相关基线 45 文件/420 项；Player Shell/Core/Runtime Host 三个 `src` 目录全部 55 文件/416 项，其中八文件/134 项重复；另三项异步轮询检查和两项独立构建检查。去重 **94 文件/707 项相关测试全部通过**。新线程客户端/后台流程 20 项覆盖字节/哈希一致、旧 checkpoint 篡改拒绝、取消/超时/失败/错 ID/迟到回复、兼容路径及 URL 释放、100 步背压、换工程与显式读取不被旧任务覆盖。根类型、双构建、工作区/架构/需求/交付四项审计通过；jsdom 原生媒体未实现提示及大 chunk 警告保留。

构建接续审计还发现 13 个既有压力/预算工具自行 `configFile:false` 打包，无法自动取得新的 Worker 源码入口。统一构建适配器，并把历史基线的源码替换同时传入子 Worker；两项实际打包冒烟核对可解析完整 Shell 和正确传递基线覆写。应用的默认 Worker 输出与已经测量/导出的字节再次相等；只证明构建接续，不冒充全部历史压力/预算脚本的业务流程重跑。

最终代码审计另抓到真实边界：第一份恢复点还在计算时读取相同 hash 的正式槽位，旧任务取消而去重标记没有清除，导致没有补写独立恢复点。新增用例先超时，再用更短的专用等待明确复现“应有第二任务却只有一个”；读档后明确重建保护，修复后通过，不延长测试预算。对该修正重新测量、正式导出和三引擎/八轮检查，不沿用前一运行时的通过结果。

扩大回归暴露旧语言用例仍在标题/正文直接查找已经收进阅读菜单的状态和选择器。读取实际代码及 HEAD 确认是既有界面路径变更，按真实“打开菜单→核对回退提示/切换语言→返回故事”更新，保留译文、原文回退、即时切换与重开偏好断言，没有删除功能检查或修改产品。

本机独立浏览器探针还确认：异步 `waitForFunction` 条件即使最终 false，也可能立即得到 false-valued handle。原恢复采样第一次分离读取出现 active=1，第二次对象快照得到 false 而不是就绪结果。改为明确 await `page.evaluate` 的值并有界轮询，只有实际就绪才返回；新增“多次 false 后才成功、永远 false 必须超时、数据库失败必须报错”三项用例。更新等待、独立恢复与连续使用均用相同严格轮询重跑，不扩大超时或把未就绪算通过。最新过程失败报告保留，最终报告必须独立通过；此前弱等待的连续运行不作为最终持久性证明。

初始测试夹具使用非法稳定 ID/缺结局，随后修正为合法可编译工程；读取较早存档的测试还需保留正式 Meta Progress 单调合并规则，改为保护“实际读入后的状态”，不是强迫回退已读标记。这些过程失败不算产品成功。最终审计汇总、实际三引擎矩阵和八轮持久性/资源检查均以对应报告为准；不宣称全仓、生成语料分片、人工听感或两小时 soak 通过。
