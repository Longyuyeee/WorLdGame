# 开发前待确认决策

这些问题会显著改变产品或技术方向，不能由开发者自行默认。

## A. 产品定位

1. 首发最重要的人群是谁？
   - A：完全不会编程的独立创作者；
   - B：有大型项目需求的编剧/小团队；
   - C：两者同等，但首屏使用新手模式。

建议：**B 为架构基准，A 为交互门槛**。这样不会因新手友好牺牲大型项目能力。

2. 产品是否允许无账户完整本地使用？

建议：允许。账户只用于同步、协作和云构建。

3. 是否计划建设作品分发/社区平台？

建议：前三个里程碑不做，优先兼容 itch.io、Steam、Web 和应用商店。

## B. 商业与许可

4. 编辑器、项目格式和运行时分别采用什么许可证？

建议：开放工程格式与运行时规范；核心运行时优先考虑宽松开源；云服务收费。最终需法律评审。

5. 云构建采用订阅、点数还是自托管？

建议：免费额度 + 订阅额度 + 团队私有节点。

6. 插件市场是否允许付费插件？

建议：M4 再决定，但 P1 SDK 从一开始保留签名和授权接口。

## C. 首发平台

7. 首发编辑器是否必须同时包含 iPhone/iPad？

建议：M1 Windows + Android，M2 iPad/iPhone 编辑，M3 iOS 构建。若 iOS 用户是首要市场则提前。

8. macOS/Linux 编辑器是否为首发承诺？

建议：PWA 提供基本覆盖；原生桌面包在 Windows 稳定后跟进。

9. Web 玩家包是否允许依赖网络 CDN？

建议：默认完全离线、自包含；可选 CDN/章节分包。

## D. 创作模型

10. 场景脚本是否接受文本为主要持久化形式？

建议：接受。视觉用户无需看到文本，但这是开放性、规模和版本控制的基础。

11. 是否要求兼容/导入 Ren'Py、WebGAL、Yarn、ink？

建议：P1 做受支持子集导入，不承诺任意自定义代码的完整转换。

12. 是否支持用户执行任意 JavaScript/C#？

建议：核心脚本禁止；通过明确权限的插件 SDK 扩展。

## E. 视觉与运行时

13. 首发是否必须包含 Live2D？

建议：不作为 M1 阻塞项，M2/M3 通过独立官方适配插件加入。

14. 3D 场景是否属于产品核心？

建议：不是。保持插件接口，不把通用 3D 引擎引入核心。

15. UI Composer 首发做到什么程度？

建议：M1 提供设计 Token + 模板；M2 完成常用屏幕可视化；M3 才开放复杂组件。

## F. 云与协作

16. 项目是否默认上传云端？

建议：不默认。明确区分“只在此设备”“已备份”“团队项目”。

17. 实时协作和版本化异步协作谁优先？

建议：版本化同步、评论和语义 Diff 优先；实时协作 M4。

18. 是否托管用户签名证书？

建议：提供临时上传和加密托管两种模式；默认解释风险并支持撤销。

## G. AI

19. AI 是首发卖点还是后续插件？

建议：后续可选插件。先让没有 AI 的创作、调试和发布流程完整。

20. 是否允许云模型读取未发布剧情？

建议：仅在用户逐次明确同意后，按选中内容最小发送；不得默认用于训练。

## H. 品牌

21. “WorLd Studio”是否为正式名称？

建议：保持工作名，完成目标用户访谈、商标和域名检查后再冻结。

## 建议的首次评审议程

1. 确认首要用户与产品定位；
2. 确认六个差异化支柱；
3. 审阅 P0 与排除项；
4. 确认脚本为主要持久化形式；
5. 确认 M1 平台顺序；
6. 批准或修改 D1 原型范围；
7. 明确只有完成 D1/S0 后才允许产品编码。
