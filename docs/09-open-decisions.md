# 开发前决策记录

这些问题会显著改变产品或技术方向。已经确认的结论作为当前基线；其余问题不能由开发者自行默认。

## 0. 2026-08-10 已确认的 M1 基线

- 首要用户：大型项目编剧/小团队为架构基准，零编程独立创作者为交互门槛；
- 当前范围：只执行到 M1，M2 以后保留为未排期愿景池；
- M1 平台：Windows 与 Android 编辑，Web、Windows、Android 玩家包；
- 账户与云：M1 不做账户、云同步或云构建；
- 工程真相：文本脚本是主要持久化形式，图形/时间线/舞台共享同一语义模型；
- 商业模式：当前不讨论收费方式；
- 验证故事：原创、简单的校园短篇；
- 设备方向：必须覆盖低端设备，具体型号与预算在 S0 前冻结；
- 审计：R3/R4 独立审阅，红线缺陷不得带例外发布 Stable。

## A. 产品定位

1. 首发最重要的人群是谁？
   - A：完全不会编程的独立创作者；
   - B：有大型项目需求的编剧/小团队；
   - C：两者同等，但首屏使用新手模式。

已确认：**B 为架构基准，A 为交互门槛**。这样不会因新手友好牺牲大型项目能力。

2. 产品是否允许无账户完整本地使用？

已确认：M1 不建设账户系统。创建、编辑、预览、导入导出和本地构建均不得要求登录；云能力以后另行决策。

3. 是否计划建设作品分发/社区平台？

建议：前三个里程碑不做，优先兼容 itch.io、Steam、Web 和应用商店。

## B. 商业与许可

4. 编辑器、项目格式和运行时分别采用什么许可证？

建议：开放工程格式与运行时规范；核心运行时优先考虑宽松开源；云服务收费。最终需法律评审。

5. 云构建采用订阅、点数还是自托管？

已确认：当前不做云构建，也不讨论订阅、点数或收费方式。本问题移入 M1 之后的愿景池。

6. 插件市场是否允许付费插件？

建议：M4 再决定，但 P1 SDK 从一开始保留签名和授权接口。

## C. 首发平台

7. 首发编辑器是否必须同时包含 iPhone/iPad？

已确认：M1 为 Windows + Android 编辑，Web + Windows + Android 发布。iPhone/iPad 编辑和 iOS 构建均未排期。

8. macOS/Linux 编辑器是否为首发承诺？

建议：PWA 提供基本覆盖；原生桌面包在 Windows 稳定后跟进。

9. Web 玩家包是否允许依赖网络 CDN？

建议：默认完全离线、自包含；可选 CDN/章节分包。

## D. 创作模型

10. 场景脚本是否接受文本为主要持久化形式？

已确认：接受。视觉用户无需看到文本，但文本脚本是开放性、规模、版本控制和安全迁移的主要持久化形式。

11. 是否要求兼容/导入 Ren'Py、WebGAL、Yarn、ink？

建议：P1 做受支持子集导入，不承诺任意自定义代码的完整转换。

12. 是否支持用户执行任意 JavaScript/C#？

建议：核心脚本禁止；通过明确权限的插件 SDK 扩展。

## E. 视觉与运行时

13. 首发是否必须包含 Live2D？

建议：不作为 M1 阻塞项，M2/M3 通过独立官方适配插件加入。

14. 3D 场景是否属于产品核心？

建议：不是。保持插件接口，不把通用 3D 引擎引入核心。

15. UI Composer 首发做到什么程度？

建议：M1 提供设计 Token + 模板；M2 完成常用屏幕可视化；M3 才开放复杂组件。

16. 默认视觉风格在“克制专业”与“高表现多彩”之间如何取舍？

已确认方向：两者同时成立。采用深色中性底、语义高彩色、有限渐变/辉光和专业信息密度，不使用低对比大面积毛玻璃或无意义彩虹色。D1 通过高保真原型冻结具体 Token。

17. “强动效”的强度如何验收？

已确认方向：动效覆盖空间连续性、因果、运行同步、直接操控和状态变化；不以持续装饰数量衡量。必须达到目标设备 60 FPS、可被输入打断，并提供完整/简化/减少动效三级。

18. 商业 Galgame 参照池包含哪些作品？

建议：D1 选择 3–5 部作品，至少覆盖电影化演出、长篇传统系统、多语言本地化和独立团队制作。首批候选包含《魔法使之夜》《月姬 -A piece of blue glass moon-》《ATRI -My Dear Moments-》，只比较能力和质量维度，不复制风格或素材。

19. Benchmark Episode 的题材、美术预算和配音范围是什么？

题材已确认：原创、简单的校园短篇。建议仍采用 20–30 分钟、3 场景、2 路线、3 结局、两种语言和一段 60–90 秒高密度演出；具体角色、美术、配音和预算在 D1 前冻结。

20. 首发性能目标设备矩阵是什么？

方向已确认：必须支持低端设备。M1 至少确定一台低内存 Android、一台主流 Android、一台集显 Windows 和主流浏览器设备；iPhone 不属于当前矩阵。型号与系统版本在 S0 前冻结并定期复评。

21. 首包、完整下载、安装和软/硬内存预算分别是多少？

建议：不要用一个容量覆盖所有项目；由模板给出默认预算，项目必须按平台与 Profile 显式确认。没有目标设备和预算时，不能声称“优化完成”。

22. 默认是否启用章节、语言、语音和高分辨率资源分包？

建议：Web/移动的长篇模板默认启用章节与语音分包，短篇模板保持自包含；所有项目保留完全离线构建选项。

## F. 云与协作

23. 项目是否默认上传云端？

建议：不默认。明确区分“只在此设备”“已备份”“团队项目”。

24. 实时协作和版本化异步协作谁优先？

建议：版本化同步、评论和语义 Diff 优先；实时协作 M4。

25. 是否托管用户签名证书？

建议：提供临时上传和加密托管两种模式；默认解释风险并支持撤销。

## G. AI

26. AI 是首发卖点还是后续插件？

建议：后续可选插件。先让没有 AI 的创作、调试和发布流程完整。

27. 是否允许云模型读取未发布剧情？

建议：仅在用户逐次明确同意后，按选中内容最小发送；不得默认用于训练。

## H. 品牌

28. “WorLd Studio”是否为正式名称？

建议：保持工作名，完成目标用户访谈、商标和域名检查后再冻结。

## I. 工程治理与审计

29. R3/R4 核心与发布变更是否要求独立批准？

已确认：要求。数据、VM、迁移、权限、签名和更新链不能由提交人单独批准；早期无法职责分离时只能发布 Preview。

30. 软件供应链成熟度按什么节奏推进？

当前确认：M1 输出 SBOM、基础 Provenance、产物哈希和签名。SLSA Build L2/L3 作为 M1 之后的愿景，不构成当前排期。

31. Stable 是否允许带工程审计例外发布？

已确认：只允许有 Owner、补偿控制和到期时间的非红线例外。数据损坏、密钥泄露、越权、未签名更新、不可回退迁移和确定性剧情错误不得例外。

## 剩余 D0 评审议程

已确认事项不再重复询问。D0 只剩：

1. 冻结 M1 P0 与明确排除项；
2. 冻结校园短篇的角色、分支、美术、配音、语言和素材预算；
3. 冻结低内存 Android、主流 Android、集显 Windows 与浏览器的具体设备和容量/内存预算；
4. 批准 D1 原型任务、参与者和验收表；
5. 明确 D1/S0 全部通过后，仍需产品负责人再次发出“开始开发”指令。
