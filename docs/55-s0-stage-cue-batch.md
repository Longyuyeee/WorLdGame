# S0.36 演出 Cue 无损复制、多选与原子批量编辑审计

## 阶段目标

S0.36 补齐图形化演出轨道的高频生产操作：无损复制单条 Cue、在桌面与手机端显式进入多选模式，并把同类 Cue 的参数修改作为一个不可分割的权威脚本事务提交。轨道仍然只是 `.world` 脚本的投影，不维护第二套时间线数据。

本阶段不包含跨场景操作、批量删除、账户、云同步或发布打包；这些能力不能借由批量编辑入口隐式扩张范围。

## 冻结契约

### 无损复制

- 只允许复制 `background`、`show`、`audio` Directive。
- 除新稳定 ID 外，原始 Directive 行逐字节保持不变，包括旧式描述、未知 `key=value`、插件元数据、空白与 CRLF 换行。
- 新 ID 必须合法、未被当前语句、文本 ID 或 tombstone 使用。
- 目标带相邻注释或原始行无法唯一定位稳定 ID 时拒绝执行，避免错误复制注释归属或替换业务文本。
- 成功复制是一个 source command、一个 revision 和一个 Undo 粒度。

### 原子批量参数修改

- 一批最多 256 个唯一 statement ID；空批次、重复 ID、目标缺失或混合命令类型全部拒绝。
- 所有目标必须是同一种 Directive 命令；UI 只暴露该命令已审计的安全参数。
- 参数支持显式“设置”和“移除”，类型、枚举、时长、音量及资源索引引用沿用单条 Directive Patch 的验证规则。
- 任一目标失败，返回零写入结果；不会暴露或提交中间 source。
- 成功批次只产生一个 command、一个 revision 和一个 Undo，目标 ID 排序后进入命令指纹，保证重放确定性。

## 交互与移动端

- 多选是明确开关，而不是普通点击的隐藏副作用；进入后当前 Cue 自动成为首个选择。
- 多选状态仅属于当前 Writer 会话，切换场景或目标消失时自动清理，因此 project schema 保持 v2。
- 多选时禁用移动、复制、删除和拖放，避免结构命令与参数批次竞争。
- 同类 Cue 达到两条后显示批量面板，并持续提示“任一目标失败则整批零写入”。
- Cue 和多选开关使用 `aria-pressed` 暴露状态；手机布局改为单列，批量控件和提交按钮保持触控尺寸。

## 审计结论

1. 复制由 CST 结构 Patch 完成，不经过格式化或语义重建，旧式脚本和插件字段不会因图形化操作丢失。
2. 批量写入先在局部工作副本完成全部验证，最后才进入现有 source transaction，满足 all-or-nothing。
3. React 只发出稳定 ID 命令；Script、Writer、Preview、自动保存和 Undo/Redo 继续读取同一权威脚本。
4. 命令的 revision、幂等指纹、同 ID 异载荷冲突和历史恢复沿用既有 source session 约束。
5. 256 个目标的上限同时约束 UI 和核心 API，防止隐藏调用绕过性能与操作风险边界。

## 验证证据

- `npm run check` 全部通过：45 个测试文件、300 项测试、生产构建、34 个可移植文件 / 3 个 Node adapter 架构边界，以及脚本与资源性能门。
- 10,000 行脚本全链路 155.07 ms；256 条 Cue 原子批量 Patch 302.42 ms，低于 2,000 ms 冻结预算。
- 真实 Chromium 主链路验证：默认 Preview 为 16:9 / 1920×1080；复制后场景从 4 步变 5 步；显式多选两条背景 Cue 后一次提交把两处 `transition=fade` 写入同一 revision；一次 Undo 同时移除两处参数，并保留已复制 Cue。
- 单元与集成回归覆盖：CRLF/旧式描述/插件元数据无损复制，重复或非法 ID，相邻注释，空批次、重复目标、混合命令、超过 256 条、缺失目标、确定性重放及单步 Undo。

## 下一阶段入口
