## 作者使用流程

在“游戏外观 → 皮肤与动效”新增“带上图片和字体一起复用”，保留原 `.worldskin.json` 配置往返。

1. **导出皮肤与素材**：列出皮肤实际引用的封面、对白窗体和字体，不把整个素材库、剧情、角色演出或音乐一起打包。可编辑随包公开署名与许可。
2. **导入皮肤与素材**：读取 `.worldskin.zip`，逐项选择包内文件、已有素材、补齐/替代文件，或明确选择不用图片/系统黑体。缺失文件不自动当作已修复；文件损坏或摘要不符时拒绝载入。
3. **检查并预览皮肤**：核对实际文件格式、摘要、大小与媒体预算，只在内存生成候选外观。预览使用正式 Player，始终静音，并沿用其存储隔离。
4. **导入皮肤与素材到工程**：确认后整批新增所需素材，不覆盖已有条目；相同内容可自动对应已有素材。保留当前作品的标题、简介、剧情和制作名单，合并附带公开鸣谢。
5. **保存到本机**：外观与来源记录进入当前工程后，按正常工程保存流程落盘；刷新或换电脑前仍需保存/导出工程。

未应用的外观草稿需先应用或放弃，再导入另一皮肤。改变对应会使预览结果失效，必须重新检查。取消预览不写入素材；提交失败保留对应并提示重试。导出皮肤本身不改变工程。

当前包支持已检查的 PNG/JPEG/WebP 图片和 WOFF/WOFF2/TTF/OTF 字体，沿用图片 8 MB / 400 万像素、字体 32 MB 限制，合计最多 64 MB / 8 项。只接受本应用生成的存储式 ZIP，外部重新压缩的包会给出明确提示。自动正文字体保持自动语义，跟随目标工程；要固定源字体，应先在字体页明确选择，导出窗口会提示这一点。

## 来源与署名

公开署名/许可随包附带，导入时合并到当前作品鸣谢，不替换原团队、人员名单或版权说明。鸣谢超过现有限额时，在写入素材前阻止提交。

“附带内部来源台账”**默认关闭**；默认包不包含来源事实、内部依据或审核人。明确勾选后可将相关记录交给可信协作者；导入后仍标为待确认，不把原记录当成新工程已完成发行审查。当前工程已有的来源记录不被覆盖，替代文件内容变化后也不继承旧文件的确认依据。

内部记录只保留在可编辑工程，正式游戏继续使用现有元数据剥离逻辑。公开许可保留不等于证明所有素材可以发行。

## 代码与一致性

- `player-skin-bundle.ts` 复用原皮肤配置契约和 ZIP/摘要能力，检查文件清单、引用、类型和来源记录；统一生成映射、候选外观和仅含必要字节的预览 reader。
- `PlayerSkinBundleTools.tsx` 提供导出、对应、补齐、预览与明确确认；沿用 `PlayerSkinPreview`，不增加独立播放器。
- `IndexedDbAssetRepository.importNewAssets` 在现有 writer lease 和索引版本保护下，一次提交新增 Blob、Index 和生命周期。取消、旧版本、失去编辑权或已有标识冲突时，不留下半个素材批次；原单项导入和备份流程保留。
- App 提交前再次核对工程、素材和已保存外观，先验证候选引用/署名，再提交素材并应用外观。素材事务与后续工程文件保存是两个正常步骤，不宣称跨所有存储的整工程磁盘事务。

实际截图审查修复了旧弹窗宽度覆盖新布局的问题，桌面保留并排预览，手机改为可滚动的单列。脚本早期两次失败分别是把原生 select 的 option 当可见元素等待、使用了错误标题类名；两份 `failure-*.json/png` 保留，没有计入通过。

《给明天的回信》**0.4.0 保持原样，不重发**，用于导出所需封面和文楷字集。通过真实界面另外建立“来信皮肤复用验证”**0.1.0**，包含三段新旁白和一个结局，用来证明皮肤复用不会带走原故事。这是功能验证小工程，不是完整篇幅样章。

- [新工程源包](../evidence/web-skin-bundles/skin-reuse-project.zip)、[独立 HTML](../evidence/web-skin-bundles/skin-reuse.html)、[目录游戏](../evidence/web-skin-bundles/skin-reuse-web.zip)。
- [桌面对应界面](../evidence/web-skin-bundles/import-mapping-desktop.png)、[手机对应界面](../evidence/web-skin-bundles/import-mapping-phone.png)、[手机游戏](../evidence/web-skin-bundles/player-phone.png)。
- `missing-font.worldskin.zip` 是从实际导出包去掉字体成员的缺失修复用例；`repair-font.woff2` 是同一包原字体的副本。没有用直接重写工程或注入运行状态替代作者操作。

**87 项相关测试、16 个文件通过**，覆盖包格式、映射/同名冲突、缺失回退、公开/内部记录、预览后取消、提交失败重试、整批回滚、编辑权/版本保护及原有外观/素材操作。见 [unit-tests.json](../evidence/web-skin-bundles/unit-tests.json)。根类型、Editor / Player 生产构建和便携架构审计通过；原有大 chunk 提示保留。

[五组真实静音任务通过](../evidence/web-skin-bundles/browser-checks.json)：实际打包与隐私选择；新工程预览后取消（导出源包仍为零素材）；缺失字体阻止/系统回退/补齐后导入；保存重开和重复导入仍只有两素材；HTML `file://` 桌面与目录 HTTP `/gal/` 手机 **390×844** 均加载导入字体、样式并到达“新的开始”。作者弹窗另核对 736 / 390 / 320px。

两份游戏包含同一工程；两素材逐一核对原 SHA-256，目录清单 **13 个文件**大小/摘要通过。内部验证标记出现在源工程、不出现在玩家 HTML/目录入口，字体公开许可保留。实际下载字节和摘要也记录在浏览器报告。

本验证工程独立 Player 单结局在两种格式各 **1/1**。没有把它计入原 0.4.0 的两结局覆盖，也没有新增编辑器整部试玩记录。真机/Safari、任意外部字体包、崩溃恢复、完整篇幅、自然阅读/听感和实际公网交付不在本批通过范围。
